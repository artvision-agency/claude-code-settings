## Правило (HARD)

У КАЖДОГО активного клиента/проекта обязаны быть ДВА артефакта плана:

1. **`clients/<slug>/plan/task-plan.md`** — текстовый persistent-план (источник правды, чеклисты).
2. **`clients/<slug>/plan/<slug>-plan.html`** — ВИЗУАЛЬНОЕ отображение (тот же план как gantt/kanban/статус-борд), деплой на review-URL artvision.pro/_priv-* или /preview/.

Оба обновляются в конце каждой сессии по проекту. На ресюме — читать `task-plan.md` ПЕРВЫМ (правило resume-read-project-state).

## Шаблон task-plan.md (копировать)

```markdown

> Полное состояние → context-log.md + STATUS.md. Обновлён: <дата>.
> Адрес/реквизиты: <город, адрес> (правило project-docs-keep-address).

## Цель проекта (1-2 строки)
<что и зачем; для кого результат>

## Этапы
### Э1. <название> — [статус: ✅/🔄/⏳/🔒]
- Цель этапа:
- Чеклист:
  - [ ] шаг 1
  - [ ] шаг 2
- Критерий DONE:
- Блокер/зависимость:
- Срок:

### Э2. ...

## Блокеры (CONFIRM / клиент)
- <что ждём, от кого>

## Зависимости
- Э2 ждёт Э1 (почему)

## Следующий шаг
1. HIGH: ...
```

## Визуальное отображение (`<slug>-plan.html`) — требования

- Автономный HTML (правило html-clients: всё инлайн, без CDN), mobile-first (kp-brand).
- Бренд Artvision (sticky bar + кнопка «Задать вопрос» + футер) — прямой клиент.
- Формат на выбор по проекту: **gantt** (этапы × сроки), **kanban** (To-Do / In-Progress / Done / Blocked), **статус-борд** (карточки этапов с %/статусом).
- Каждый этап: название, статус (цветовой бейдж ✅🔄⏳🔒), чеклист-прогресс, блокер, срок.
- Структуры — СПИСКАМИ (document-list-format).
- Деплой на review-URL, ссылка в STATUS.md + хабе клиента.
- Эталоны (USmile): `plan/gantt-usmile.html`, `plan/usmile-plan-rabot.html`, `plan/usmile-billboards-map.html`.

## Форматы визуализации плана (минимум 2, один из них — ASCII)

Один и тот же план отображается в НЕСКОЛЬКИХ форматах под разные инструменты/контексты:

| Формат | Инструмент | Когда | Кому |
|--------|-----------|-------|------|
| **ASCII** (gantt/kanban/дерево в моноширинном тексте) | терминал, markdown, чат, recap | быстрый просмотр в сессии, статус одним взглядом без браузера | Claude + Антон в терминале |
| **HTML** (gantt/kanban/статус-борд) | браузер, deploy review-URL | показать клиенту/владельцу визуально | клиент, Антон |
| **Mermaid** (gantt / flowchart) | markdown-рендер (GitHub, доки) | внутри .md документов проекта | команда |
| **Asana** (задачи/таймлайн) | Asana | трекинг с assignee+дедлайнами | команда (правило asana-required-fields) |

**Обязательно:** ASCII-версия в `task-plan.md` (или рядом) + HTML-версия `<slug>-plan.html`. Остальные — по необходимости.

ИЛИ ASCII-kanban:
```

              |               | Э4 Директ      | iDent ✅
```

### Важно про ASCII vs HTML (не путать с document-list-format)
- ASCII-gantt/kanban/дерево — РАЗРЕШЕНО и обязательно для **внутреннего/терминального** просмотра плана (это инструмент Claude+Антон).
- В **клиентских HTML-документах** ASCII-tree для иерархий — ЗАПРЕЩЁН (правило document-list-format → там списки `<ul>`/`<ol>`). Это разные контексты: ASCII = терминал/план для нас, списки = клиентский HTML.

## Правило (HARD)

У КАЖДОГО активного клиента/проекта обязаны быть ДВА артефакта плана:

1. **`clients/<slug>/plan/task-plan.md`** — текстовый persistent-план (источник правды, чеклисты).
2. **`clients/<slug>/plan/<slug>-plan.html`** — ВИЗУАЛЬНОЕ отображение (тот же план как gantt/kanban/статус-борд), деплой на review-URL artvision.pro/_priv-* или /preview/.

Оба обновляются в конце каждой сессии по проекту. На ресюме — читать `task-plan.md` ПЕРВЫМ (правило resume-read-project-state).

## 🔴 СТАНДАРТ ВИЗУАЛЬНОГО ГАНТА (Антон 2026-06-20, HARD — на КАЖДЫЙ проект)

> «Это будет наш стандарт. На каждый проект. Согласно приложениям в договорах проектов с юрлицами.»

**Эталон формата = USmile-гант** `clients/usmile/plan/gantt-usmile.html`. Каждый проект получает гант ровно в этом формате — не тёмный по-дням, не произвольный.

Признаки эталонного формата (копировать 1-в-1):
- **Светлая чистая тема** (`--bg:#f5f8fc`, белая карточка, без тёмного фона).
- **Горизонтальный гант фазы × месяцы**: колонка `230px` (направление + подпись `<small>`) + 6 колонок-месяцев; полосы `.bar` позиционируются `left%`/`width%`.
- **Фазы** секциями (`.phase`: Запуск / Этап-1 / Этап-2 / Контроль…).
- **Легенда направлений** цветными точками (SEO/Директ/ВК/Аналитика/Оффлайн/Отчёты).
- **Бренд Artvision** в футере + кнопка «Задать вопрос» (прямой клиент).
- Маркер «сегодня» + контрольные точки (Акт/milestone) золотым.
- Mobile: `overflow-x:auto` обёртка (`.scroll` + `min-width` inner) — гант не ломает вёрстку на 375.
- Имя файла: `clients/<slug>/plan/gantt-<slug>.html`, деплой `artvision.pro/_priv-<slug>-gantt/`.
- 🔴 **Сетка by-days = РЕАЛЬНЫЕ даты этапа, НЕ календарный месяц** (strict-фактчек 20.06: июньская сетка 1–30 срезала старт 29.05 слева и добавила лишние 29–30.06 справа → искажение длительности). Шкала строится `start..end` фактического периода (напр. 29.05–28.06), live-маркер «сейчас» считается от того же `start`.
- Статусы deliverables: «✅ Готово» только после ЯВНОГО одобрения клиента (`explicit-approval-tracking`); до этого — «на ревью». Числа/сроки — по договору (8 целей ≠ выдуманные 14 без пометки «перевыполнение»).

**Содержание ганта = СОГЛАСНО ПРИЛОЖЕНИЯМ ДОГОВОРА (проекты с юрлицом):**
- Строки/этапы/сроки берутся из **Приложения 1/2 договора** (состав работ, deliverables, этапы, сроки), а НЕ «из головы».
- Источник: `clients/<slug>/CONTRACT-DELIVERABLES.md` (выжимка приложений) + подписанный договор (`legal/`). Расходятся → победитель PDF-договор, свериться попунктно.
- Часть правила схождения `project-tasks-single-source-reconciliation.md`: гант ↔ worklist ↔ Asana ↔ Приложения договора = единый источник.
- Проекты БЕЗ юрлица/договора (наши продукты, presale) — гант по `task-plan.md`, формат тот же USmile.

**Две версии** (`project-tasks-single-source-reconciliation`): внутренняя (с исполнителями) + клиентская (БЕЗ имён исполнителей) — из одного источника.

Эталоны для копирования: `clients/usmile/plan/gantt-usmile.html` (по месяцам), `clients/grelka-gudelka/plan/gantt-grelka.html` (Этап-1→Этап-2 по приложениям договора, 20.06).

## Визуальное отображение (`<slug>-plan.html`) — требования

- Автономный HTML (правило html-clients: всё инлайн, без CDN), mobile-first (kp-brand).
- Бренд Artvision (sticky bar + кнопка «Задать вопрос» + футер) — прямой клиент.
- Формат на выбор по проекту: **gantt** (этапы × сроки), **kanban** (To-Do / In-Progress / Done / Blocked), **статус-борд** (карточки этапов с %/статусом).
- Каждый этап: название, статус (цветовой бейдж ✅🔄⏳🔒), чеклист-прогресс, блокер, срок.
- Структуры — СПИСКАМИ (document-list-format).
- Деплой на review-URL, ссылка в STATUS.md + хабе клиента.
- Эталоны (USmile): `plan/gantt-usmile.html`, `plan/usmile-plan-rabot.html`, `plan/usmile-billboards-map.html`.

## Форматы визуализации плана (минимум 2, один из них — ASCII)

Один и тот же план отображается в НЕСКОЛЬКИХ форматах под разные инструменты/контексты:

| Формат | Инструмент | Когда | Кому |
|--------|-----------|-------|------|
| **ASCII** (gantt/kanban/дерево в моноширинном тексте) | терминал, markdown, чат, recap | быстрый просмотр в сессии, статус одним взглядом без браузера | Claude + Антон в терминале |
| **HTML** (gantt/kanban/статус-борд) | браузер, deploy review-URL | показать клиенту/владельцу визуально | клиент, Антон |
| **Mermaid** (gantt / flowchart) | markdown-рендер (GitHub, доки) | внутри .md документов проекта | команда |
| **Asana** (задачи/таймлайн) | Asana | трекинг с assignee+дедлайнами | команда (правило asana-required-fields) |

**Обязательно:** ASCII-версия в `task-plan.md` (или рядом) + HTML-версия `<slug>-plan.html`. Остальные — по необходимости.

### ASCII-шаблон (в task-plan.md, моноширинный блок)

```

═══════════════════════════════════════════

Э2 Подготовка Аудиторий[██░░░░░░░░] 20%  ⏳  ждёт Э1
Э3 Загрузка сегментов  [░░░░░░░░░░]  0%  🔒  доступ кабинет
Э4 PPC в Директе       [░░░░░░░░░░]  0%  🔒  ждёт Э3
═══════════════════════════════════════════
Легенда: ✅ done · 🔄 в работе · ⏳ ждёт · 🔒 blocked

```

ИЛИ ASCII-kanban:
```
TODO          | IN PROGRESS   | BLOCKED        | DONE
--------------|---------------|----------------|-------------
Э2 Аудитории  | Э1 выгрузка   | Э3 загрузка    | инструкция
              |               | Э4 Директ      | iDent ✅
```

### Важно про ASCII vs HTML (не путать с document-list-format)
- ASCII-gantt/kanban/дерево — РАЗРЕШЕНО и обязательно для **внутреннего/терминального** просмотра плана (это инструмент Claude+Антон).
- В **клиентских HTML-документах** ASCII-tree для иерархий — ЗАПРЕЩЁН (правило document-list-format → там списки `<ul>`/`<ol>`). Это разные контексты: ASCII = терминал/план для нас, списки = клиентский HTML.

# Карта спроса + динамики (cluster-trend-map) — СТАНДАРТ для КАЖДОГО SEO/PPC-проекта (DEFAULT ON, HARD)

> **Установлено:** 2026-06-28 (Антон, USmile cluster-trend). Дословно: «очень важно использовать эти инструменты для КАЖДОГО нашего проекта».
> **Связано:** skill `/cluster-trend-map`, `cluster_trend_pipeline.sh`, workflow `cluster-trend-map.js`, `seo-rising-subclusters-fast-traffic.md` (растущие = быстрый трафик), `tfidf-clustering` (Arsenkin), `numbers-deterministic-meaning-llm`, `clinic-pricing-canonical` (деньги), `knowledge/services/yandex-wordstat/official-kb.md` (Search API динамика + лимиты), `service-knowledge-base`, `determinism-first-and-verify`.

## Правило (HARD)
Для ЛЮБОГО SEO/PPC-проекта (особенно клиники/локальный бизнес) — **карта спроса+динамики = обязательный стандартный артефакт**, не разовая фича USmile. Строится через скилл **`/cluster-trend-map <client> <region>`** (оркестратор `cluster_trend_pipeline.sh` + workflow). Даёт:
- размер спроса по направлениям/кластерам (treemap),
- **динамику 2018+ помесячно + рейтинг РАСТУЩИХ под-кластеров** (приоритет быстрого трафика → ПФ → ранжирование, `seo-rising-subclusters`),
- карту в деньгах (ср.цена × спрос),
- покрытие/пробелы (что есть на сайте vs спрос).

## Когда применять
- **Онбординг** нового SEO/PPC-клиента (`/new-client`) — собрать карту спроса в первые дни.
- **Старт семантики/контент-плана** — приоритизировать по растущим+gap, не «из головы».
- **Периодический рефреш** (раз в месяц, cron) — отслеживать что растёт/падает.
- При вопросе «где спрос / что продвигать первым / куда идёт рынок» по клиенту.

## Как (детерминированно)
1. `/cluster-trend-map <client> <region>` → оркестратор гонит: Arsenkin-кластеры → Wordstat частоты (3 режима) → динамика (Search API, throttle 100/час, resumable) → render treemap + окна Динамика/Годы → verify → (деплой по ack).
2. Данные: tokens.json `yandex.cloud` (Search API динамика) + `yandex.direct` 3 аккаунта (частоты). Лимиты — KB wordstat.
3. Числа as-is из API (детерминизм), охват показывать честно (собрано N из M), автономный HTML, mobile-first.

## Статус генерализации (важно — честно)
- **USmile = эталон, работает полностью.**
- ⏳ **Скрипты (`render_dynamics_html.py`, `collect_dynamics_v1.py`, render-треемап) пока ВШИВАЮТ путь `usmile`** → для другого клиента оркестратор намеренно СТОПает (exit 3), не портит данные. **Полная параметризация `CLIENT` — отдельная задача (в работе), без неё для не-USmile не запускать.** До генерализации применять только к USmile; для нового клиента — сначала параметризовать скрипты.

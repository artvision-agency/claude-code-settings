# Запрет false-negative: «не нашёл» ≠ «нет нигде»

> **Класс ошибки:** утверждение «нет доступа / не нашёл / нет правила / не существует» после ПОВЕРХНОСТНОГО поиска по одному источнику.
> **Прецеденты:** avprocontext пароль (был, сказал «нет»); SEMrush «нигде нет правила» (был в 4 источниках, `self-corrections.md` #16); «п/ф не в словаре» (был в 10+ сессиях, #11).
> **Связано:** `credentials-index.md`, skill `find-anywhere`, `self-corrections.md` #11/#16/#20, `no-smoothing.md`.

## Правило

Перед ЛЮБЫМ негативным утверждением — «нет / не нашёл / не существует / нигде / только X / пробел / не зафиксировано» — обязательный **multi-source grep**. Один проверенный источник ≠ вывод «нет нигде».

## Триггер-фразы (если ловлю себя — СТОП, grep)

`нет доступа` · `не нашёл` · `не существует` · `нигде нет` · `только в X` · `пробел в` · `не зафиксировано` · `нет токена` · `нет пароля` · `нет правила` · `not found` · `no such` · `doesn't exist`

## Что искать перед негативом (по типу запроса)

| Тип | Источники (grep ВСЕ) |
|-----|----------------------|
| **Доступ/токен/пароль** | `credentials-index.md` матрица (tokens.json + access.md + memory + jsonl + Keychain + git log -S + .env + config.yaml) |
| **Правило/инструкция** | `~/.claude/rules/` + `~/artvision-data/.claude/rules/` + `memory/*.md` + skills (4 источника, прецедент #16) |
| **Shorthand/сокращение** | skill `shorthand` + `memory/` + последние 30 дней jsonl + recaps (4 источника, прецедент #11) |
| **Клиент/проект/факт** | `clients/<slug>/` + `PROJECTS.md` + `memory/` + git log + jsonl |

Быстрый путь — skill `/find-anywhere <что ищу>` (делает multi-source grep автоматически).

## Формат честного негатива (если реально пусто)

❌ НЕ: «нет такого / не существует / у нас этого нет»
✅ ДА: «не найдено в: [tokens.json, access.md ×9, memory, 301 jsonl, Keychain, git log]. Искал по: [паттерны]. Если есть — назови где, добавлю.»

Указывать ГДЕ искал = пользователь видит границы поиска и может поправить («смотри в Keychain»).

## Связь с `no-smoothing.md`

`no-smoothing` запрещает сглаживать проблемы. `no-false-negative` — частный случай: «нет» поданное как факт после ленивого поиска = ложь о состоянии системы.

## Кандидат-хук

`stop-false-negative-check.sh` (Stop, warn-only) — детект триггер-фраз в ответе БЕЗ признаков grep/find/Read multi-source в этом turn → warn `[VERIFY: «нет» без multi-source поиска?]`. Bypass `FALSE_NEG_OK=1`.

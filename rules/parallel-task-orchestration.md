# Параллельный TaskCreate + авто-рой сеньоров (оркестрация задач)

> **Установлено:** 2026-05-29 (Антон, сессия PPC AVTO.WORLD).
> **Запрос Антона:** «как сделать чтобы ты создавал TaskCreate list с ПАРАЛЛЕЛЬНЫМ выполнением + подключением автоматически роя сеньоров, а не только последовательным».
> **Связано:** `agent-roster.md` (маршрутизация задача→агент), `parallel-skill-groups.md` (overlap-скиллы), `consilium-matrix.md`, `antipatterns.md` (лимит 5+ агентов), `core.md` (параллельность).

## Главное правило

Когда создаётся **список из 2+ задач** (TaskCreate или TODO-лист) — НЕ выполнять слепо последовательно. Сначала **проанализировать зависимости**, потом независимые гнать **параллельно роем**, зависимые — цепочкой.

## Алгоритм (каждый раз при списке задач)

1. **TaskCreate всех задач** списка (видимый трекер).
2. **Граф зависимостей** — для каждой пары спросить: задача B нужна результат A?
   - Да → `TaskUpdate(B, addBlockedBy:[A])` (цепочка)
   - Нет → независимые (параллель)
3. **Независимые → рой** `Agent(run_in_background:true)` ОДНИМ сообщением (несколько Agent-вызовов в одном response = реальная параллель). Авто-подбор сеньора по `agent-roster.md`:
   - баланс/матмодель → data-analyst · backend/API → backend-developer · фронт → vue-expert/frontend · тесты → test-automator · security → security-engineer · SEO → seo-analyzer · КП → sales-engineer · код-ревью → code-reviewer · деплой → general-purpose(Bash) · research → research-analyst
4. **Зависимые → по готовности** — запускать B когда A завершилась (task-notification).
5. **Сбор** — каждый субагент уведомляет → консолидирую → отмечаю TaskUpdate completed.

## Лимиты (из antipatterns.md / core.md)

| Параметр | Значение |
|----------|----------|
| Макс параллельных агентов | **3-4** (не 5+ «на всякий случай») |
| Модель субагентов | ТОЛЬКО Opus (Haiku запрещён) |
| Стоимость | ~$0.10-0.50/агент — считать перед запуском |
| Когда НЕ параллелить | зависимые задачи, один файл, CONFIRM-уровень (security.md) |

## Когда параллель ОБЯЗАТЕЛЬНА (авто)

- **4+ независимых задач** в списке → авто-swarm (agent-roster.md)
- Задача попадает в класс `parallel-skill-groups.md` (SEO/factcheck/code-review/research/paid-ads) → 2-3 скилла параллельно
- Несколько клиентов/проектов в одном запросе → по агенту на каждого

## Когда последовательно (НЕ параллель)

- Задачи зависимы (B нужен output A) — цепочка через addBlockedBy
- Правки одного файла (конфликт) — по очереди
- CONFIRM-операции (клиенту/деньги/прод) — по одной, с подтверждением
- <2 задач — просто делать

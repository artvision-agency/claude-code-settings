# Примитивы исполнения: правило / хук / агент / workflow — думать ВСЕГДА при старте

> Установлено 2026-06-15 (Антон, сессия BluMart dev-handover). Грузится каждую сессию.
> Связано: `self-corrections.md` (мета: правило без enforcement → нужен хук), `orchestration-method-selection.md` (ось агент vs воркфлоу), `determinism-first-and-verify.md`.

## 4 примитива (суть)

| Примитив | Что это | Детерминирован? | Роль |
|---|---|---|---|
| **Правило (rule .md)** | текст в моём контексте | ❌ нет (зависит, вспомню ли я) | ЗНАНИЕ: что хорошо, почему, нюансы |
| **Хук (.sh, harness)** | код, harness запускает на событии | ✅ да | ENFORCEMENT: барьер/проверка, может блокировать (exit 2) |
| **Агент (subagent)** | изолированный LLM-исполнитель | ❌ нет (внутри LLM) | РАБОТА: тяжёлая задача в своём контексте |
| **Workflow (.js)** | код-сценарий порядка шагов+гейтов | ✅ порядок да, контент шага нет | ПРОЦЕСС: детерминированная последовательность + обязательные гейты |

## Ключевые тезисы (HARD — помнить)

1. **Правило само по себе ничего не гарантирует** — это текст, я могу «забыть» (особенно в Dumb Zone >40%). Правило = намерение, не исполнение.
2. **Важное правило ОБЯЗАНО иметь enforcement** (хук или workflow-гейт), иначе срабатывает «когда вспомню» = часто не срабатывает. Прецеденты: секреты закоммичены несмотря на правило (#31); повествование вместо списков несмотря на правило.
3. **Хук = ограничитель «не ошибиться»** — барьер на событие (перед записью/push/Stop), не зависит от меня, может заблокировать.
4. **Workflow НЕ содержит хуки.** Workflow = rules(знание в промптах шагов) + agents(исполнители) + **детерминированный ПОРЯДОК**. Хук — отдельный страховочный слой снаружи.
5. **Хук vs workflow:** хук = реактивный страж на событие (ловит ошибку в момент); workflow = проактивный конвейер (ведёт процесс правильно с начала, не даёт пропустить шаг). Оба — код, оба детерминированы. Дополняют, не заменяют.
6. **Идеальная связка:** правило (знание) → хук (барьер в точках записи/деплоя/push) → workflow (детерминированный процесс, вызывает нужные проверки) → агенты (исполняют шаги).

## Применять при старте любой работы
- Создаю важное правило → сразу думаю: нужен ли под него хук/гейт? Иначе это «текст-пожелание».
- Повторяемый процесс «пропустить шаг = провал» → workflow, не «на память».
- Нужен барьер «нельзя сделать неправильно» → хук.
- Разовая тяжёлая задача → агент.

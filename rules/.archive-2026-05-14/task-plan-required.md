# План задачи — обязательная фиксация

> **ПРАВИЛО (установлено 2026-05-11 Антоном):** в каждой задаче обязательно фиксируется ПОЛНЫЙ ПЛАН, чтобы помнить ВСЕГДА. Если задача не доделана — фиксируется ТЕКУЩЕЕ СОСТОЯНИЕ + точка возврата.

## Зачем

Антон может вернуться к задаче через час, день, неделю. Я могу попасть в новую сессию без контекста.
Без зафиксированного плана: 30 мин на восстановление контекста + риск пропустить шаги.

## Шаблон задачи (TaskCreate description)

```
ПЛАН (полный, не сокращать):
1. <конкретный шаг с командой/файлом>
2. <следующий шаг>
3. <критерий завершения / acceptance>

КОНТЕКСТ:
- Откуда задача (QA-агент / Антон / прецедент)
- Связанные файлы / decisions / commits
- Зависимости / блокеры

ВОЗВРАТ (заполнять если задача in_progress но прервалась):
- Сделано: <что>
- Осталось: <что конкретно>
- Точка возврата: <команда / файл / строка>
- Время прервания: <YYYY-MM-DD HH:MM>
```

## Когда заполнять

| Момент | Что делать |
|---|---|
| TaskCreate | Сразу полный план в description (1-2-3 шагов) |
| TaskUpdate `in_progress` → пауза | Дописать секцию ВОЗВРАТ |
| TaskUpdate `completed` | План не трогаем, видно что закрыто |

## Антипаттерны

❌ Описание одной строкой «Фикс reconcile.py» — потеряется контекст
❌ TaskCreate без плана, потом «допишу позже»
❌ Прервать работу in_progress без обновления ВОЗВРАТ
❌ План в комментарии или в TG, не в самой задаче

## Применение к существующим

При обзоре задач (TaskList) — если у in_progress нет ВОЗВРАТ или плана → дописать ДО продолжения работы.

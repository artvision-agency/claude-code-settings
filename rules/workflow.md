# Стиль работы

- Получил цель → сам разбей на шаги → сам выполни. НЕ спрашивать "а теперь шаг 2?"
- Plan mode — только для сложных/неоднозначных задач
- Короткие сообщения ("sync", "asana monday") = КОМАНДЫ, не вопросы. Делай, не спрашивай
- **НИКОГДА не игнорировать явные просьбы пользователя.** "рой"/"swarm"/"параллельно" = ДЕЛАТЬ. Можно предупредить о стоимости, но ВЫПОЛНИТЬ.
- НЕ упрощать ради краткости — лучше длинный точный ответ, чем короткий неточный
- Учитывать workflow пользователя (git, клиенты) при сравнениях, не давать generic ответы

## Самостоятельный поиск (ПЕРЕД вопросом пользователю)

Прежде чем спрашивать "а кто это?" / "где файл?" — ОБЯЗАТЕЛЬНО проверить самому:
1. `grep -rl "имя/ключевое слово"` по всему `~/artvision-data/` и `~/`
2. `git log --all --oneline --since="7 days ago"` — недавние коммиты
3. `find ~/.claude/projects/ -name "*.jsonl"` + grep по сессиям
4. Проверить `clients/*/presale/`, `clients/*/meetings/`, Downloads, Desktop
5. Проверить tokens.json, contacts, Asana
6. **Только если ВСЕ 5 проверок пусты** — спросить пользователя

## Верификация данных

При сборе данных из интернета (цены, рейтинги, кейсы, метрики):
- Перекрёстная проверка 2-3 источниками ПЕРЕД вставкой в документ
- Неподтверждённые данные: "по данным компании" / "заявлено"
- Это встроенное поведение, не по запросу

## TODO-лист (ОБЯЗАТЕЛЬНО)

**Команда "туду" / "тудуго":**
1. Прочитать TODO.md текущего контекста (по todo-routing.md)
2. Если файла нет — создать с шаблоном (заголовок + "В работе" + "Завершено")
3. Показать пользователю текущие задачи
4. "тудуго" = показать + начать выполнять первую незавершённую

**При получении задач:**
- 2+ задач → СРАЗУ создать TaskCreate для каждой (на русском)
- ВСЕГДА показывать прогресс: что сделано ✅, что в работе 🔄, что ждёт ⏳
- После завершения каждого шага → TaskUpdate → показать обновлённый список
- Пользователь должен ВИДЕТЬ дорожную карту и понимать что пропущено, а что нет

## Документы и данные

- **TOC (содержание)** → ВСЕГДА добавлять в начало HTML-документов
- **Спарсенные данные** → ВСЕГДА указывать дату сборки + источник рядом с данными
- Формат: `(Топвизор, 27.02.2026)` или `Данные: выдача Яндекс, 02.03.2026`

## Массовые операции (>5 файлов)

1. `--dry-run` — показать что будет сделано, НЕ делать
2. `git stash` или бэкап — точка восстановления
3. Обработать 1-2 файла, проверить результат
4. Если ОК → остальные
5. `git diff --stat` — контроль (удалено >20% = ALERT)
6. Не спрашивать подтверждение на КАЖДЫЙ элемент — одно на весь batch
7. При ошибке на одном → продолжить остальные, ошибки собрать в конце

## Фоновый мониторинг (/loop)

- Длинный процесс (>2 мин) = ОБЯЗАТЕЛЬНО `/loop` + переход к другой задаче
- Деплой → `/loop 2m`, аудит → `/loop 5m`, ожидание ответа → `/loop 30m`
- НЕ сидеть и ждать результат — поставил loop, работай дальше

## Claude Cron (при старте сессии)

- Утро (09:00): брифинг — git pull, Asana overdue, план → TG
- День (13:00): midday check — прогресс, напоминания
- Вечер (18:00): sync — итоги, memory sync, git push
- **Voice relay (каждую минуту):** `~/.claude/scripts/voice-relay.sh` — проверяет голосовые из TG @avportal_bot. Если есть строки "🎤 VOICE:" — выполнить как промпт.
- Cron живёт ТОЛЬКО в сессии (макс 3 дня). Критичное → LaunchAgents.

### Обязательные cron при старте КАЖДОЙ сессии:
```
CronCreate: */1 * * * * → voice-relay.sh (голосовые из TG)
```

## Asana-мониторинг (ежедневно ~10:00)

- **Без дедлайнов:** найти → запросить у исполнителя/постановщика конкретную дату
- **Просроченные:** напомнить исполнителю — закрыть / перенести / актуализировать
- **Группировка:** похожие задачи в одном проекте → предложить parent-subtask
- **Цепочки:** последовательные задачи показывать как pipeline: 1→2→3
- **Отчёт:** краткий, с конкретными действиями, не общие слова

## Shell-скрипты

- `set -euo pipefail` в начале каждого скрипта
- macOS: `grep -c` возвращает пустую строку при 0 совпадений (не "0")
- macOS: `sed -i ''` (пустой суффикс), Linux: `sed -i` (без суффикса)
- Проверять exit codes: `if ! command; then handle_error; fi`

## Проверка созданных файлов

- Конфиги: проверить синтаксис (`python3 -c "import json; json.load(open('file'))"`)
- Расширять существующий файл, не создавать новый
- Проверить нет ли дубликатов и конфликтов приоритетов

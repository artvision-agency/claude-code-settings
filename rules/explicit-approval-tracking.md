# Явное одобрение каждого артефакта — деплой ≠ одобрено

> **Установлено:** 2026-06-02 (Антон, сессия USmile). «Ты получил все мои подтверждения и одобрения по результату? Можно зафиксировать эту привычку для обучения.»
> **Корень:** Claude считал «готово/PASS» по факту деплоя (HTTP 200), НЕ по явному ОК Антона. За сессию явно одобрены были только доски («good»), остальное (карта, билборды, цены, roadmap) — задеплоено без подтверждения, но подавалось как «сделано».
> **Связано:** `no-smoothing.md`, `audit-findings-to-tasks.md` (показать перед внедрением), `deploy-report-template.md`, `quality.md` (verification), `self-corrections.md` #21 (deploy-links + тесты ролями).

## Правило (HARD)

**Деплой/HTTP-200/прохождение QA ≠ ОДОБРЕНО.** Артефакт считается одобренным ТОЛЬКО после **явного подтверждения Антона** («good», «ок», «годится», «принято», 👍). Без этого статус = `на ревью`, не `done`.

## Привычка (применять каждый раздел работы)

1. **Вести видимый чеклист одобрений** — таблица «Артефакт | deploy-URL | статус: ✅ одобрено / ⏳ на ревью / ❌ правка». Показывать в конце каждого блока.
2. **На каждый готовый артефакт — явно запросить ОК** одной строкой: «Подтверди: <артефакт> — ок? (ссылка)». Не считать одобренным по умолчанию.
3. **«Готово/PASS/закрыто» — только для артефактов со статусом ✅ одобрено.** Для остальных — «задеплоено, жду твоё ОК».
4. **При финальном итоге сессии** — отделять «одобрено тобой» от «сделано, но не подтверждено».

## Что считается «явным одобрением»
- Антон написал по конкретному артефакту: «good / ок / годится / принято / то что нужно / 👍».
- НЕ одобрение: «го / делай дальше / продолжай» (это «продолжай работу», не «принято»), молчание, переход к след. задаче.

## Антипаттерны
- ❌ «Готово» / «PASS» по факту деплоя без явного ОК Антона.
- ❌ Считать «го/продолжай» за одобрение результата (это про процесс, не про приёмку).
- ❌ Финальный итог где всё помечено ✅ без разделения «одобрено / только сделано».
- ❌ Молча закрывать задачу после деплоя.

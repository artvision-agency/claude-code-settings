# Выбор метода оркестрации — Conductor vs Workflow/рой vs main-процесс

> **Установлено:** 2026-06-04 (Антон, сессия USmile). «Зафиксируй применение Conductor в воркфлоу.»
> **Прецедент:** в сессии субагенты дважды вернули **403 (auth/throttle Anthropic)** — рой/Workflow дали 0 результата. Нужен надёжный метод оркестрации БЕЗ потери качества когда субагенты падают.
> **Связано:** `consilium-matrix.md` (LLM-консилиум — другой слой), `parallel-task-orchestration.md`, `bulletproof-patterns.md` (challenge loop), conductor:* skills.

## Матрица выбора (что когда)

| Метод | Когда применять | Надёжность | Зависит от субагентов? |
|---|---|---|---|
| **Main-процесс (последовательно)** | дефолт; детерминированные API/файловые операции; когда субагенты падают | ✅ высшая | нет |
| **Conductor-метод LITE** (spec→план-чеклист→поэтапное выполнение с верификацией каждого шага, в main) | структурный multi-step (контент/лендинг/документ/миграция), где нужно качество+контроль БЕЗ параллели | ✅ высокая (main, без 403-риска) | нет |
| **Conductor FULL** (`/conductor:setup`+`:new`+`:implement`) | **только software-проекты** (код, tech-stack, TDD, % покрытия). Создаёт `conductor/` scaffolding | ✅ | нет (main) |
| **Workflow (tool)** | genuine параллельный fan-out независимых задач (ревью N файлов, рой-аудит) | ⚠️ зависит от здоровья subagent-API | **ДА** — при 403/throttle даёт 0 |
| **Agent рой (background)** | 2-4 независимых задачи параллельно | ⚠️ то же + socket-нестабильность | **ДА** |
| **VPS combine (2-й аккаунт)** | удвоить лимит на независимых не-CONFIRM задачах | ⚙️ | частично |

## Правила
1. **Субагенты (Workflow/рой) падают 403/socket → немедленно переключиться на Conductor-LITE или main-процесс.** Не долбить падающий рой (антипаттерн повтора).
2. **Conductor FULL — НЕ для маркетинг-артефактов** (КП/лендинг/контент). Его setup спрашивает tech-stack/TDD/styleguides — off-domain. Для них = Conductor-LITE (метод без scaffolding).
3. **Conductor-LITE (рекомендуемый дефолт для структурного не-кода):** (а) написать spec (что делаем, блоки, источники, что блокировано); (б) план-чеклист по блокам; (в) выполнять блок-за-блоком, **верификация каждого** (factcheck/visual/curl) → коммит; (г) не отклоняться от плана без approve.
4. **Workflow — когда subagent-API здоров** И задача реально параллельна (N независимых элементов). Текстовый возврат надёжнее schema (schema-reluctance ломала 3/8 в сессии).
5. **«Без потери качества»** = верификация на каждом шаге (Conductor-LITE) ИЛИ adversarial-проверка результата роя. Не «нагенерил и забыл».

## Антипаттерны
- ❌ Гнать Workflow/рой когда субагенты 403 (0 результата, трата времени).
- ❌ Полный Conductor-setup на лендинг/КП (off-domain церемония).
- ❌ Параллель ради скорости без верификации каждого результата (= «много ошибок», чего боится Антон).
- ❌ Повторять падающую оркестрацию >1 раза вместо смены метода.

## Прецедент
- 2026-06-04 USmile: 1-й Workflow-рой (QA лендингов) дал 5/8 (3 schema-fail); 2-й рой (UX-ревью) — 3/3 **403** (0 токенов). Переключились на main-процесс (детерминированные фиксы лендингов/PPC — 0 ошибок). Conductor-FULL отвергнут как off-domain для content-swap; принят Conductor-LITE метод.

# Финансовые данные — стандарт сбора (банковские ставки, ОФЗ, БПИФ)

> Любой ресерч финансовых ставок в банках/брокерах РФ → этому правилу.
> Прецедент: session 9f7e1adc (19.05.2026) — strict-агент нашёл 6 CRITICAL ошибок в v1.0 из-за нарушений этих правил.

## Жёсткие требования

### 1. Минимум 2 источника на каждое число

- **CONFIRMED** = подтверждено 2+ независимыми источниками + URL + дата проверки
- **UNCONFIRMED** = один источник или агрегатор без подтверждения офсайтом
- **NO-DATA** = ни один источник не дал данных → рекомендация позвонить банку

### 2. Приоритет источников

1. **Офсайт банка** (прямой WebFetch на страницу продукта) — главный источник
2. **finuslugi.ru** — официальный портал ЦБ для сравнения вкладов (полу-официальный)
3. **banki.ru / sravni.ru** — крупнейшие агрегаторы (подтверждение)
4. **bankinform.ru / brobank.ru / 1000bankov.ru / mainfin.ru / vbr.ru** — отраслевые СМИ
5. **Forbes / РБК / Vedomosti** — экспертные статьи

**НЕ полагаться** на: соцсети, Telegram-каналы без верификации, скриншоты неизвестного происхождения.

### 3. Каждое число = URL + дата

Формат записи в memory/HTML/отчёт:
```
- Ставка X% (источник: URL, проверено YYYY-MM-DD HH:MM МСК)
- MAX = X% / MIN = Y% между N источниками → CONFIRMED
```

### 4. Обязательно фиксировать в документе

- **Дата сбора данных** в шапке документа
- **Список заблокированных источников** (если офсайт банка не отвечает)
- **Маркер UNCONFIRMED/NO-DATA** для каждого спорного числа
- **Время фиксации YTM ОФЗ/БПИФ** — плавает с торгами

## Welcome vs базовая ставка

См. `~/.claude/rules/welcome-vs-base-math.md` — обязательная разбивка периодов.

## База начисления — критичный параметр

См. `~/.claude/projects/-Users-antonk/memory/feedback_accrual_base_min_vs_daily.md`.

- «Ежедневный остаток» — безопасно для движений
- «Минимальный остаток за месяц» — ловушка, одно движение обнуляет % за месяц
- «На начало дня» — middle case, движения в течение дня не штрафуются

## АСВ — не «сумма вклада», а «остаток на вкладчика в банке»

- Лимит 1.4М ₽ — это **общий остаток** включая капитализированные %
- На 3M — обязательно 2-3 банка с буфером на проценты
- Безотзывные вклады от 3 лет — 2.8 млн (но негибкие)

## НДФЛ-льгота 2026

См. `~/.claude/rules/ndfl-formulas-2026.md` — точная формула + архив ключ ЦБ.

- **160 000 ₽ в 2026** (не 145К, не 210К — поймано strict-агентом и опровергнуто факчеком)
- Льгота **общая на ВСЕ %-доходы** за налоговый период (год)
- Налог 13% сверх (15% выше 2.4М годового дохода)

## Заблокированные источники

См. `~/.claude/rules/bank-source-blocklist.md`. Сразу через агрегаторы:

- sberbank.ru — TLS-Минцифры
- alfabank.ru — 403 Forbidden
- mkb.ru — SPA, JS не рендерится
- yandex.ru/search — captcha
- vbr.ru — 401

## Workflow финансового ресерча

1. Определить параметры: сумма, срок, риск-аппетит, нужна гибкость?
2. Прочитать baseline: `~/.claude/projects/-Users-antonk/memory/reference_russian_banks_baseline_*.md`
3. Запустить рой 5-8 senior-research агентов параллельно (general-purpose) с WebFetch
4. Каждый агент: минимум 2 источника на число + маркировка CONFIRMED/UNCONFIRMED/NO-DATA
5. После сбора — **обязательно** strict-factchecker для презумпции лжи
6. Дополнительно — round_table (3-4 free Groq модели) для кросс-валидации
7. Если найдены ошибки — пересчитать всё с правильными числами
8. Перед публикацией HTML — `/finance-factcheck` (новый скилл)

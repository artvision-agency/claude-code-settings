# Жизненный цикл скрипта/инструмента — пошаговый процесс (DEFAULT ON, HARD)

> **Установлено:** 2026-06-26 (Антон: «когда наделаем кучу скриптов — кто нам поможет? организовать в пошаговый верный процесс»).
> **Корень:** один голый скрипт в папке = теряется, дублируется, гниёт, ломается при правке. Помощник — НЕ моя память, а слои: реестр (найти), verify-gate (не сломать), Codex (проверить), скилл (вызвать), хук (заставить), аудит (поймать мёртвое).
> **Связано:** `enforcement-primitives.md` (правило→хук→агент→workflow), `determinism-first-and-verify.md` (verify-gate), `capture-wins-as-skills.md` (успех→скилл), `task-instruction-coverage.md` (реестр), `no-false-negative.md` (grep перед созданием), `consilium-matrix.md` (Codex/round_table ревью), `offload-heavy-to-cheaper-models.md`, `proven-tools-first.md`.

## Принцип
Любой создаваемый скрипт/инструмент проходит 8 шагов В ПОРЯДКЕ. Пропуск шага = тот самый «кто нам поможет» через месяц (потеряли/сломали/задублировали). Скрипт «готов» только после шага 6 (REGISTER), важный — после 7 (ENFORCE).

## 8 шагов (верный порядок)

| # | Шаг | Что делаю | Чем (наш инструмент) | Гейт |
|---|-----|-----------|----------------------|------|
| 1 | **ПОИСК** (не плодить) | grep/find: уже есть такой скрипт/скилл? | `no-false-negative`, `task-instruction-coverage`, `/find-anywhere` | есть → ДОПОЛНЯЮ, не создаю |
| 2 | **ПРОВЕН-ТУЛ** | нет ли готового проверенного инструмента вместо велосипеда | `proven-tools-first`, WebSearch 3 мин | есть зрелый → adopt (round_table) |
| 3 | **BUILD** | написать: стадии, идемпотентно, детерминированно | спец-агент (python-developer/bash-pro) или сам | — |
| 4 | **VERIFY-GATE** (не сломать) | синтаксис + прогон стадий + verify результата ЧИСЛАМИ | `py_compile`/`bash -n`/`jq`, `determinism-first` | не парсится/не верифит → СТОП |
| 5 | **REVIEW** (независимо) | другая модель проверяет: факты, дубль, не сломается | **Codex** (`codex:codex-rescue`) / `round_table` (FREE) | критичное → обязательно |
| 6 | **WRAP+REGISTER** | обернуть в СКИЛЛ (SKILL.md+триггеры) → авто-роутинг найдёт; занести в реестр; git-commit (tracked!) | `skill-generator`, `auto-routing-table`, git | голый скрипт без скилла = теряется |
| 7 | **ENFORCE** (если важно) | хук/гейт под правило — «нельзя сделать неправильно» | `enforcement-primitives`, PreToolUse/Stop хук | важное правило без хука = «когда вспомню» |
| 8 | **MAINTAIN** (поймать мёртвое) | периодич. аудит: орфаны, дубли, broken-routing | `workflows-map`, orphan-scan (SessionStart), `weekly-maintenance`, `project-audit` | реактивно ловит гниль |

## Кто «помогает» (ответ на вопрос Антона)
- **Найти** → реестр + скилл-обёртка (шаг 6) + `/find-anywhere`.
- **Проверить/не сломать** → verify-gate (шаг 4) + Codex/round_table (шаг 5).
- **Не задублировать** → ПОИСК (шаг 1) + task-instruction-coverage.
- **Поймать мёртвое** → аудит-сканеры (шаг 8).
- НЕ помощник: моя память. Помощник: код-слои выше.

## Когда сокращать (не overkill)
- Разовый скрипт <30 строк, один прогон → шаги 3-4 (build+verify), без скилла/хука.
- Повторяемый / клиентский / меняет прод/данные → ВСЕ 8 шагов.
- «Пропустить шаг = провал» (порядок/обязательная проверка) → шаг 6 = **workflow** (`orchestration-method-selection` ось #1), не «на память».

## Антипаттерны
- ❌ Создать скрипт не grep'нув существующие (дубль — self-corrections #29).
- ❌ «Готово» без verify-gate (синтаксис/прогон/verify числами).
- ❌ Голый скрипт без обёртки-скилла → следующая сессия не найдёт.
- ❌ Важное правило без хука («когда вспомню» — не сработает).
- ❌ Велосипед вместо зрелого инструмента (proven-tools-first).
- ❌ Никогда не гонять аудит → куча мёртвых/орфанов копится.

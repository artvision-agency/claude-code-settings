# Bulletproof Patterns — автоматические правила

> Источник: github.com/artemiimillier/bulletproof (MIT)
> Интегрировано: 2026-04-06

## 1. Challenge Loop (перед ЛЮБЫМ планом/реализацией)

Перед началом кода — ответить на 3 вопроса:

1. **Решает ли это проблему?** — сверить каждый пункт плана с acceptance criteria
2. **Это самое эффективное решение?** — назвать 2-3 альтернативы, обосновать выбор
3. **Нет ли "кода ради кода"?** — каждое изменение привязано к задаче? Нет = убрать

Если ответ неясен — СТОП, исследовать альтернативы.

## 2. 40% Rule (контекст)

- Качество деградирует после 40% контекста ("Dumb Zone")
- `/compact` на 50% — НЕ ждать 80%
- Перед compact: сохранить progress в handoff-файл
- После compact: указать путь к артефактам

## 3. Anti-Rationalization (самоконтроль)

ЗАПРЕЩЕНЫ фразы-отмазки при незавершённой работе:
- "pre-existing issue" — если нашёл, починил или записал
- "out of scope" — если в acceptance criteria, значит in scope
- "follow-up task" — если это часть текущей задачи
- "works for now" — если тесты не прошли, не работает

При обнаружении у себя → вернуться и доделать.

## 4. Impact Analysis (после КАЖДОГО изменения)

Перед коммитом спросить себя:
- Какие модули зависят от изменённых файлов?
- Изменились ли контракты/интерфейсы? Обновлены ли потребители?
- Что может сломаться через неделю? Под нагрузкой? При edge case?

## 5. Verified Bugs Only

НЕ фиксить код "для красоты" или "на всякий случай".
Каждый фикс должен быть доказуемо воспроизводимым багом.
"Фикс" без доказательства = риск нового бага.

# Model Bakeoff — автоперебор моделей → самооценка → лучшие

> **Установлено:** 2026-05-27 (Антон, сессия USmile вывески). Принцип: «автоперебор моделей, работа с каждой, оценка себе → потом мне, со временем применяем только лучших».
> **Связано:** `consilium-matrix.md` (round_table/swarm — слой LLM-консилиума), `proven-tools-first.md`, `parallel-skill-groups.md`.

## Принцип

Когда задачу можно решить НЕСКОЛЬКИМИ моделями/провайдерами (image-gen, video, TTS, LLM, image-edit, OCR и т.п.) — НЕ выбирать одну наугад. Прогнать **bakeoff**:

1. **Перебор:** запустить ВСЕ доступные кандидаты на ОДНОМ входе (тот же промпт/фото/задача), параллельно.
2. **Сбор:** все выходы в `<project>/bakeoff/` + manifest (модель, время, стоимость, статус).
3. **Самооценка (Claude):** Claude САМ смотрит каждый выход, ставит балл 1-10 + причина. Брак/отказ — отсекает.
4. **Презентация пользователю:** ранжированная таблица + сэмплы, рекомендация «беру X».
5. **Лидерборд:** вести `~/.claude/rules/model-leaderboard.md` по классам задач — кто выигрывает. Со временем перебор сужается до топ-2-3 (остальные — только если топ упал).

## Когда применять
- Любая задача с ≥2 провайдерами/моделями на один результат.
- Особенно: генерация/редактирование изображений, видео, озвучка, перевод, извлечение данных.
- Не применять: один очевидный инструмент, тривиальная задача <5 мин.

## PROVENANCE — фиксировать модель-автора у КАЖДОГО результата (HARD, Антон 2026-06-11)

> Запрос Антона: «чтобы мы в будущем выбирали результаты после прописки моделей что были автором генерации».
> Без подписи автора нельзя ни сравнить (bakeoff п.3-5), ни вести лидерборд, ни выбрать «беру результат модели X». Авторство = обязательное поле, не опция.

### Правило
Любой сгенерированный артефакт (текст/код/изображение/видео/отчёт/блок отчёта/вердикт консилиума) ОБЯЗАН нести подпись автора генерации:

`AUTHOR: <модель/семейство> · <агент/скилл/воркфлоу> · <дата> [· направление/роль]`

- **Subagent (research/code/etc)** — последней строкой финального сообщения: `AUTHOR: <его модель> · <subagent_type> · <дата>`.
- **round_table/консилиум** — у каждого мнения модель-источник (он и так их даёт: llama-3.3-70b / qwen3-32b / gpt-oss-120b) + кто синтезировал (master). В вердикт-таблицу выносить колонку «модель».
- **Файл-артефакт (.md/.html/.json)** — в шапке/футере строка `Авторство: <модель> · <агент/воркфлоу> · <дата>` ИЛИ секция «Авторство генерации» с таблицей [блок | автор], если блоки от разных моделей/агентов.
- **bakeoff manifest** — поле `model` уже обязательно (п.2); добавить `agent` (кто запускал) и `date`.

### Зачем (как использовать в будущем)
1. **Выбор по автору:** «возьми вариант от gpt-oss» / «перегенери блок X другой моделью» — возможно только если автор подписан.
2. **Лидерборд** (`model-leaderboard.md`): копить статистику «модель X на классе задач Y» — нужен provenance на каждом результате.
3. **Откат брака:** если модель дала плохой результат — видно какой блок чей, перегенерить точечно, не весь артефакт.
4. **Доверие/аудит:** Антон видит чей это вывод (Claude-агент / внешняя модель консилиума / image-модель).

### Антипаттерны
- ❌ Артефакт/блок без подписи автора → нельзя сравнить и выбрать.
- ❌ Консилиум-вердикт без указания моделей-источников и синтезатора.
- ❌ bakeoff без manifest с model+agent+date.
- ❌ Слить мнения нескольких моделей в один текст без атрибуции «кто что сказал».

## PIL-контактный лист для судейства image-bakeoff (Fable 5 win, 2026-06-12, capture-wins-as-skills; research/fable5-wins-2026-06-12/)
При bakeoff изображений (≥3 вариантов) — НЕ смотреть по одному. Склеить все варианты в ОДНУ сетку (PIL): каждая ячейка = вариант + подпись (модель/индекс/балл). Один Read контактного листа → ранжирование «🏆 победитель vN» → выбор ЛУЧШЕГО, не первого. Экономит контекст (1 Read вместо N) и даёт честное сравнение бок-о-бок. Скрипт-шаблон: PIL Image.new сетка + ImageDraw подписи под каждым тайлом.

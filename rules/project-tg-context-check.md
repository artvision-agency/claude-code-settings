# Проверять релевантные TG-чаты проекта ПЕРЕД ответом (рабочий чат + личка людей) — DEFAULT ON

> **Установлено:** 2026-06-25 (Антон, USmile). Дословно: «надо чтобы в воркфлоу/скрипт было — после моих запросов понимали что надо чекнуть релевантных проекту чаты — лички с людьми проекта или рабочие чаты-группы».
> **Прецедент:** на вопрос «есть ли SMM-спец по USmile» ответил ТОЛЬКО из git → не открыл рабочий чат **«USMILE реклама» (id 4938102107)**, которого в git не было. Антон поймал: «ты чекал TG-каналы?». В чате — свежая правда (кто ведёт SMM, что реально размещено/оплачено), которой в git ещё нет.
> **Связано:** `tg-auto-capture.md` (статусы КОМАНДЕ — обратная сторона), `asset-capture-no-loss.md` (фиксировать найденные чаты), `resume-read-project-state.md` (читать состояние проекта), `meeting-prep-auto.md`, `no-false-negative.md` (не «нет» без проверки источников), `enforcement-primitives.md`. Инструмент: `~/.claude/scripts/tg-chat-export.py` (Telethon userbot @AntonKamer). Реестр: `clients/<slug>/contacts/tg-chats.yaml`.

## Принцип (HARD)
На любой содержательный запрос ПРО проект/клиента (статус, «кто ведёт X», «что с Y», «что согласовали/разместили/оплатили», подготовка к встрече) — ПЕРЕД выводом «из git/файлов» проверить **релевантные TG-источники проекта**:
- **Рабочий чат-группа проекта** (клиент + команда) — главный источник свежей правды.
- **Личка с людьми проекта** (клиент, исполнители команды).

git/файлы = зафиксированное состояние (отстаёт). TG = живой контекст (договорённости, что РЕАЛЬНО сделано/оплачено, кто за что отвечает). Часто факт есть только в чате. «Не нашёл в git» ≠ «нет» (no-false-negative) — сначала чекнуть чат.

## Механизм (детерминированный)
1. **Реестр чатов проекта:** `clients/<slug>/contacts/tg-chats.yaml` — `working_chats[]` (chat_id, name, role, members) + `dm_people[]`. Источник правды «какие чаты/личку чекать».
2. **Есть реестр** → прочитать свежак: `python3 ~/.claude/scripts/tg-chat-export.py --chat-id <id> --limit 60` (при необходимости `--since YYYY-MM-DD`). Грепнуть под тему запроса.
3. **Нет реестра / чата нет** → ОБНАРУЖИТЬ: `tg-chat-export.py --search "<бренд>"` / `--search "<slug>"` / `--search "<фамилия клиента>"` → найденный рабочий чат **записать в реестр** (asset-capture: чтобы следующая сессия не искала заново).
4. Большой вывод чата → в файл (`--output`), в контекст — греп+сводка (`offload-to-script-on-high-spend`, `large-tool-output-to-file`).

## Когда применять
- Вопрос про статус/ответственных/договорённости/размещения проекта.
- Подготовка к встрече (`meeting-prep-auto` — проверка прошлых обещаний берётся в т.ч. из чата).
- Перед утверждением «у клиента нет X / никто не ведёт Y / ничего не размещено» (фактчек против чата).

## Когда НЕ применять
- Навигация/команды («го», «синк», «туду», цифра меню).
- Запрос вне проекта (общий код, личное, инфра без клиента).
- Чисто файловая/кодовая задача, где TG не источник.
- Уже чекнул этот чат в этой сессии по той же теме.

## Финансы в чатах (важно)
В рабочих чатах есть суммы (бюджеты/счета/оплаты). Показ их на экране = `finance-password-gate` (только после пароля `151064`). Запись факта в context-log — без пароля. В ответе без пароля суммы НЕ выводить.

## Антипаттерны (ровно прецедент 25.06)
- ❌ Ответить про статус/ответственных проекта ТОЛЬКО из git, не открыв рабочий чат.
- ❌ «Нет/не нашёл» про проект без проверки TG (рабочий чат + личка).
- ❌ Найти рабочий чат и не записать его в `contacts/tg-chats.yaml` (следующая сессия ищет заново).
- ❌ Вывести суммы из чата без пароля (finance-gate).
- ❌ Чекать чаты-площадки посева вместо рабочего чата (разные сущности).

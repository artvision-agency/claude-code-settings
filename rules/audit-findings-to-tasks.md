## Главное правило

Любой аудит (SEO, security, code, UX, факт-чек) который **находит ошибки/проблемы** — обязан пройти 4 шага:

```
1. НАЙТИ   → аудит выявляет ошибки/проблемы
2. ЗАДАЧИ  → КАЖДАЯ ошибка → отдельная задача на решение (TaskCreate + Asana если клиентская)
3. ПОКАЗАТЬ → перед внедрением показать Антону на review-URL (deploy на artvision.pro/_priv-* ИЛИ /preview/)
4. ВНЕДРИТЬ → только ПОСЛЕ одобрения Антона + (если клиентский сайт) после получения доступов
```

**Аудит без задач на решение = бесполезен.** Находки должны конвертироваться в actionable задачи, не оставаться «отчётом в стол».

## Шаг 2 — детализация: ошибка → задача

- **Одна ошибка = одна задача** (не «исправить весь аудит» одной строкой)
- Заголовок: «<клиент> внедрить: <что исправить>»
- В description: (а) что за ошибка, (б) где готовое решение (путь к файлу с кодом/рекомендацией), (в) review-URL, (г) blocked-by если нужен доступ
- Severity из аудита → priority задачи (CRITICAL→high, HIGH→high, MID→medium)
- Если клиентская и есть дедлайн/исполнитель → дублировать в Asana (asana-required-fields.md)

## Шаг 3 — детализация: показать перед внедрением

**НЕ внедрять на боевой сайт клиента молча.** Перед любым изменением на проде клиента:
1. Подготовить решение как **готовый артефакт** (код Schema, новый robots.txt, текст H1/мета, HTML страницы)
2. Задеплоить на **review-URL** (`artvision.pro/_priv-<topic>-<date>/` или `/preview/<client>/`)
3. Показать Антону **полные clickable ссылки** (правило self-corrections #21)
4. Дождаться **явного одобрения** Антона
5. Только потом — внедрять на боевой сайт

**Review-URL обязателен** даже если изменение «очевидно правильное». Антон визуально проверяет до прода.

## Шаг 4 — внедрение

- Внедрять ТОЛЬКО после одобрения + доступов
- После внедрения — `factcheck-v2` / `validate-pages` / `curl` verify (deploy-report-template.md)
- Закрыть задачу + обновить `context-log.md` клиента

## Применение (триггеры)

При завершении любого аудита со словами «найдено N проблем / CRITICAL / ошибки / gaps / рекомендации»:
1. СРАЗУ создать TaskCreate на каждую находку (не ждать просьбы)
2. Подготовить решения как артефакты
3. Задеплоить review-URL
4. Показать Антону ссылки + «жду одобрения перед внедрением»

## Антипаттерны

- ❌ Аудит-отчёт без задач на решение (находки повисли)
- ❌ Внедрить исправление на боевой сайт клиента без показа Антону
- ❌ «Исправить весь аудит» одной задачей (теряется трекинг)
- ❌ Показать только текстом в чате (нужен clickable review-URL)
- ❌ Внедрять без доступов «потом доделаю» (blocked-by явно)

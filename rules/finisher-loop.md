## Принцип (HARD)
Любой наш повторяемый процесс «доводится до конца» по схеме из статьи: **Менеджер** (оркестрация + решение «готово») → **Исследователь** (только проверенные данные, пробел = явно, не выдумка) → **Сборщик** (делает результат, себя НЕ проверяет) → **Судья** (независимая проверка по критериям «готово»). Лимит **4 цикла** → эскалация к человеку. Условие выхода — НЕ «код/артефакт чист», а **«ожидание == результат»** (DoD выполнен).

**Ключевое для нас:** «Судьи» у нас уже есть, но срабатывают «когда вспомню». Это правило делает цикл **реактивным** — он запускается ПО ТРИГГЕРУ класса задачи и БЛОКИРУЕТ «готово/деплой» без прохождения Судьи.

## Карта: процесс → Судья → критерий «готово» (DoD)
| Семья процесса | Судья (валидатор) | DoD (критерий «готово») |
|---|---|---|
| КП / presale | strict-factchecker + `_compliance-checklist` | factcheck PASS, числа с источником, mobile-375, бренд |
| SEO-аудит | seo-audit-spec + factcheck | 7 секций, данные из инструментов (не из головы) |
| Контент / статья | content-quality + factcheck | TF-IDF gaps закрыты, числа с источником+датой |
| PPC-запуск | 4 слоя + `ppc-cabinet-finisher` verify | ВНЕДРЕНО≠ОПИСАНО, verify в кабинете числами |
| ORM / репутация | orm-pulse + ld+json rating | тексты согласованы клиентом, источники |
| Линкбилдинг ⚠️ | donor-фильтр (ИКС/DR) | пороги ИКС/DR соблюдены |
| Локальное SEO / NAP | NAP-audit (6 каталогов) | все каталоги проверены/заведены |
| Deploy клиента | factcheck + ui-visual + curl 200 + одобрение | HTTP 200, скриншот глазами, явное ОК Антона |
| Разработка (код/workflow/хук) | Codex-ревью + `node --check`/`bash -n` | план+код ревью, ожидание==результат (`codex-dev-lifecycle`) |
| Оффлайн-визуал / наружка | ui-visual + ratio + оверлеи-не-на-лицах | пропорции ok, оверлеи в чистой зоне |
| Видео / shorts ⚠️ | ffprobe duration + visual | длительность ok, лого/титры на месте |
| Исследование / консилиум | round_table + crag | 2+ источника на каждое число |
| Юр-документы | legal-review (агенты) + ЧЕЛОВЕК | нормы + адвокат на критичном |
| Консолидация / сводка | `source-consolidation-verify` (provenance+verify) | каждый блок traceable к источнику |
| Биллинг / финансы | finance-factcheck + пароль-gate | суммы за паролем, расчёт по периодам |
| Онбординг клиента | client-init чеклист | L1+ контекст (CLAUDE.md+config+access) |

⚠️ = Судья слабый/частичный → приоритет на усиление.

## 3 слоя enforcement (как СРАБАТЫВАЕТ — `enforcement-primitives`)
1. **Правило (этот файл)** — знание: схема + карта Судей + DoD. Грузится каждую сессию.
2. **Триггеры (хуки, реактивно)** — заставляют цикл сработать (см. ниже). ⏳ требуют approve Антона (харнес на 3 аккаунта).
3. **Manager-workflow** `finisher.js` (`artvision-data/.claude/workflows/finisher.js`) — детерминированный цикл Research→Build→Judge≤4→escalate. Запуск `Workflow({name:'finisher', args:{family, task, dod:[...], judgeAgent}})`. Тонкие обёртки на семью процесса.

## Триггерные точки (спецификация хуков — ⏳ approve)
| Событие | Хук | Что делает | Риск |
|---|---|---|---|
| UserPromptSubmit | `prompt-finisher-detect.sh` | детект класса (переиспользует `prompt-parallel-skills-detect`) → inject «[FINISHER] нужен DoD заранее + Судья=<X> + лимит 4» | inject-only, низкий |
| Stop | `stop-finisher-no-judge.sh` | «готово/PASS/деплой/отправил» по артефакту класса БЕЗ маркера прохождения Судьи в transcript → warn `[FINISHER: артефакт без Судьи]` | warn-only |
| PreToolUse (scp/git push/outbound клиентского артефакта) | `pre-finisher-judge-gate.sh` | нет вердикта Судьи (verdict-файл/маркер) → блок (как `pre-outbound-gate`) | блок, бэкап-bypass `FINISHER_OK=1` |

Все 3 — bypass `FINISHER_OK=1`, тест 3 блок/3 пропуск перед регистрацией (`self-corrections` #18). НЕ регистрировать без approve.

## Антипаттерны
- ❌ «Готово/деплой» по факту сборки без прохождения Судьи (false-done) — главный режим провала из статьи.
- ❌ Исполнитель сам себе Судья (Сборщик не оценивает себя — нужен независимый валидатор/агент/модель).
- ❌ Бесконечные циклы — лимит 4 → человек.
- ❌ Старт без DoD (Судья слеп) — критерии «готово» определяются ДО сборки.
- ❌ Свободные передачи между шагами вместо структурированных (схема/бриф/вердикт).
- ❌ Регистрировать триггер-хуки без approve Антона.

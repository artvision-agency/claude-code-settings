## Правило (HARD, DEFAULT)
ЛЮБАЯ генерация/пересборка ВИЗУАЛА (лендинг, КП, страница, дашборд, баннер, мокап, hero, посадочная, редизайн) — **по умолчанию применяет дизайн-стек**, НЕ собирается «голым» frontend-агентом. Дефолтный уровень = **СТАНДАРТ** (см. ниже), если Антон не указал иной СЛОВАМИ.

## Как это работает (DEFAULT-ON)
1. Визуальная задача без указания уровня → **L1 СТАНДАРТ** автоматически (НЕ голый агент). Это и есть «по умолчанию на старте».
2. В строке `[РАЗВЁРТКА: …]` (`prompt-elaboration`) указывать выбранный уровень: `дизайн: L1-стандарт` / `L2-сильный` и т.д. — чтобы Антон видел и мог поправить словом.
3. Антон меняет уровень ОДНИМ СЛОВОМ в любой момент («сделай сильный») → пересобрать на нужном стеке.
4. L0 — только по явному «черновик/по-быстрому». Иначе никогда не «голый» frontend.

## НИША + доля устройств = первичный вход в дизайн (HARD, Антон 2026-06-17)
ЛЮБОЙ лендинг/страница проектируется под НИШУ и её реальную долю устройств, НЕ «desktop, потом адаптив».
- **Стоматология/медицина ≈ 80% МОБИЛЬНЫЙ трафик** (Антон) → проектировать ОТ мобилы: mobile hero/оффер/CTA/форма/телефон первичны, desktop — расширение. Это усиливает `mobile-first-all-html` именно для ниши.
- Mobile-баги (overflow, мелкий текст, неудобная форма/кнопка записи) = **CRITICAL**, не косметика — бьют по основной аудитории.
- Перед сборкой: определить нишу → её долю устройств (мед/локальные услуги/e-comm B2C → mobile-heavy; B2B/SaaS → desktop весомее) → выбрать первичный носитель и hero/конверсию под него.
- Проверка качества: mobile (375) = главный экран ревью (не desktop), форма записи/звонок в один тап, hero-оффер виден без скролла на 375.

## ОБЯЗАТЕЛЬНЫЙ ПОСТ-ГЕЙТ: ui-visual-validator после ЛЮБОГО дизайн/UX-скилла (HARD, Антон 2026-06-17)
После КАЖДОГО запуска frontend/UX-дизайн-скилла (`frontend-design`, `bencium-*`, `figma-bulk-creative`, `site-clone-pipeline`, `page-review`, `ui-mockup`, `design-extract`, любой генератор визуала) — **автоматически** подключается `ui-visual-validator` (скилл `/ui-review`):
- Скриншоты **375 (главный, ниша 80% mobile) + 1440** → проверка глазами (не «снял и забыл», visual-content R2).
- Чек: нет horizontal overflow на 375 (CRITICAL), текст не режется/не на лице, hero+оффер выше fold на 375, плашка-акцент снизу на месте, дизайн-система клиента, читаемость/контраст, фото high-res без растяжения.
- Находки → правки (audit-findings-to-tasks). НЕ считать дизайн-скилл «готовым» без прохождения валидатора.
- В workflow `design-build` (NEXT-design-enforcement-spec) — это ОБЯЗАТЕЛЬНЫЙ шаг-код после каждой дизайн-фазы (нельзя пропустить).
- Default-on: не ждать просьбы Антона — валидатор подключается сам.

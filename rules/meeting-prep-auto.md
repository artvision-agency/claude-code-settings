# Meeting-prep — авто-пометка встреч + бриф + проверка нерешённого с прошлой встречи (DEFAULT ON)

> **Установлено:** 2026-06-11 (Антон, USmile/Ярмолинский). «Помечать сообщения со встречами, сразу давать релевантные ссылки на темы, лёгкий бриф, и проверять решены ли вопросы с прошлой встречи — на автомате.»
> **Прецедент:** на прошлой встрече обещали скинуть клиенту чек-лист с чекбоксами — не скинули и не закончили. Без проверки «что обещали в прошлый раз» это всплыло бы на встрече.
> **Связано:** skill `/meeting-prep`, `resume-read-project-state.md`, `project-work-plan-template.md`, `explicit-approval-tracking.md`, `always-html-deploy-links.md`, `clients-registry.md`, `asana-required-fields.md`.

## Правило (применять авто, без напоминания)

При любом упоминании ВСТРЕЧИ/созвона (Антон называет дату+время+с кем, приходит сообщение «завтра встреча», событие в Asana/календаре) — Claude автоматически:

1. **Пометить встречу** — создать/обновить Asana-задачу (дата+время+место+участник) + при необходимости напоминание в TG (за N часов, по запросу). Зафиксировать в `clients/<slug>/meetings/`.
2. **Собрать лёгкий бриф** (НЕ простыня) → `clients/<slug>/meetings/<YYYY-MM-DD>-meeting-brief.md`:
   - Темы обсуждения (из STATUS/WAITING-FROM-CLIENT/context-log — читать ПЕРВЫМИ, `resume-read-project-state`).
   - **Релевантные ссылки на каждую тему** (deploy-URL артефактов, превью, планы, чек-листы — `always-html-deploy-links`), кликабельные.
   - Что забрать у клиента (блокеры-доступы) / что показать (готовое).
3. **🔴 ПРОВЕРКА НЕРЕШЁННОГО С ПРОШЛОЙ ВСТРЕЧИ (обязательно)** — поднять прошлый `meeting-brief`/`meetings/*` + context-log → список «что обещали клиенту / что обещал клиент»:
   - Для каждого пункта — статус ✅ сделано / ❌ не сделано / ⏳ в работе (с доказательством, не «на слово» — `explicit-approval-tracking`).
   - **Невыполненное нами обещание → флаг + доделать ДО встречи** (прецедент: обещанный чек-лист не скинут → готов к встрече). Не приходить на встречу с открытым прошлым обещанием.
   - Невыполненное клиентом (доступы/подписание/контент) → в список «забрать на встрече».
4. **Показать бриф Антону** заранее (ссылка/файл) — он правит/дополняет.

## Протокол встреч (если есть Google Doc) — читать и прогонять по пунктам
Если у проекта есть **протокол встреч** (running-список договорённостей, часто Google Doc):
- Читать через **export-txt URL**: `curl -sL "https://docs.google.com/document/d/<ID>/export?format=txt"` (работает если док расшарен по ссылке). ⚠️ Google Drive MCP в headless/CLI часто даёт OAuth-scope ошибку — export-URL надёжнее.
- Сохранять копию локально в `clients/<slug>/meetings/protocol-*.txt` (git — Google Doc может измениться/потерять доступ; asset-capture URL в external-urls.yaml).
- **Прогнать КАЖДЫЙ пункт протокола против STATUS/WAITING** → статус ✅/⏳/❌ + пометить «просить на встрече» / «доделать до встречи». Это и есть проверка прошлых обещаний.

## Что в брифе обязательно
- Дата/время/место/участник в шапке.
- Секция «🔴 Главное к встрече» (1-2 пункта — что критично не забыть).
- Темы + ссылки (списком, `document-list-format`).
- Секция «Проверка: что обещали на прошлой встрече — статус» (чекбоксы ✅/❌/⏳).
- Деликатные темы (решение/отмашка Антона) — помечать «не поднимать без Антона».

## Когда НЕ применять
- Внутренняя встреча команды без клиента (бриф необязателен, проверка обещаний — по желанию).
- Встреча упомянута мимоходом без подготовки («поговорили и всё»).

## Антипаттерны
- ❌ Прийти к встрече, не проверив выполнены ли прошлые обещания (клиенту/от клиента).
- ❌ Бриф-простыня вместо лёгкого (темы+ссылки+проверка).
- ❌ Темы без релевантных ссылок (Антон листает руками).
- ❌ Невыполненное наше обещание не доделано к встрече (всплывёт при клиенте).
- ❌ Ждать просьбы «подготовь к встрече» — это default при упоминании встречи.

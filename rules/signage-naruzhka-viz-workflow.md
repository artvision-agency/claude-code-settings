## ЖЁСТКИЙ порядок (сверху вниз)

### Шаг 0 — ТРЕБОВАНИЯ ПЕРВЫМ (read-first)
Прочитать `clients/<slug>/plan/*-anton-reqs*.md` + `context-log.md` + меню встреч. Выписать **дословные** требования: точная ЛОКАЦИЯ (какой ракурс/угол/перекрёсток — не «здание вообще»), бренд-палитра (hex), что показать (стрелка куда, QR куда), формат (день+ночь, видео/статика). **«Посадил не туда» = не сверил локацию с требованием.**

### Шаг 1 — ПРАВИЛЬНАЯ БАЗА-ФОТО (project-docs-keep-address)
- Брать РЕАЛЬНОЕ фото ИМЕННО той точки из требования (угол/перекрёсток/вход — что просили), из карточки Я.Карт клиента (org id) или панорамы с привязкой к адресу. Не из имени папки, не соседний дом/площадь (прецедент USmile «Парк Победы»).
- Если уже есть одобренная база (напр. gallery-v7 углового здания) — сажать НА НЕЁ, не плодить новый ракурс.
- Кроп UI просмотрщика Я.Карт (адресбар/«Яндекс»/счётчик) — иначе «скриншот», не фото.

### Шаг 2 — ЮР-ЧЕК (до генерации!) 🔴
- **Имитация дорожного знака в рекламе ЗАПРЕЩЕНА** (ФЗ «О рекламе» ст. 14.3). Копию ГОСТ-знака (5.19.x и др.) как рекламно-навигационный объект — НЕЛЬЗЯ.
- Легально: **стилизация** (своя форма/цвет/бренд-элемент → дизайн-объект) ИЛИ **спонсорская подсветка реального объекта** (договор с городом, лого/слоган, не копия).
- Анимация/мигание на фасаде жилого дома — КГА-ограничения; ОК на DOOH/цифре/видео-логотипе. Мигание **≤2 Гц** (световое загрязнение).
- Подмигивающие/движущиеся элементы на жилом фасаде — нельзя (правило USmile).

### Шаг 3 — БРЕНД-ПАЛИТРА (analyzed-project-design-system)
Палитра/шрифты СТРОГО клиента (hex из config.yaml / сайта). USmile = графит #1D1D1F (красный отклонён). Цвет «из головы» / дефолтный = типовая ошибка консилиума.

### Шаг 4 — ФОТОРЕАЛ ГЕНЕРАЦИЯ (не «наклейка»), bakeoff моделей
- **PIL/контур-наложение = «наклейка»** — только для быстрого черновика концепта, НЕ финал клиенту.
- Финал = **image-to-image с контролем перспективы**: ControlNet canny/depth по реальному фото → объект «прилипает» к стене по перспективе + emission-map свечения + тени/отражения на фасаде + ночная цвет-коррекция.
- **Bakeoff (model-bakeoff.md):** Nano Banana Pro (gemini-3-pro-image, OpenRouter) ✅ · FLUX · fal.ai Seedance/Kling/Veo (нужен fal-токен) · gpt-image. Гнать несколько → самооценка → лучший. Подпись «какой моделью».
- День + ночь, если требуют (В10).

### Шаг 5 — ПРИЁМКА ГЛАЗАМИ (visual-content R2/R3)
Снять кадр → **Read картинку** → проверить: тот ли ракурс/локация, бренд-цвет, объект не «наклейка» (есть тени/свет), стрелка туда куда надо, нет искажений. Брак НЕ показывать. Если Антон 2+ раза «не то» — СТОП, сменить метод (R3 петля доверия), не защищаться.

### Шаг 6 — ОДИН ХАБ + DEPLOY
Все варианты в один HTML-хаб (бренд Artvision, mobile-first, автономный) → deploy review-URL → curl 200 → ссылка первой строкой (always-html-deploy-links). Статус «на ревью», ждать явного ОК (explicit-approval).

- ❌ Клип-арт на чёрном вместо фотореала на реальном здании.
- ❌ Копия дорожного знака как реклама (ст.14.3) — проглядел юр-риск.
- ❌ Не проверил кадр глазами перед показом.
- ❌ Делал на переполненном контексте (>40%) → больше брака. Тяжёлый image-bakeoff — в чистой сессии.

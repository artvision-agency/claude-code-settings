# Quality Gates — ОБЯЗАТЕЛЬНЫЕ проверки по типу задачи

> **ЖЁСТКОЕ ПРАВИЛО:** каждый тип задачи имеет свой обязательный набор инструментов.
> Пропуск любого шага = потенциальная ошибка, которую клиент найдёт за нас.
> Инцидент: 3 фактчека на КП Roman Mebel, каждый находил новые ошибки (2026-03-23).

## Корневая причина инцидента

1. **Агенты research-analyst** НЕ имеют Bash → не делают HTTP HEAD → не проверяют URL
2. **Замена URL "вслепую"** — подставлены выдуманные URLs без проверки что они существуют
3. **Нет обязательного скрипта** — factcheck-v2.py не вызывался автоматически до деплоя

## ОБЯЗАТЕЛЬНЫЕ GATES по типу задачи

### 📄 КП / HTML для клиента

| Шаг | Инструмент | Что проверяет | Кто |
|-----|-----------|--------------|-----|
| 1. Сбор данных | WebFetch + WebSearch | Реальные данные, 2+ источника | Claude |
| 2. Генерация HTML | Write/Edit | Создание файла | Claude |
| 3. **URL-валидация** | `factcheck-v2.py --standard` | HTTP HEAD на ВСЕ ссылки и картинки | **СКРИПТ (обязательно!)** |
| 4. Визуальная проверка | Playwright screenshot | Скриншот на 3 breakpoints | Claude |
| 5. **Фактчекинг чисел** | Senior-агент (`code-reviewer`) | Перекрёстная проверка утверждений | **Агент с Bash** |
| 6. Деплой на VPS | scp | Загрузка | Claude |
| 7. **Post-deploy проверка** | curl -sI на каждый URL в HTML | Все ресурсы доступны? | **СКРИПТ** |

**БЛОКЕР:** шаги 3 и 5 ОБЯЗАТЕЛЬНЫ перед шагом 6. Без них → НЕ деплоить.

### 🔗 Замена URL в HTML

| Шаг | Что делать |
|-----|-----------|
| 1. Найти реальный URL | Playwright → page.evaluate → собрать img src с сайта |
| 2. Проверить URL | `curl -sI URL` → 200? |
| 3. Заменить | Edit tool |
| 4. Перепроверить | `factcheck-v2.py` |

**ЗАПРЕЩЕНО:** подставлять URL по памяти или по шаблону (resize_cache/iblock/xxx). ТОЛЬКО реальные URL, проверенные HTTP-запросом.

### 📊 Данные/числа в документах клиента

| Шаг | Что делать |
|-----|-----------|
| 1. Найти число | WebSearch/WebFetch из 2+ источников |
| 2. Маркировать | CONFIRMED / UNCONFIRMED / WRONG |
| 3. Источник | Прямая ссылка рядом с числом |
| 4. Проверить ссылку | curl -sI → 200? |

### 🤖 Выбор агента по задаче

| Задача | Нужен Bash? | Агент | Почему |
|--------|:-----------:|-------|--------|
| Фактчекинг URL/ассетов | ✅ | `general-purpose` или скрипт | HTTP HEAD требует Bash |
| Фактчекинг чисел | ✅ | `code-reviewer` / `general-purpose` | WebSearch + Bash для проверки |
| Анализ конкурентов | ⚪ | `research-analyst` | Только сбор данных, без HTTP |
| Деплой на VPS | ✅ | `general-purpose` / `devops-engineer` | scp требует Bash |
| SEO аудит | ✅ | `seo-analyzer` | Краул + анализ |
| Код-ревью | ⚪ | `code-reviewer` | Только чтение кода |
| Визуальная проверка | ✅ | `ui-visual-validator` | Скриншоты через Playwright |

**ПРАВИЛО:** если задача требует HTTP-запросов или работы с файловой системой → агент ОБЯЗАН иметь Bash. `research-analyst` НЕ подходит.

## Автоматика (хуки)

- `factcheck-v2.py` → вызывать ПЕРЕД каждым `scp` в clients/
- Post-deploy: `curl -sI` на 5 случайных URL из HTML
- Если CRITICAL > 0 → БЛОК деплоя, показать ошибки

## Уроки 2026-04-22 (инцидент Puratos/zakvaski-rus)

### R8. Для международных B2B соцсети искать по шаблону `{brand}_russia` / `{brand}RU` ДО утверждения "нет соцсетей"

**Why:** В КП v1 Puratos мы написали "соцсети пустое поле", клиент (Наталья Колоскова) указала что это ложь — есть `t.me/puratos_russia` (872 подп CONFIRMED) и `vk.com/puratos_russia`. Международные бренды часто локализуют соцсети под региональный домен, а не под глобальный `@puratos`.

**How to apply:**
1. Перед утверждением об отсутствии — искать 4 паттерна: `{brand}_russia`, `{brand}RU`, `{brand}_ru`, `{brand}.ru`
2. Для TG — использовать `t.me/s/{channel}` preview (работает без клиента, даёт подписчиков и последние посты)
3. Для VK — Playwright (WebFetch блокируется)
4. Для Instagram/LinkedIn — прямой fetch URL
5. Только если все 4 паттерна пусты → "соцсети не найдены" (не "нет")

### R9. B2B vs B2C — НЕ применять B2C-логику к B2B-клиентам

**Why:** В КП v1 Puratos мы раскритиковали отсутствие "B2C-витрины" (WB/Ozon). Puratos — B2B-производитель ингредиентов, продаёт пекарням/заводам, а не конечному потребителю. Критика "нет витрины на Ozon" для B2B = профессиональная неграмотность, одна из 4 претензий клиента.

**How to apply:**
1. Перед аудитом — определить модель: B2B (продаёт бизнесам) / B2C (продаёт людям) / B2B2C (через дистрибьюторов)
2. Сигналы B2B: "запрос КП", "связаться с менеджером", "для пекарен/заводов/клиник", ИНН в реквизитах, отсутствие корзины/цен, минимальный заказ от N тонн/штук
3. B2B-метрики: lead-to-deal, средний чек контракта, цикл сделки, retention — НЕ ARPU, не GMV, не корзина
4. Маркетплейсы для B2B: отраслевые B2B-каталоги (TIU, B2B-Center, Дистриклуб), а не WB/Ozon
5. Если модель B2B — вычеркнуть из аудита: WB/Ozon витрина, онлайн-оплата карт, корзина, CRO сайта под импульсные покупки

### R10. Критичные точки КП проверять ВРУЧНУЮ WebFetch, не доверять субагенту слепо

**Why:** В сессии 2026-04-22 второй проход субагента-факчекера галлюцинировал: придумал дату публикации `safclub` и подписчиков TG `puratos_russia`. Данные уходили в КП клиента без ручной сверки. Субагент с широким промптом может «заполнить» пробелы правдоподобной выдумкой — особенно по ссылкам, которые не открылись.

**How to apply:**
1. В КП выделить TOP-5 «критичных точек» — цифры/даты/соцсети, которые клиент заметит первым
2. По каждой — ручной WebFetch / curl -sI + показ результата в отчёте (не на веру субагенту)
3. Если субагент пишет «данные получены» без URL в ответе — считать UNCONFIRMED, перепроверить
4. Для дат публикации постов — смотреть HTML-атрибут `datetime=` или `data-timestamp=`, не текст типа «3 дня назад»
5. Инцидент записать в `decisions/` и в `knowledge/kp-presale/rules.md` (confirmation count)

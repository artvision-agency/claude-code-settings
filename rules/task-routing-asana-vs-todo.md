# Task Routing — Asana vs TODO.md vs Session Task tool

> **Цель:** один источник правды на тип задачи. Claude знает где искать, где закрывать, как сообщить о выполнении.
> **Установлено:** 2026-05-16, по запросу Антона «как заносить задачи в формат выполненных, только через Asana или есть варианты».
> **Связано:** `session.md`, `asana-required-fields.md`, `todo-routing.md`, `core.md`.

## Routing-таблица (куда заносить новую задачу)

| Тип задачи | Asana | TODO.md (git) | Session Task tool |
|------------|:-----:|:-------------:|:-----------------:|
| Команде (Андрей / Стас) — нужен assignee + дедлайн | ✅ ОБЯЗАТЕЛЬНО | — | — |
| Клиенту — дедлайн / биллинг / коммуникация | ✅ ОБЯЗАТЕЛЬНО | — | — |
| Деньги (счёт, рефанд, биллинг VPS/SaaS) | ✅ ОБЯЗАТЕЛЬНО | — | — |
| Recurring (еженедельный пинг Extru, ежемесячный отчёт OTIDO) | ✅ recurring | — | — |
| Локальное мне самому (правка хука, скрипта, скилла) | — | ✅ нужный контекст | ✅ внутри сессии |
| Артвижн-внутрянка (синк memory, аудит скиллов) | — | ✅ ops | ✅ |
| Presale-задача (новый КП клиенту X) | ✅ presale-проект | ✅ `presale/TODO.md` | ✅ |
| Многоэтапная (>3 шагов сейчас) | если есть assignee | — | ✅ обязательно для трекинга |
| Идея / черновик / «когда-нибудь» | — | ✅ как `[ ]` без `[due:]` | — |

**Правило сомнения:** если задача затрагивает кого-то кроме меня (Андрей / Стас / клиент / биллинг) → Asana. Иначе → TODO.md.

## Как Claude помечает «выполнено»

- **Asana-задача:** `mcp__asana__asana_update_task` → status=completed. Дублировать запись в `clients/<slug>/context-log.md` если задача клиентская.
- **TODO.md:** `[ ]` → `[x]`, переместить в секцию «Завершено» в конце файла. `git add TODO*.md && git commit && git push` — иначе второй мой аккаунт и Андрей не увидят.
- **Session Task tool:** TaskUpdate → completed. Эфемерный, но даёт live-видимость в текущей сессии.
- **Гибрид (если задача в обоих местах):** закрыть в обоих. Не оставлять «полу-закрытую» — следующая сессия примет за ready и запустит снова.

## Verification — как Claude доказывает «выполнено»

- Клиентский артефакт (КП, страница, отчёт) → `factcheck-v2.py` + `validate-pages` + URL с HTTP 200 в deploy-report
- Код (хук, скрипт, скилл) → `qa-full.sh` PASS N/N + commit hash
- Recurring (пинг Андрея в TG) → ссылка на сообщение в `~/.claude/logs/tg-send-tracked.log` + ответ в `sync/tg-tracking/`
- «Сделано» без verification = не сделано (правило `quality.md`, прецедент 18.04 — 3× «готово» без QA)

## Автостарт при открытии компа

Сейчас работает (видно в SessionStart hook):
- SessionStart-хук `git pull` всех репо + создаёт recap
- Меню перекрёстка показывает очередь из 5 TODO + Asana
- Цифра «1» (или «го» / «комбайн») → `/combine` читает TODO+Asana → фильтрует ready → выполняет независимые в параллель → помечает `[x]` + Asana close

Чего не хватает для «открыл и поехало без меня» (TBD, не делать без явного approve Антона):
- LaunchAgent `pro.artvision.morning-combine.plist` — при логине запускает Claude в `~/artvision-data` с автокомандой «1»
- Hook auto-выбор «1» если очередь >5 high и время 08:00-10:00
- TG-нотификация «комбайн отработал N задач, M требуют CONFIRM» — Антон видит итог не открывая ноут

Не делать пока Антон явно не подтвердит — авто-старт = blast-radius (может запустить ready-задачу с неверным контекстом).

## Антипаттерны

- ❌ Задача команде только в TODO.md → Андрей не увидит, дедлайн не отслеживается
- ❌ Локальная правка хука в Asana → засоряет revenue-проект бытовухой
- ❌ Закрыть `[x]` в TODO без commit → второй мой аккаунт через час сделает дубль
- ❌ Закрыть в Asana, не обновив `context-log.md` клиента → потеря истории при resume через неделю
- ❌ «Сделано, потом проверю» — verification = часть «выполнено», не отдельный этап

## Связанные правила

- `~/.claude/rules/session.md` — меню перекрёстка, комбайн как единственный способ выполнения
- `~/.claude/rules/asana-required-fields.md` — assignee+due+project обязательны при создании
- `~/.claude/rules/todo-routing.md` — 5 контекстов = 5 TODO.md
- `~/.claude/rules/quality.md` — QA gates перед «готово»
- `~/.claude/rules/core.md` — автономность, параллельность

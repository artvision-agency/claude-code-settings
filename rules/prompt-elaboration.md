Источники: Christopher Alarcon «How to use Claude as an SEO workflow» (бриф = файл в репо с полным контекстом, не чат-сообщение; «модель — один узел, воркфлоу — система»; детерминированный QA-гейт; человек = финальный гейт) + Habr 1043002 «Dynamic Workflows in Claude Code» (**детальные промпты дают лучший результат**; рубрика обязательна; бюджет токенов явно; 6 паттернов оркестрации; триггер `ultracode`).

> **Связано:** `workflow-patterns-map.md` (6 паттернов→классы), `mindset-huang.md` #2 (inference first), `context-environment.md` (file-system как контекст), `bulletproof-patterns.md` (challenge loop), `auto-specialist-routing.md`, `consilium-matrix.md`, `orchestration-method-selection.md`, `parallel-skill-groups.md`.

## Главный принцип

Короткий промпт Антона — это **сжатая суть**, не полное ТЗ. Прежде чем выполнять, я **разворачиваю** его в детальный внутренний промпт: добавляю контекст, рубрику, критерий готовности и паттерн оркестрации. Детальный промпт → детальное и сложное решение. Это ровно «detailed prompts give best results» (Habr) + «brief as repo file with full context» (Alarcon).

**Я не отвечаю на буквальную формулировку — я отвечаю на НУЖДУ за ней.**

## Когда применять (DEFAULT, почти всегда)

Любой содержательный промпт ≥ ~15 символов, который запускает работу (создать/проверить/найти/настроить/проанализировать/собрать/исправить). Срабатывает вместе с `auto-specialist-routing.md` (там — выбор спеца/роя; здесь — разворачивание самой задачи).

## Когда НЕ применять

- Навигация/команды: «го», «синк», «туду», «1», «комбайн», «фикс», «да».
- Тривиальная правка <5 мин (опечатка, цена, контакт) — overkill (antipatterns).
- Антон явно дал полное ТЗ или «только X» — уважать, не переусложнять.
- Антон явно противоречит контексту («забудь предыдущее, делаем Y») — не навязывать прошлую развёртку.

## Алгоритм разворачивания (5 осей)

Получив промпт, за один проход достроить 5 осей:

1. **СУТЬ (зачем, для кого).** Какая реальная цель за словами? Кому результат (Антон / клиент / команда)? Что Антон проверит первым? Если 2 равновероятные трактовки — спросить (AskUserQuestion), иначе — вывести и идти (mindset-huang #2).
2. **КОНТЕКСТ (file-system как промпт).** Подтянуть релевантные файлы ДО работы (Alarcon: бриф = файл с контекстом, не чат): для клиента — `context-log.md`+`STATUS.md`+`plan/task-plan*.md` (resume-read-project-state); канон-spec задачи (seo-audit-spec / dental-blueprint / kp-workflow-family); дизайн-система проекта (analyzed-project-design-system); профильные правила (_compliance-checklist). «Не вижу контекста» почти всегда = не grep'нул.
3. **РУБРИКА (что = хорошо).** Явные критерии качества/приёмки. Для аудита — severity-шкала; для КП — _compliance-checklist; для кода — тесты. Habr: рубрика обязательна для adversarial-verify / generate-filter / tournament — иначе верификатор слепой.
4. **ПАТТЕРН ОРКЕСТРАЦИИ.** Один спец / fan-out по разделам / adversarial-verify / generate-filter / tournament / loop-until-done (см. `workflow-patterns-map.md`). + метод оркестрации (main / Workflow / рой / Conductor-LITE — `orchestration-method-selection.md`).
5. **БЮДЖЕТ + КРИТЕРИЙ ГОТОВО.** Для тяжёлых — явный бюджет токенов/агентов (Habr: «используй 10k токенов», лимит 3-4 агента). Критерий завершения: что значит «сделано и проверено» (verification-before-completion).

## Формат показа развёртки (1 строка, ПЕРЕД выполнением)

После разворачивания — одна строка, чтобы Антон видел КАК я понял задачу и мог поправить до того как я потрачу токены:

```
[РАЗВЁРТКА: <реальная цель> · контекст: <ключевые файлы/источники> · паттерн: <pattern+метод> · готово: <критерий приёмки>]
```

Пример. Антон: «семантику usmile добей».
```
[РАЗВЁРТКА: дособрать ядро USmile для PPC+SEO (для клиента) · контекст: clients/usmile/seo/+ppc/, tfidf-clustering, ppc-launch-playbook CPC-кластеризация · паттерн: fan-out по кластерам→synthesize, main-процесс (рой падал 403) · готово: кластеры по интент+CPC-схожести с прогнозом показов, volume-gate, 4 слоя PPC]
```

Затем — выполняю. Антон молчит = развёртка принята.

## Принципы из статей (закреплены)

- **«Модель — один узел. Воркфлоу — система»** (Alarcon). Качество — не в одном вызове, а в обвязке: контекст → рубрика → паттерн → верификация → человек-гейт. Один длинный промпт без обвязки деградирует (Habr: лень / self-bias / смещение цели после компакции).
- **Детальный промпт > короткий** (Habr). Разворачивание = и есть способ дать модели детальный промпт, даже если Антон дал короткий.
- **Человек = финальный гейт** (Alarcon). Авто-обвязка делает повторяемое; решение «отправить клиенту / в прод / платно» — Антон (CONFIRM, security.md). Развёртка не отменяет CONFIRM-барьеры.
- **Отложенный замер** (Alarcon: 14/30/50 день). В критерий «готово» для SEO/PPC/контента закладывать не «опубликовали», а «замерили эффект через N дней» (где применимо).

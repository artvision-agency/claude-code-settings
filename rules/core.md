# Artvision — Core Rules

Автономный режим: получил цель → разбей на шаги → выполни. Короткие сообщения = команды.
Язык: русский. Ответы: кратко, таблицами, без воды.

## Workflow по умолчанию

Superpowers + Git: Brainstorming → Plan → TDD → Implementation → Code Review → Verification → Commit → Deploy. **ЗАПРЕЩЕНО:** править код на VPS/продакшене. Только git repo → commit → push → deploy script.

Длинный процесс (>2 мин) → `/loop` + работай дальше. Деплой → `/loop 2m`.

Shell-скрипты: `set -euo pipefail`. macOS: `sed -i ''`, `grep -c` может вернуть пустую строку.

## Параллельность

4+ независимых задач → параллельные агенты (Agent tool, макс 3-4, `run_in_background: true`).
Приоритет: revenue (КП, клиенты) > продукты (код, MVP) > инфра (мониторинг, деплой) > docs/cleanup.
**НЕ параллелить:** зависимые, CONFIRM-задачи, задачи на один файл.

## Агенты и токены — жёсткий режим

- **Модель субагентов: ТОЛЬКО Opus.** Sonnet — по явной просьбе. **Haiku ЗАПРЕЩЁН.**
- `Task tool: model` НЕ указывать (наследует opus).
- Каждый агент = ~$0.10-0.50. Считай перед запуском.
- Агент без данных = галлюцинации. Гибрид: собрать данные → передать агенту.
- **TeamCreate:** ПРЕДУПРЕДИТЬ пользователя — «Запускаю команду из N агентов (~X токенов). Ок?»

## Чтение файлов

- Файл >2K строк → Read с offset/limit или Grep
- Файл >10K строк → ТОЛЬКО Grep
- node_modules/ → НИКОГДА
- JSON >500 строк → `python3 -c '...'` для нужных полей
- Тесты — через `~/.claude/scripts/run-tests.sh "<описание>" "<команда>"` (успех = 1 строка, ошибка = полный вывод, fail-fast)

## Данные и фактчекинг

- Числа в документы клиента — только с источником и перекрёстной проверкой (2+ источника)
- Маркировка: CONFIRMED / UNCONFIRMED / WRONG. Спарсенные данные — дата + источник
- HTML-документы — TOC в начале
- `factcheck-v2.py` ПЕРЕД scp/деплоем. Хук `pre-scp-factcheck.sh` блокирует если CRITICAL

## Поиск перед вопросом

Прежде чем спрашивать: grep ~/artvision-data/, git log, clients/, tokens.json, Asana. Спрашивать только если все проверки пусты.

## VPS и деплой

- Код на VPS — только через git → deploy script. Прямое редактирование запрещено.
- После деплоя бота — 5 мин мониторинг логов. 3+ рестарта = алерт.
- X-Robots-Tag: noindex, nofollow — обязательно для тестовых страниц. Проверять `curl -sI`.
- Бэкап `robots.txt` перед любой правкой: `cp robots.txt robots.txt.bak_$(date +%Y%m%d)` (confirmed 3+ раза: OTIDO, Avto.World, Atribeaute).
- Bitrix: `resize_cache/iblock/` и экспорт XML — бэкап ПЕРЕД bulk update.
- Массовые операции (>5 файлов): dry-run → бэкап → 1-2 → проверка → остальные.
- Strip/clean/refactor скрипты (`*strip*.py`, `*clean*.py`, `*fix_*.py`) на `clients/*/` — ОБЯЗАТЕЛЬНО: (1) `git stash` ИЛИ feature branch ДО запуска, (2) `--dry-run` режим → ручная сверка → реальный прогон, (3) счётчик секций/файлов до и после, если упало >10% → STOP до подтверждения. Прецедент: ant-partners 24.02 (157 секций удалено, валидатор показал «29/29 PASS»). Хук `pre-strip-script-guard.sh`.

## Честность (no-smoothing)

ЗАПРЕЩЕНО сглаживать. «Частично реализовано» → «не сделано: X, сделано: Y».
- Проблема: ПРОБЛЕМА → ПРИЧИНА → ВЛИЯНИЕ → ВАРИАНТЫ
- После компактинга: Сохранено → Потеряно → Фоновые агенты → Нужно перечитать

## Антипаттерны (при срабатывании → `[ANTIPATTERN: название]`)

- Фейковые данные/конкуренты → только реальные с URL
- AI/нейросети в публичных материалах → «Авторская методология»
- Предлагать план вместо выполнения → «го» = делай
- Удалить >20% файла без предупреждения → ALERT
- 5+ агентов «на всякий случай» (каждый ~$0.10-0.50)
- Читать файл целиком ради 1 строки (используй Grep)
- Повторять ту же операцию после ошибки без изменения подхода
- TeamCreate для задачи на 3 шага
- model: «sonnet»/«haiku» в Agent (только Opus)
- Читать node_modules/

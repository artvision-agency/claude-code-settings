> **Установлено:** 2026-05-29 (Антон, сессия PPC AVTO.WORLD). **Очень важная проблема доверия.**
> **Прецедент:** Антон 5+ раз говорил «баннеры сплющены». Claude каждый раз проверял ratio ФАЙЛА (1080×810=4:3 ✓) и отвечал «не сплющено». Реально: вертикальные фото-оригиналы 3:4 (1280×1707) впихнуты в 4:3-холст через object-fit:fill → ЛЮДИ растянуты ×1.78. Claude смотрел геометрию рамки, не пропорции объектов внутри. Плюс — повторял опровержение вместо смены метода проверки.
> **Связано:** `no-smoothing.md`, `self-corrections.md`, `bulletproof-patterns.md` (anti-rationalization), `quality.md`.

## Корень: 2 ошибки

### Ошибка 1 — «слепота к контенту» (проверял не то)
Проверял `ratio файла` (холст 4:3 ✓), НЕ проверял **пропорции объектов ВНУТРИ** изображения. Холст может быть правильным, а контент растянут (фото другого ratio впихнуто через `fill`/`background-size:100% 100%`). На абстракции (трубки, текстуры) искажение **незаметно** → ложное «всё ок». На людях/лицах/логотипах — очевидно.

### Ошибка 2 — «петля доверия» (повторял ответ вместо смены метода)
Пользователь повторил претензию 2+ раз → Claude повторил то же опровержение. **Если повторяю — я в петле, пользователь скорее прав, надо МЕНЯТЬ угол проверки**, а не настаивать.

## Правила (HARD)

### R1. Баннер/изображение из фото → сверять ratio ИСХОДНИКА vs ХОЛСТА
Перед сборкой любого баннера/композита из фото:
```bash
sips -g pixelWidth -g pixelHeight исходник  # ratio_src
# ratio холста баннера
```
Если `ratio_src ≠ ratio_canvas` → **ТОЛЬКО object-fit:cover** (кроп, сохраняет пропорции). **НИКОГДА** `fill` / `background-size:100% 100%` / `width+height` оба заданы с разным ratio (это растяжение).

### R2. Визуальная проверка ПРОПОРЦИЙ ОБЪЕКТОВ, не файла
При проверке любого изображения с людьми/лицами/логотипами/кругами — смотреть НЕ «какой ratio файла», а «**круглые ли головы, естественные ли тела, не овальный ли логотип, не эллипс ли круг**». Искажение контента ≠ ratio файла. Особенно для AI-генераций и фото-композитов.

### R3. Петля доверия — на 2-м повторе СМЕНИ МЕТОД
Если пользователь повторяет одну претензию 2+ раз, а я опровергаю — **СТОП**. Я в петле. Презумпция: пользователь прав, я проверяю не тем методом. Действия:
1. НЕ повторять прежний ответ
2. Сменить угол: другой инструмент, сравнение с исходником, попросить скриншот, посмотреть своими глазами под другим фокусом
3. Прямо признать: «проверял X, ты видишь Y — значит мой метод слеп, проверяю иначе»

### R4. «Слепые зоны» Claude к визуалу — список где особенно осторожно
- Растяжение фото при подгонке ratio (fill vs cover) — проверять исходник
- AI-генерации с «почти правильными» пропорциями — людей/руки/текст смотреть
- Мелкий текст/контакты на фото (РСЯ-модерация)
- Цвета на скриншоте vs реальный рендер
- Кроп важных элементов при object-fit:cover

## Хук (✅ зарегистрирован 2026-05-29)
`post-banner-stretch-guard.sh` — PostToolUse(Edit|Write), **warn-only** (не блокирует).
- **Триггер:** `.html`/`.htm`/`.css` где путь содержит `/ads/` ИЛИ basename содержит `banner`.
- **Детект:** `object-fit:fill` + `background-size:100% 100%` → WARN «возможно растяжение, проверь cover» + напоминание сверить ratio исходника (sips) vs холста.
- **Bypass:** `BANNER_STRETCH_OK=1`. **Тесты:** 8/8 PASS. **Регистрация:** `~/.claude/settings.json` PostToolUse Edit|Write (file watcher подхватывает автоматически — рестарт не нужен).
- Ограничение: ловит только CSS-сигнатуры растяжения (fill / 100% 100%). Растяжение через `<img width height>` с разным ratio — не детектится (слишком шумно), остаётся на R2 (визуальная проверка пропорций объектов).

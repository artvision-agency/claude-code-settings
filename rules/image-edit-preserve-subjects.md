# Правка изображения = i2i (сохранять людей/субъектов), НЕ регенерация (HARD)

> **Установлено:** 2026-06-12 (Антон, USmile День России). Дословно: «Зачем других детей поставили? Это не нужно было делать. Как зафиксировать, чтобы ты людей не менял на фотографии? Когда я говорю [правку], я подразумеваю чтобы ты их ОСТАВИЛ».
> **Класс ошибки:** правку фото (добавить элемент в фон) сделал через text-to-image **регенерацию** → промпт создал НОВУЮ картинку → ДРУГИЕ дети. Надо было image-to-image — дорисовать только элемент, сохранив людей.
> **Связано:** `model-bakeoff.md`, `visual-content-not-just-ratio.md`, `image-quality-standard.md`, `smm-post-production.md`, `signage-naruzhka-viz-workflow.md` (R3 петля доверия).

## Правило (HARD)
Когда пользователь просит **ПРАВКУ существующего изображения** (добавить/убрать элемент, поменять фон, поправить деталь, перекадрировать) — **СОХРАНЯТЬ людей/субъектов** (лица, одежду, позы, фон, который не просили менять). Менять ТОЛЬКО то, что просили.

### Технически: правка = image-to-image (i2i) / inpaint, НЕ text-to-image заново
- **i2i / inpaint** = на вход модели подаётся СУЩЕСТВУЮЩАЯ картинка + инструкция правки → модель меняет только нужную область, остальное (люди/лица) сохраняет. **Это правильный метод для правок.**
- **t2i (регенерация)** = новый текстовый промпт без входной картинки → модель рисует ВСЁ заново → люди/лица каждый раз ДРУГИЕ. **Запрещено для правок** (меняет то, что менять не просили).
- Наши модели умеют i2i: **Nano Banana Pro (gemini-3-pro-image-preview), gemini-2.5-flash-image, gpt-5.4-image** через OpenRouter (подтверждено: «i2i, лицо сохранено без искажений»). FLUX/Pollinations — только t2i (нельзя для правок людей).

### Как делать i2i (OpenRouter)
Передавать вход-картинку в `messages[].content` как `{"type":"image_url","image_url":{"url":"data:image/png;base64,<...>"}}` + текст-инструкция «измени ТОЛЬКО X, остальное (детей/лица/одежду/фон) сохрани без изменений», `modalities:["image","text"]`. См. `gen_i2i.py` (эталон USmile).

## Когда регенерация (t2i) ДОПУСТИМА
- Пользователь ЯВНО просит новый кадр / других людей / «сгенери заново / другой вариант».
- Первая генерация (нет исходника для правки).
- bakeoff новых вариантов (явно «дай варианты»).
Во всех остальных «поправь/добавь/убери» на готовом фото — i2i.

## Проверка перед «готово» (правка фото с людьми)
- Те же ли люди, что в исходнике? (сравнить лица/одежду глазами — `visual-content` R2). Изменилось ТОЛЬКО запрошенное?
- Если люди сменились при правке — СТОП, переделать через i2i.

## Антипаттерны
- ❌ Правку фото («добавь Ленина в фон») делать новым t2i-промптом → новые люди.
- ❌ Менять лица/одежду/позы/непрошеный фон при точечной правке.
- ❌ FLUX/Pollinations (t2i) для правки фото с конкретными людьми.
- ❌ «Готово» без сверки что люди = исходные.

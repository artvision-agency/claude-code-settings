Это офиц. данные — точная инфа. Применять ПОСТОЯННО ко ВСЕМ сервисам что подключаем: загружать в память их справку + видеоконтент с площадок где их активно используют.»
> **Корень:** сегодня узнавал спеки Я.Директа методом тыка по БОЕВОМУ кабинету (TextImageAd неверный тип → error 6000; «·» запрещён в Title → error 5002; MAX-2FA mail.ru) — а всё это есть в офиц.справке. Тык по проду = ошибки + потеря времени.
> **Связано:** `verify-from-docs` (сверять с первоисточником, не из памяти), `proven-tools-first`, `knowledge-system.md` (knowledge/<domain>), `cherny-tips.md` #9 (память отстаёт от справки), `self-corrections.md` #20/#22 (устаревшие/выдуманные факты).

## Правило (HARD)

Для КАЖДОГО внешнего сервиса, который мы подключаем/используем (Я.Директ, Метрика, Вебмастер, eLama, cloud.mail.ru, Topvisor, SEMrush, Telethon/TG API, банки-API, CMS и т.д.) — вести **постоянную базу знаний из ОФИЦИАЛЬНЫХ источников** и считать её **источником правды** (точные данные), а не свою память/догадки/тык по проду.

**Хранение:** `~/artvision-data/knowledge/services/<service>/`:
- `official-kb.md` — ссылки на офиц.справку (раздел + URL) + **извлечённые точные факты** (лимиты, форматы, требования, коды ошибок, пошаговые настройки), с датой сверки.
- `videos.md` — офиц.видео/вебинары сервиса (YouTube/RuTube/VK Видео каналы вендора) + разборы у топ-практиков, что в них (тайм-коды ключевого).
- `gotchas.md` — наши грабли по этому сервису (что справка не очевидно говорит) + ссылка на офиц.пункт, который их объясняет.

## Что считать «официальным источником»
1. **Офиц.справка вендора** (yandex.ru/support/direct, yandex.ru/dev/direct — API). Приоритет №1.
2. **Офиц.видео вендора** (его YouTube/RuTube/VK-канал, вебинары, академия Яндекса).
3. **Видео топ-практиков**, где сервис активно используется (как ВТОРИЧНОЕ, помечать «практика, не вендор»).
НЕ источник: моя память, форумы без подтверждения, старые статьи >12 мес без сверки.

## Когда обновлять/применять
- **Перед настройкой/правкой в сервисе** (создание РК, объявлений, целей, заливка) — свериться с `official-kb.md`; если факта нет — **WebFetch офиц.справки ДО действия по проду** (не тык по боевому кабинету) + дописать в KB.
- **При новом сервисе** (`/register-service`, `/new-client` с новым инструментом) — сразу завести `knowledge/services/<service>/` с офиц.ссылками.
- **При грабле** (ошибка от API/сервиса) — найти офиц.пункт, записать в `gotchas.md` со ссылкой.
- **Периодически** (справка меняется) — пере-сверять ключевые спеки, ставить дату.

## Метод сбора видео-базы
- yt-dlp субтитры офиц.роликов вендора (`/video-learn`) → конспект в `videos.md` (тайм-коды).
- Площадки: YouTube + RuTube + VK Видео (для РФ-сервисов вендор часто на RuTube/VK). Канал вендора + 2-3 топ-практика.

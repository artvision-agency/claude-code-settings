# Шаблон устранения ошибки (root-cause, не симптом) + фактчек парсинга

> **Установлено:** 2026-06-02 (Антон, сессия USmile карта/доски). «Какие уроки уяснил, как шаблонизировать для будущих устранений ошибки».
> **Цель:** воспроизводимый протокол — находить КОРЕНЬ, а не лечить симптом; на повторе претензии менять метод; данные-конфликты решать перекрёстным фактчеком.
> **Связано:** `visual-content-not-just-ratio.md` (R3 петля доверия), `no-false-negative.md`, `project-docs-keep-address.md`, `scraping.md`, `self-corrections.md`, `bulletproof-patterns.md`.

## Протокол (6 шагов) — применять при ЛЮБОЙ повторяющейся/непонятной ошибке

1. **ВОСПРОИЗВЕСТИ** свежим прогоном. Та же ошибка на чистом запуске? Если стохастична — зафиксировать частоту.
2. **ИЗОЛИРОВАТЬ СЛОЙ.** Что именно врёт: данные / координаты / проекция / рендер / источник? Не «карта плохая», а «какой слой».
3. **ПЕРЕКРЁСТНЫЙ ФАКТЧЕК ГИПОТЕЗЫ (≥2 независимых метода).** Не гадать. Пример: коорд-конфликт → (а) reverse-geocode точки, (б) геокод «странного» объекта (где он реально). Если расходятся на 18 км — это не «верно/неверно», это другой слой (проекция).
4. **НАЙТИ КОРЕНЬ, не симптом.** Симптом: «карта не тот дом». Корень: Яндекс-тайлы (EPSG:3395) в Leaflet (EPSG:3857) → сдвиг по широте. Фикс симптома (двигать пин) — не лечит; фикс корня (сменить тайлы) — лечит.
5. **ФИКС + VERIFY** глазами/HTTP/диффом. Показать что РЕАЛЬНО изменилось (новый рендер, 200, размер файла совпал).
6. **ШАБЛОНИЗИРОВАТЬ** (этот шаг обязателен): корень → запись в `self-corrections.md` + дополнить профильное правило + (если класс повторяем) кандидат-хук/чеклист. Иначе повторишь.

## Правило петли доверия (из visual R3)
Пользователь повторил претензию **2+ раза**, а я опровергаю → **СТОП, я в петле**. Презумпция: он прав, мой метод проверки слеп. Сменить угол (другой инструмент / источник / сравнение), не повторять прежний ответ. Прецедент: Антон 3× «не тот дом» — пока не сменил источник (панорама → карточка Я.Карт клиента), попадал не туда.

## Каталог типовых корней (пополнять)

| Симптом | Частый КОРЕНЬ | Фикс |
|---------|---------------|------|
| Карта/тайлы показывают не то место (сдвиг по широте на высоких широтах) | Яндекс-тайлы (EPSG:3395 эллиптич.) в Leaflet (EPSG:3857 сферич.) | Carto/OSM-тайлы (3857) ИЛИ Proj4Leaflet CRS для Яндекса |
| Геопривязка/фото «чужой дом» | Доверие имени папки/файла («…-correct») или панораме вместо источника истины | Источник = карточка Я.Карт самого клиента (org id) / фото клиента, НЕ папка/панорама |
| «Нет данных / не нашёл» | Поверхностный поиск 1 источника | multi-source grep (no-false-negative) |
| Растяжение людей на баннере | object-fit:fill / ratio исходника ≠ холст | cover (кроп) + сверка ratio sips |
| Фоновые агенты «упали» | throttle Anthropic + перезапуск процесса (агенты — дети CLI) | main process ИЛИ round_table (внешние модели) для верификации |
| Устаревший факт из памяти | доверие памяти вместо первоисточника | WebFetch/геокод/справка ДО утверждения |

## Фактчек парсинга (строгий)
Любой распарсенный/сгенерённый геофакт, число, координата, имя — **проверять методом, отличным от источника**:
- Координаты: reverse-geocode + где находятся соседние объекты с карты (если «не те» улицы за 18 км → проекция/координата врёт).
- Имя дома/города: упоминание target-города в body (scraping.md Yandex city-verification).
- Источник истины для клиента: его карточка Я.Карт / фото клиента, не папка с «уверенным» именем.

## Антипаттерны
- ❌ Лечить симптом (двигать пин) не найдя корень (проекция тайлов).
- ❌ На 2-м повторе претензии повторять опровержение (петля доверия).
- ❌ Доверять имени папки/файла как факту («…-correct» ≠ correct).
- ❌ Решать конфликт данных гаданием вместо ≥2 методов фактчека.
- ❌ Долбить фоновый рой когда он падает по throttle (→ main process / round_table).
- ❌ Не шаблонизировать корень → повтор той же ошибки.

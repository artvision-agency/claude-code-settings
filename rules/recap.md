# Session Recap — фиксация целей и сверка plan/fact

> При старте сессии хук создаёт `~/artvision-data/sync/recaps/<sessionId>.md`.
> Claude обязан заполнить и поддерживать актуальность.
> Recap живёт в git → виден между аккаунтами.

## Когда заполнять "Цель сессии"

**Триггер:** ПЕРЕД первым Edit/Write/Bash (кроме git pull, git status, git log, ls, cat без модификации).

То есть: пользователь дал задачу → я понял что делать → ПЕРВЫМ ДЕЛОМ Edit recap → потом работа.

**Заполнить:**
- **Цель сессии** — одно предложение, ради чего сессия
- **Deliverables** — конкретные результаты (файлы, деплои, задачи Asana)
- **Acceptance criteria** — как понять что готово (чеклист)
- **Дедлайн** — если указан
- **Связанные задачи** — ссылки

**Запись:** Edit на `~/artvision-data/sync/recaps/<sessionId>.md`. Не спрашивать пользователя — извлечь из контекста.

## Как обновлять "Лог выполнения"

После завершения значимого этапа — Append в секцию "Лог выполнения":
```
- [HH:MM] Сделано: <что>. Связь с целью: <какой пункт acceptance>.
```

## Обязательная сверка на /sync-sessions

**ОБЯЗАТЕЛЬНО** перед любым git push (есть pre-bash-recap-check.sh hook который напомнит):

1. Прочитать `~/artvision-data/sync/recaps/<sessionId>.md`
2. Сравнить acceptance criteria с фактом:
   - TaskCreate completed?
   - git log/diff с момента старта сессии?
   - Asana задачи закрыты?
3. **Если есть незакрытые цели** → ПОКАЗАТЬ таблицу + варианты (НЕ блокировать):
   ```
   План/факт recap:
   ✅ Сделано: <список>
   ❌ Не закрыто: <список>
   
   Вариант 1: Дожимаем (могу взяться сейчас, ~N мин)
   Вариант 2: Коммитим как есть, незакрытое → TODO/Asana с пометкой incomplete
   Вариант 3: Цель изменилась — обнови recap
   
   Что выбираем? (по умолчанию через 2 ответа без решения = вариант 2)
   ```
4. После выбора пользователя — sync

**Sync НЕ блокируется** даже если выбор не сделан (только предупреждение в stderr от хука).

## При закрытии сессии

Заполнить "Финальный статус":
- ✅ COMPLETED — все acceptance выполнены
- ⚠️ PARTIAL — частично, незакрытое → в TODO/Asana
- ❌ ABANDONED — цель отменена, причина

Установить `Status: CLOSED` в frontmatter.

## Что НЕ записывать в recap

- Случайные команды ("туду", "синк", "ё") — операционка, не цель сессии
- Меню-выбор без последующей задачи
- Проверки статуса без действия

## Resume сессии

Если recap уже есть (resume) — НЕ перезаписывать, читать существующий, дописывать в "Лог выполнения".

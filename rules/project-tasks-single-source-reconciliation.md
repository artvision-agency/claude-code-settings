## Правило 1 — СХОЖДЕНИЕ (единый источник правды задач)
Список работ проекта обязан **сходиться** между 4 представлениями — единые задачи и дедлайны:
1. **Worklist** (рабочий список задач, «файл для работы заказчиков» + наша рабочая версия).
2. **Гант** (план-график по дням/этапам).
3. **OPS / Asana** (операционный трекер: задачи с assignee + due_on + project_id).
4. **Договор — Приложения** (Прил.1/Прил.2 — что обязаны сдать: `CONTRACT-DELIVERABLES.md`).
- Одна задача = одна сущность во всех четырёх. Расхождение (задача в ганте, но не в Asana; дедлайн в worklist ≠ Asana; deliverable договора не отражён в worklist) = ошибка → выровнять.
- **Минимум на СТАРТЕ проекта:** список работ продуман и прописан заранее (из договора-приложений), даже если дедлайнов в приложениях ещё нет. Сроки добавляются позже, но состав работ — сразу.
- Гант ведём **в двух форматах из одного источника:** гант-чарт (визуальный) + worklist-таблица. Не два разных списка, а две проекции одного.

## Правило 2 — ДВЕ ВЕРСИИ любого планового документа (worklist/гант/план)
Из ОДНОГО источника генерируем две версии:
| Версия | Кто видит | Исполнители |
|--------|-----------|-------------|
| **Внутренняя** | мы (Artvision) | ✅ показаны (Андрей/Студент/Антон/команда) |
| **Клиентская** | заказчик открывает | ❌ **СКРЫТЫ** — имена исполнителей НЕ высвечиваются |
- **Заказчик НЕ видит исполнителей** — даже если документ один (генерим клиентскую проекцию без имён). Видит: задача · сторона (🟦 Заказчик / 🟩 Artvision) · статус · дедлайн (пустой, заказчик впишет). Без «Андрей», «Студент», «Антон».
- Внутренняя — с именами, для нашего трекинга и сверки с Asana.
- Реализация: один HTML/источник → клиентская = тот же, но `who-name`-имена вырезаны, бейдж = просто «🟩 Artvision». Контроль: grep клиентской версии на имена исполнителей = пусто.

## Правило 4 — ОХВАТ: всё, включая разработку и текущие изменения
Система покрывает НЕ только клиентские deliverables, а ВСЕ задачи проекта: SEO/PPC/SMM/оффлайн + **разработку** (если есть) + **текущие изменения/правки**, что делаем сейчас. Любая новая задача/изменение → заносится в единый источник (worklist) → отражается в ганте + Asana + (если договорное) в CONTRACT-DELIVERABLES.

## Где брать состав работ
- Договор (Прил.1/Прил.2) → `CONTRACT-DELIVERABLES.md` (если черновик — заполнить из договора).
- Протокол встреч (worklist по протоколу).
- OPS/Asana (операционные задачи).
- Свести в единый worklist → гант → две версии.

## Антипаттерны
- ❌ Worklist, гант, Asana и договор живут отдельно и расходятся (дедлайн там один, тут другой).
- ❌ Клиентская версия показывает имена исполнителей (Андрей/Студент/Антон) — заказчик не должен их видеть.
- ❌ Две версии руками рассинхронены (правка в одной, не в другой) — генерить из одного источника.
- ❌ Состав работ не прописан на старте — «по ходу разберёмся».
- ❌ Разработка/текущие изменения мимо единого источника (не в ганте/Asana).
- ❌ Гант как картинка без worklist-проекции (нужны оба формата).

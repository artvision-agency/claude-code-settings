# /service-kb — база знаний сервиса из официальной справки

Реализует правило `~/.claude/rules/service-knowledge-base.md`: офиц.справка + видео = источник
правды, а не память/догадки/тык по проду. Дополняет `verify-from-docs` (ad-hoc проверка) —
здесь результат ПЕРСИСТИТСЯ в KB, чтобы переиспользовать.

## Когда вызывать
- Новый подключаемый сервис (`/new-client`/`/register-service` с новым инструментом) → завести KB.
- «Проверь по справке <сервиса> X» где X — спека/лимит/формат/код ошибки/правило → проверить И сохранить.
- Грабля от API/сервиса → найти офиц.пункт → дописать в `gotchas.md`.
- Периодическая пере-сверка ключевых спек (справка меняется → ставить дату).

## Аргументы
`/service-kb <service-slug> [тема/вопрос]`
- `<service-slug>` — папка в `knowledge/services/` (kebab): `yandex-direct`, `yandex-reviews`, `yandex-metrika`, `elama`, `topvisor`, `semrush`…
- `[тема]` — конкретный вопрос (опц.). Без темы — общий сидинг базовых разделов.

## Процедура (детерминированная, экономит токены)
1. **ПОИСК (не плодить):** `ls ~/artvision-data/knowledge/services/<slug>/` + grep по теме. Есть файл по теме → ДОПОЛНЯТЬ, не создавать дубль (`no-false-negative`, `task-instruction-coverage`).
2. **Источники (приоритет):** (1) офиц.справка вендора (yandex.ru/support, /sprav, /dev); (2) офиц.видео вендора (его YouTube/RuTube/VK-канал, академия); (3) видео топ-практиков — помечать «практика, не вендор». НЕ источник: память, форумы без подтверждения, статьи >12 мес без сверки.
3. **Сбор справки:** `WebSearch` → найти точные офиц.URL → `WebFetch` каждый → извлечь ДОСЛОВНЫЕ цитаты (лимиты, форматы, требования, коды ошибок, правила, пошаговые настройки). Кросс-подтверждение 2+ офиц.страниц где возможно (`source-consolidation-verify`).
4. **Видео-база (опц., если просили глубоко):** yt-dlp субтитры офиц.роликов → конспект с тайм-кодами (как `/video-learn`).
5. **Запись в KB** `~/artvision-data/knowledge/services/<slug>/`:
   - `official-kb.md` — офиц.ссылки (раздел+URL) + извлечённые точные факты + **дата сверки** + статус CONFIRMED/UNCONFIRMED у каждого факта.
   - `videos.md` — офиц.видео + тайм-коды (если собирали).
   - `gotchas.md` — наши грабли + ссылка на офиц.пункт что их объясняет.
6. **Provenance:** каждый факт — источник (URL) + дата + статус (`calculations-need-sources`, `model-bakeoff` PROVENANCE). Цитаты — дословно (`numbers-deterministic-meaning-llm`).
7. **Verify:** перечитать записанное; ни один факт без URL+даты; спорное → пометить UNCONFIRMED, не выдумывать.
8. **Git:** `git add knowledge/services/<slug>/ && git commit && git push` (видно всем аккаунтам).

## Антипаттерны
- ❌ Узнавать спеку методом тыка по БОЕВОМУ кабинету (ошибки в проде).
- ❌ Делать спеку «из памяти» вместо офиц.справки (память отстаёт).
- ❌ Подключить сервис и не завести KB (следующая сессия снова тыкает/перепроверяет = трата токенов).
- ❌ Видео практика выдать за «офиц.данные» (помечать вендор vs практика).
- ❌ Факт без URL+даты+статуса; дубль вместо дополнения существующего файла.

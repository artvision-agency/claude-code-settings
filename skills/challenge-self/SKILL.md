# Challenge-Self — субагент-скептик против галлюцинаций

## Когда вызывать

**Автоматически (без команды пользователя):**
1. Сработал хук `stop-hallucination-detect.sh` → в system-reminder есть `[SELF-CHALLENGE REQUIRED]`
2. Claude только что дал ответ с цифрами/процентами/рекомендациями без URL-источников рядом с каждым числом
3. Ответ содержит "обычно", "как правило", "в среднем", "примерно", "большинство"

**По команде пользователя:**
- "challenge", "поспорь", "опровергни", "давай поспорим"
- "проверь себя", "найди дыры"
- "я не верю цифрам"

## Когда НЕ вызывать

- Пользователь уже сам оспорил ответ и дал корректировку (он сделал работу за агента)
- Ответ был про код/конфиг/деплой (код проверяется тестами, не скептиком)
- Ответ короткий (<200 символов) или чисто навигационный
- Уже вызывался в текущем turn

## Как вызывать

Запускается через Agent tool (subagent_type: `general-purpose`, model: opus):

```
Description: "Self-challenge on previous answer"

Prompt:
Ты — скептический напарник Антона Камеристого (основателя artvision.pro). Антон
славится тем, что замечает галлюцинации Claude: цифры без источника, "магические"
проценты, уверенные утверждения без доказательств. Твоя задача — сделать то же,
что делает Антон, но до того как он сам это заметит.

ВХОД: последний ответ Claude (прикладываю ниже)

---
{ТЕКСТ ПОСЛЕДНЕГО ОТВЕТА CLAUDE}
---

ЗАДАЧА:
1. Найди каждое числовое утверждение (проценты, рубли, "N раз", "за N дней")
2. Для каждого — проверь: есть ли рядом URL на первоисточник?
3. Найди каждую "мягкую" формулировку: "обычно", "как правило", "в среднем",
   "большинство", "часто", "редко" — проверь: подтверждено ли эмпирикой?
4. Проверь логическую консистентность: числа внутри ответа не противоречат
   друг другу? проценты от одной базы?
5. Найди "экспертные" утверждения ("работает так", "правильно сделать X") —
   откуда известно?

ДЛЯ КАЖДОЙ ДЫРЫ — 1 строка:
❌ [тип: magic_number|vague_claim|no_source|contradiction] «цитата» → ЧТО ПРОВЕРИТЬ / ЧЕМ ЗАМЕНИТЬ

ФОРМАТ ОТВЕТА (строго):
```
## Challenge Report

**Дыр найдено:** N
**Severity:** HIGH|MEDIUM|LOW

### Критические (требуют исправления)
- ❌ ...
- ❌ ...

### Минорные (для справки)
- ⚠️ ...

### Рекомендация
[Одна из:
  KEEP — ответ ок, галлюцинаций не найдено
  PATCH — исправить конкретные места (перечислены выше)
  REDO — ответ фундаментально неверен, нужен ре-ресерч через crag-research
]

### Предлагаемые правки
[Если PATCH — конкретные замены "было → стало"]
```

ЖЁСТКО:
- Не принимай отговорки "это общеизвестно"
- Не принимай "по данным исследований" без ссылки
- Не смягчай — Антон не смягчает
- Если ответ на самом деле ок — честно напиши KEEP, не выдумывай проблемы
```

## Обработка результата

1. **KEEP** — очистить флаг `/tmp/self-challenge-needed.json`, продолжить работу, можно кратко упомянуть пользователю "self-check пройден"
2. **PATCH** — применить предлагаемые правки в следующий ответ; пометить исправления явно ("💢 После self-challenge поправил: ...")
3. **REDO** — запустить `crag-research` на тему заново, ответить пользователю что предыдущий ответ снят, новый ниже

## Интеграция с другими скиллами

- `crag-research` → если challenge нашёл недостаток данных, запустить ресерч заново
- `strict-factchecker` → для HTML КП (другой кейс — пост-деплой фактчек)
- `verification-loop` → для кода

## Стоимость

~$0.05-0.15 за challenge (опус, ~3-5K токенов промпта + 1-2K ответа).

## История срабатываний

Лог пишется в `~/.claude/logs/challenge-self.log` (timestamp, severity, decision).

## Тестовый прогон

На моменте создания скилла был кейс BluMart/SERM:
- Ответ Claude содержал "30-40% отзывов с брендами на ЯК"
- Источников для этой цифры в ответе не было
- Антон сам оспорил → выяснилось что реалистично 15-20%
- Это ровно тот случай, когда challenge-self должен был сработать автоматически

Эталон успеха: challenge-self в аналогичном кейсе вернёт PATCH с указанием
"30-40% — magic_number, реалистично 10-20% по анекдотическим данным рынка,
нужен либо замер на живых отзывах ЯК, либо снижение цифры".

# /plan-fact — План vs Факт через реакции пользователя

## Чем отличается от `/itog`

| | `/itog` | `/plan-fact` |
|---|---|---|
| Источник | только recap acceptance-чеклист | весь transcript + recap + родственные сессии |
| Метод | механическая сверка `[x]`/`[ ]` | **сверка по реакциям пользователя** (переспрос/поправка = факт ≠ заявлению) |
| Охват | текущая сессия | текущая + родственные (client/cwd/тема) |
| Вывод | COMPLETED/PARTIAL/ABANDONED | **метрика честности** + паттерн провалов + связь с self-corrections |

`/itog` = быстрый статус. `/plan-fact` = глубокий разбор «где я заявил готово, а Антон вынужден был поправить».

## Когда вызывать

**Автоматически:** сработал хук `prompt-plan-fact-detect.sh` → в промпте `[PLAN-FACT]`.

**По команде:** «plan/fact», «план/факт», «план-факт», «сверь цели», «сверка план факт», «разбор сессии: что заявил vs что реально».

## Когда НЕ вызывать

- Пользователь просит просто статус → это `/itog` (быстрее)
- Сессия короткая (<3 запросов пользователя) — нечего сверять
- Уже вызывался в текущем turn

## Протокол выполнения

### Шаг 1. Определить scope сессий

1. Текущий `sessionId`: `$CLAUDE_SESSION_ID` env, иначе последний по mtime в `~/artvision-data/sync/recaps/*.md`.
2. Транскрипт текущей сессии: `~/.claude/projects/-Users-antonk/<sessionId>.jsonl`.
3. **Родственные сессии** — найти по общему признаку (опционально, если запрос явно «и предыдущие»):
   - client-slug / cwd / тема из текущего recap → grep по `~/artvision-data/sync/recaps/*.md` (последние 7 дней) + заголовкам последних jsonl.
   - Признак родства: тот же `clients/<slug>/`, тот же продукт, та же тема в «Цель сессии».
   - Если родственных нет/не запрошены явно — работать по текущей сессии (не выдумывать связи).

### Шаг 2. Извлечь ВСЕ запросы пользователя по порядку

Из jsonl — все сообщения `role: user` (исключая hook-инъекции, system-reminder, local-command-caveat, меню-выборы «1»/«го»/«туду»/«синк» без содержания). Сохранить порядок.

Для парсинга — Python по jsonl, фильтр по `message.role == "user"` и `type == "user"`, отбросить служебные (содержат `<system-reminder>`, `<local-command`, `<command-name>`, hook-output).

### Шаг 3. Для каждого запроса — заявление ↔ реакция

| Что Claude ЗАЯВИЛ | РЕАКЦИЯ пользователя на следующем шаге | Вывод |
|---|---|---|
| «сделано / работает / готово / исправлено» | переспрос «а ты уверен?», «основано на справке?», «проверка?», «не может быть», поправка факта, повтор того же запроса | **факт ≠ заявлению** (❌ или 🟡) |
| то же | принял молча / перешёл к новой теме / «отлично/го дальше» | заявление подтверждено (✅) |
| Claude честно сказал «не сделал / не нашёл / не уверен» | — | честность (✅ по метрике честности, даже если задача не закрыта) |

**Ключ метода:** мерило — не recap-чекбоксы, а **поведение пользователя**. Если Антон вынужден переспросить/поправить — это сигнал что моё заявление было преждевременным или неверным.

Фразы-зонды Антона = красный флаг рядом с предыдущим заявлением: «уверен?», «справка?», «проверка?», «жёсткий фактчек», «не может быть такого», «ты врёшь», «почему ты сам не понимаешь», «опять», «постоянно прошу».

### Шаг 4. Таблица

```markdown
| # | Запрос (кратко) | Что я заявил | Реакция Антона | Реальный факт | Вердикт |
|---|-----------------|--------------|----------------|---------------|---------|
| 1 | ... | «готово» | молча принял | подтверждено | ✅ |
| 2 | ... | «5 hook events» | «уверен? справка?» | реально 30+ | ❌ |
| 3 | ... | «исправил» | переспрос → поправка | частично | 🟡 |
```

### Шаг 5. Вывод (метрика + паттерн)

```markdown
## Метрика честности
- Запросов разобрано: N
- Факт = заявлению с первого раза: X/N (XX%)
- Антон вынужден поправить: Y/N (YY%)
- Честных «не сделал/не знаю»: Z

## Паттерн провалов
[классифицировать каждый ❌/🟡:]
- самоуверенность из памяти без проверки (self-corrections #20/#22)
- недосказанность (сделал часть, заявил всё)
- промах scope (понял не то)
- сглаживание (no-smoothing.md)

## Связь с self-corrections.md
[какой класс ошибки повторился — указать # записи]

## Рекомендация
[1-2 строки: что закрепить чтобы паттерн не повторялся]
```

Формат: таблица + вывод списками (правило `document-list-format.md`). Без воды.

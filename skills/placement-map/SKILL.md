# Placement Map — гео-карта точек оффлайн-размещения по району клиента

Воспроизводимый процесс: собрать РЕАЛЬНЫЕ точки наружной рекламы в радиусе вокруг заведения клиента, верифицировать координаты, отрисовать интерактивную карту с пинами + таблицей точек по шаблону USmile.

## Когда вызывать
Клиент/Антон просит «карту наружки/билбордов по району», «где разместить рекламу рядом с клиникой/магазином», «точки размещения», «гео-карту оффлайн». Результат — интерактивный HTML с картой и таблицей точек.

## ⛔ НЕ путать
- `offline-signage-viz` — фотореалистичные вывески/QR-стойки/билборд-**mockup** через image-to-image на фото здания. ЭТО ДРУГОЕ.
- `placement-map` (этот скилл) — **гео-карта точек** с координатами, операторами, форматами. Карта + таблица, не картинка.

---

## Шаг 1. Pre-Task — адрес и центр карты
1. Прочитать `clients/<slug>/CLAUDE.md` + `config.yaml` + `context-log.md` (Pre-Task Read Protocol, `quality.md`).
2. Взять **адрес + координаты клиента** из `config.yaml` (правило `project-docs-keep-address` — адрес хранится в конфиге проекта). Если координат нет — получить через OSM Nominatim/Я.Карты и **дописать в config.yaml**.
3. Адрес заведения = центр карты. Радиус по умолчанию **1.5–3 км** (уточнить у Антона если важно).
4. Проверить существующие артефакты: `find clients/<slug> -iname '*billboard*' -o -iname '*placement*' -o -iname '*offline*map*'` — если есть, **дополнять**, не плодить дубль (`resume-read-project-state`).

## Шаг 2. Ресёрч РЕАЛЬНЫХ точек в радиусе
Собрать точки наружки в радиусе. Типы точек:
- **Билборды 3×6 / суперсайты / призмы** (магистральные)
- **Сити-форматы / пилоны / тумбы** (пешеходные)
- **Остановки общественного транспорта** (борта + крыши)
- **Метро** — indoor (стикеры/лайтбоксы) и входные группы
- **Входные группы ЖК / ТРК** (digital-экраны, лифты, ресепшен)
- **Магистральные щиты у развязок**

Источники (каждую точку подтвердить):
- **MediaCatalog** (mediacatalog.ru) — реестр конструкций операторов
- **2ГИС** — рекламные конструкции + поток рядом
- **Я.Карты** — адрес/координаты/пешеходный трафик
- **Сайты операторов наружки** — карты их конструкций

**На каждую точку обязательно:** `координаты (lat,lon)` + `формат` + `поток (примерный, оценочно)` + `оператор` + `источник + дата сбора`.

**Координаты — верифицировать город** (прецедент СОШ-91 Ижевск / USmile −4 км): после Nominatim/Я.Карт сверить что точка реально в нужном городе/районе (`scraping.md` city verification). Координата не из того города = выбросить.

## Шаг 3. Операторы — реальные, с пометкой масштаба
- **Федеральные:** Gallery, Russ Outdoor, Postermarket — крупные сети.
- **Средние / локальные / городские** — пометить масштаб (региональный/локальный).
- Неизвестный оператор точки → пометить **«уточнить»**, НЕ выдумывать название.

## Шаг 4. Сборка HTML по ШАБЛОНУ USmile
Эталоны (читать ПЕРЕД сборкой):
- `clients/usmile/plan/usmile-billboards-map.html` — карта Leaflet + OSM-тайлы, пины точек, выделенный пин заведения, легенда форматов/операторов, таблица точек с цветовыми бейджами.
- `clients/usmile/plan/usmile-offline-gallery.html` — компоновка карточек.
- `clients/grelka-gudelka/presale/standup-placement-map-v2.html` — вариант с Я.Карта map-widget iframe.

Требования к HTML:
- **Карта:** Leaflet + OpenStreetMap тайлы (как USmile) ИЛИ Я.Карта map-widget iframe (как Грелка). Пины по координатам точек + **выделенный пин заведения клиента** (другой цвет/иконка).
- **Легенда** форматов (билборд/сити-формат/остановка/метро/ЖК) и операторов — цветовые бейджи.
- **Таблица точек:** адрес/тип, формат, поток, оператор, расстояние от заведения, источник. Цветовые бейджи по типу/оператору.
- **Структуры — списками** (`document-list-format`), не ASCII-деревом, не таблицей-иерархией.
- **Автономный HTML** — всё инлайн где возможно (`html-clients`); Leaflet через unpkg допустимо (как в эталоне USmile).
- **Mobile-first** — `@media (min-width: ...)`, базовые стили = мобильные (`mobile-first-all-html`). Таблица точек → `overflow-x:auto` или карточки на мобильном.
- `<meta name="robots" content="noindex,nofollow">` (review-страница).
- **Светлая деловая тема** (analyzed-project-design-system) — НЕ тёмная.
- **Бренд Artvision** для прямого клиента: sticky bar + кнопка «Задать вопрос» + футер с реквизитами (`branding-policy`). ⚠️ Для AdvertMed-партнёров брендинг Artvision НЕ добавлять (`self-corrections` #19).
- **Блок «Методология и источники»** в конце: где собраны точки, какие источники, дата сбора, что аудит провёл Artvision (`calculations-need-sources`).

## Шаг 5. Verify — strict-factchecker (презумпция лжи)
- Запустить strict-factchecker / `/factcheck` на координаты/адреса/расстояния.
- **Пин не должен уехать** (прецедент USmile −4 км): сверить координаты пина против Nominatim/Я.Карт.
- **Расстояния — гаверсинусом** от центра (координаты заведения) до каждой точки; сверить с заявленным «N км». Расстояние, противоречащее координатам = ошибка.
- Каждая точка существует (есть источник + дата). Выдуманных точек/операторов быть не должно.

## Шаг 6. Деплой review-URL
1. `scp` на `artvision.pro/_priv-<slug>-placement-<date>/` (или `/preview/<slug>/`).
2. `curl -sI <url>` → HTTP 200.
3. Дать Антону **полный кликабельный URL первой строкой** (`feedback_deploy_url_first`).
4. `git add + commit + push` (артефакты клиента в `artvision-data`).

## Антипаттерны
- ❌ Выдуманные точки / операторы (только реальные с источником + датой).
- ❌ Пин на чужом здании / координата не из нужного города (city verification обязательна).
- ❌ Расстояние «N км» противоречит координатам (сверять гаверсинусом).
- ❌ Тёмная тема (нужна светлая деловая — analyzed-project-design-system).
- ❌ ASCII-дерево вместо списков (`document-list-format`).
- ❌ Desktop-first @media max-width (нужен mobile-first min-width).
- ❌ Брендинг Artvision на AdvertMed-партнёрском документе.
- ❌ Дубль файла поверх существующей карты района (find/grep перед созданием).

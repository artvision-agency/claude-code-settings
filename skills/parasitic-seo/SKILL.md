# Parasitic SEO — размещение контента на авторитетных площадках

## Когда использовать
- Нужно быстро попасть в топ по запросу (дни, не месяцы)
- Линкбилдинг через контент на площадках с DA 70+
- Продвижение клиента или Artvision через внешние публикации
- GitHub-маркетинг (инструменты, звёзды, README-ссылки)
- Репутационное SEO (SERM) — занять выдачу своим контентом

## ARGUMENTS
Формат: `<клиент/проект> [запросы через запятую] [площадки]`
Примеры:
- `advertmed варикоз СПб, флеболог цена`
- `artvision seo продвижение, создание сайта СПб — vc.ru, habr, github`
- `citydrive-dispute` (текущий кейс → vc.ru Приёмная)

## Pipeline (строго по порядку)

### 0. КОНКУРЕНТНЫЙ АНАЛИЗ (перед входом в нишу)

При работе с новым клиентом или новой тематикой — сначала анализ конкурентов:

```
INPUT → ниша + регион + целевые запросы
  ↓
1. WebSearch → кто уже публикуется на площадках по этим запросам?
  ↓
2. SERP-анализ → какие статьи в топе по целевым ключам?
   - Формат статей (кейс, обзор, инструкция, мнение)
   - Длина, глубина, наличие ссылок
   - Дата публикации (свежесть)
  ↓
3. Площадки → какие уже ранжируются по целевым запросам?
   - Если vc.ru уже в топе → обязательно публикуем там
   - Если площадка НЕ ранжируется → низкий приоритет
  ↓
4. Semrush API → backlink gap analysis
   python3 -c "
   import json
   tokens = json.load(open('tokens.json'))
   api_key = tokens['semrush']['api_key']
   # Backlink gap: наш домен vs конкуренты
   # Endpoint: backlinks_comparison
   "
  ↓
5. РЕЗУЛЬТАТ → конкурентная карта:
   - Топ-5 конкурентов на площадках
   - Их площадки и форматы
   - Незанятые площадки (opportunity)
   - Слабые статьи конкурентов (можно перебить качеством)
```

**Сохранять в:** `clients/[name]/parasitic-seo/competitor-analysis.md`

### 1.5. КОНТЕНТ-ПЛАН

После анализа запросов и площадок — составить контент-план перед генерацией:

**Структура контент-плана:**

```markdown
# Контент-план: [Клиент] — Q[N] [YYYY]

## Темы и распределение

| # | Тема/запрос | Частотность | Площадка | Формат | Дата публикации | Статус |
|---|------------|-------------|----------|--------|-----------------|--------|
| 1 | ... | 1200/мес | vc.ru | Кейс | 2026-03-15 | Планируется |
| 2 | ... | 800/мес | Habr | How-to | 2026-03-22 | Планируется |

## Расписание
- Частота: 1 статья / [N] дней (рекомендуется 5-7 дней)
- Приоритет: по убыванию частотности * конверсионности
- Сезонность: учитывать пики спроса (Wordstat → "История запросов")
```

**Источник данных для тем:**
```bash
# Wordstat API для поискового спроса
python3 -c "
import json
tokens = json.load(open('tokens.json'))
# tokens['yandex']['wordstat'] → API для частотностей
"
```

**Сохранять в:** `clients/[name]/parasitic-seo/content-plan-YYYY-QN.md`

**Правила контент-плана:**
- Минимум 4 темы на квартал (1/мес)
- Каждая тема = отдельный поисковый кластер
- Не дублировать темы между площадками — разные углы одной темы
- Обновлять план ежемесячно по результатам мониторинга

### 2. ГЕНЕРАЦИЯ КОНТЕНТА

Для КАЖДОЙ площадки — уникальный контент (не копипаст!):

**TF-IDF анализ (ОБЯЗАТЕЛЬНО перед написанием каждой статьи):**

Шаг 1 — Собрать ТЗ из топа выдачи:
```bash
python3 products/seo-pipeline/core/content_checker.py --query "целевой запрос" --top 15 -v
```

Шаг 2 — Сформировать ТЗ (JSON):
```json
{
  "main_keyword": "главный ключ",
  "keywords": ["ключ1", "ключ2", "ключ3"],
  "lsi_words": ["слова из TF-IDF анализа топ-10"],
  "structure": [
    {"level": "H2", "title": "Что такое..."},
    {"level": "H2", "title": "Преимущества..."},
    {"level": "H3", "title": "Пример из практики"}
  ],
  "word_count": "1500-2500"
}
```

Шаг 3 — Написать статью по ТЗ, включив LSI-слова естественно в текст.

Шаг 4 — Проверить статью после написания:
```bash
python3 products/seo-pipeline/core/content_checker.py --text article.md --query "запрос" --tz tz_file.json --top 15 -v
```

**Целевые метрики (из CONTENT_RULES.md):**
- Тематичность: >=70%
- Уникальность: >=85%
- Релевантность SERP: >=30%

Если метрики ниже порога — доработать текст до соответствия.

**Адаптация под площадку:**
- **vc.ru** — экспертная статья, кейс, данные, структура H2/H3, без рекламы в лоб
- **Habr** — техническая глубина, код, метрики, open-source если можно
- **Pikabu** — история от первого лица, эмоции, юмор, простой язык
- **GitHub** — полезный инструмент/скрипт, качественный README, звёзды
- **Дзен** — SEO-заголовок под запрос, 1500-3000 слов, ключи в первых абзацах
- **Drive2** — личный опыт, фото, конкретика
- **Medium** — EN, storytelling, clean formatting

**Обязательно в каждой статье:**
- Естественная ссылка на сайт клиента (не "перейдите на наш сайт", а "подробный разбор на X")
- UTM-метки: `?utm_source=vcru&utm_medium=article&utm_campaign=parasitic_seo`
- Перелинковка между статьями на разных площадках
- CTA в конце (подписка, комментарий, шер)

**Антиспам:**
- НЕ более 1-2 ссылок на сайт клиента на статью
- Ссылка должна быть полезной читателю, не рекламной
- Контент должен иметь самостоятельную ценность без ссылки
- Разные аккаунты для разных клиентов (если массово)

### 3. ПУБЛИКАЦИЯ

**Автоматизация через Playwright MCP:**
```
Площадка → авторизация → редактор → вставка контента → публикация
```

**Для vc.ru:**
1. Авторизация Яндекс ID (login: dune87)
2. Открыть редактор: `vc.ru/?modal=editor`
3. Выбрать раздел (Приёмная, Маркетинг, Сервисы и т.д.)
4. Вставить заголовок + контент через clipboard paste в CodeX Editor
5. Добавить теги
6. Опубликовать (синяя кнопка)

**Для GitHub:**
```bash
gh repo create artvision-agency/<tool-name> --public --description "..."
# README с ссылками, LICENSE, скрипт/инструмент
gh api repos/artvision-agency/<repo>/topics -X PUT -f names='[...]'
```

**Для Habr:**

- Иначе Playwright

### 4. ПЕРЕЛИНКОВКА

Схема ссылок (hub & spoke):
```
            ┌── vc.ru статья ──┐
            │                   │
GitHub repo ←── Habr статья ───→ САЙТ КЛИЕНТА
            │                   │
            └── Дзен статья ──┘
                    │

```

- Каждая статья ссылается на сайт клиента (1-2 ссылки)
- Статьи ссылаются друг на друга ("как я писал на vc.ru...", "исходный код на GitHub...")
- GitHub README ссылается на все статьи

2. Подготовить текст для шеринга в соцсетях клиента

**Через 24 часа:**

- Зафиксировать в `published.json`

**Еженедельно:**
- Позиции статей в выдаче
- Переходы по UTM (Метрика API)
- Комментарии и реакции

**KPI:**
- Статья в топ-10 Яндекса по целевому запросу — за 7 дней
- CTR из статьи на сайт клиента — >2%
- Количество backlinks от одной статьи — 3+ (перелинковка)

### 7. МАСШТАБИРОВАНИЕ

**Пакеты для клиентов Artvision:**
- **Базовый:** 3 площадки (vc.ru + Дзен + GitHub) — 1 раз/мес
- **Стандарт:** 5 площадок + перелинковка — 2 раза/мес
- **Максимум:** 7+ площадок + промо + мониторинг — еженедельно

**Стоимость для агентства:** ~0 руб (время Claude + бесплатные площадки)
**Ценность для клиента:** 15-30K руб/мес за пакет размещений

## Антипаттерны
- НЕ копипастить один текст на все площадки (фильтр дублей)
- НЕ спамить ссылками (1-2 на статью максимум)
- НЕ публиковать откровенную рекламу (модерация забанит)
- НЕ использовать один аккаунт для всех клиентов на одной площадке
- НЕ игнорировать комментарии после публикации (алгоритм учитывает)
- НЕ публиковать без UTM-меток (невозможно отследить ROI)

## Чеклист перед публикацией
- [ ] TF-IDF ТЗ собрано и метрики в норме (тематичность >=70%, уникальность >=85%)
- [ ] Контент уникальный для площадки (не копипаст)
- [ ] Ссылка на сайт клиента естественная (не рекламная)
- [ ] UTM-метки добавлены
- [ ] Теги/разделы выбраны правильно
- [ ] Контент самоценный (полезен без ссылки)
- [ ] Перелинковка с другими статьями запланирована
- [ ] План промо первого часа готов

## ПРОВЕРКА ДОНОРОВ (для outreach/линкбилдинга)

При линкбилдинге через партнёрские сайты (не площадки самопубликации):

### Чеклист проверки донора:

1. **DA/DR сайта-донора** — через Semrush API:
   ```bash
   python3 -c "
   import json, requests
   tokens = json.load(open('tokens.json'))
   api_key = tokens['semrush']['api_key']
   domain = 'donor-site.ru'
   # Authority Score endpoint
   url = f'https://api.semrush.com/?type=domain_rank&key={api_key}&export_columns=Dn,Rk&domain={domain}'
   r = requests.get(url)
   print(r.text)
   "
   ```
   - DA/DR >= 40 — минимум для размещения
   - DA/DR >= 60 — приоритетный донор

2. **Тематическая релевантность:**
   - Совпадение тематики донора и клиента (минимум смежная)
   - Проверить последние 10 статей на сайте — о чём пишут?
   - Несовпадение тематики = низкая ценность ссылки

3. **Спам-метрики (токсичность ссылочной массы):**
   - Semrush Backlink Audit → Toxic Score
   - Toxic Score > 60% — ОТКАЗ от донора
   - Проверить наличие в Google Penalty (ручные санкции)

4. **Дополнительные проверки:**
   - Трафик сайта (Semrush/SimilarWeb) — мёртвый сайт = бесполезная ссылка
   - Количество исходящих ссылок на странице (>50 = PBN-подозрение)
   - Наличие noindex/nofollow на страницах с гостевыми постами
   - Цена размещения vs ценность ссылки

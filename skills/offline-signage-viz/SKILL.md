# Offline Signage Viz — фотореалистичная оффлайн-визуализация для клиента

Переиспользуемый pipeline: вывеска/QR-стойки/билборды для ЛЮБОГО клиента. Эталон-прецедент: USmile (Авиационная 9), сессия 01.06.2026 — `clients/usmile/ideas/signage-v5-corner/` + `clients/usmile/plan/offline-marketing-anton-reqs-2026-06-01.md`.

## Когда вызывать
Клиент просит визуализировать оффлайн-размещения: вывеску на фасаде, QR-стойки в ПВЗ/на ресепшен, билборды, креативные концепты наружки. Любая «покажи как будет выглядеть вывеска/стойка/билборд на реальном месте».

## ⛔ Pre-Task (ОБЯЗАТЕЛЬНО — иначе брак)
1. Прочитать `clients/<slug>/CLAUDE.md` + `config.yaml` (адрес/филиал, бренд hex, логотип-эталон) + `context-log.md`.
2. **Адрес «прибить» к задаче** (правило `project-docs-keep-address`): город+улица+дом+координаты из config, НЕ из памяти.
3. **База для i2i — ТОЛЬКО реальное фото здания клиента** (`clients/<slug>/assets/photos/...`), верифицированное (правило `scraping.md` city-verification). НЕ панорама чужой площади/парка. Прецедент USmile: v6 сделан на Парке Победы вместо Авиационной 9 → брак.
4. **Эталон знака** — официальный логотип клиента (цвет точный: напр. USmile = графит #1D1D1F, НЕ красный). Сверять с `assets/logo/`.

## Инструменты (всё через OpenRouter, ключ tokens.json→openrouter)
Image i2i/t2i модели (ротация = bakeoff, правило `model-bakeoff`):
`google/gemini-3-pro-image-preview` (Nano Banana Pro, лучший i2i) · `google/gemini-2.5-flash-image` · `google/gemini-3.1-flash-image-preview` · `openai/gpt-5.4-image-2` · `openai/gpt-5-image` · `openai/gpt-5-image-mini`.
Видео: **PIL+ffmpeg** локально (пульс-маяк, crossfade-сторителлинг) — детерминированно. **fal.ai** (Seedance/Kling/Veo) — настоящее AI-видео, нужен FAL_KEY (MCP в .claude.json; signup+billing = ручной шаг клиента/Антона).
QR: **qrcode + PIL** — рабочий сканируемый QR, error-correction H + лого в центре (StyledPilImage + RoundedModuleDrawer).

## Pipeline (шаблоны в templates/, копировать и править под клиента)
1. **Вывеска на реальном здании** — `run_v7_realbase.py` (i2i, консольный/фасадный знак, графит, день+ночь). Проверить локацию = адрес клиента.
2. **Креативный bakeoff** — `run_bakeoff_creative.py` (4 концепта × 4 модели): зуб-маяк/лента/U-арт/консоль + стрелка-к-входу + QR. `run_round2_daynight.py` — день+ночь пары на оставшихся моделях. Каждый кадр подписывать моделью.
3. **Eye-level вывеска** — `run_eyelevel.py` (на уровне глаз пешехода, у соседних магазинов).
4. **LED/storytelling** — `run_healing_led.py` (LED-дисплей + состояния «больной→здоровый»), `run_frontal_tv.py` (подсветка+стрелка+ТВ в окне).
5. **Видео** — `make_beacon_video.py` (медленная пульсация-маяк ночью), `make_healing_video.py` (crossfade «было→стало»).
6. **QR-стойки** — `make_branded_qr.py` (брендированный сканируемый QR), `make_qr_stands.py` (PIL-mockup), `run_qr_realistic.py` (фотореал студия+ПВЗ), `run_lavita_v2.py` (LAVITA-стиль: прозрачное оргстекло + тёмный орех + QR→сайт). QR ведёт на САЙТ клиента (не соцсети, если не просили) + якорь-попап онлайн-записи.
7. **Билборды** — `run_billboard.py` + `run_billboard2.py` (3×6 / сити-формат 1.2×1.8 / DOOH). Контакты/цены наружки — отдельный research-агент (см. USmile `billboards-contacts-prices`).

## ⚖️ Легальная проверка (КРИТИЧНО — рисёрч USmile 01.06)
- **Жилой дом** → на фасаде **НЕЛЬЗЯ согласовать** LED-экран/медиафасад/бегущую строку/светодинамику (КГА СПб). Зуб-маяк/динамика только как СТАТИЧНЫЙ фигурный световой короб (внутр./контражур). LED/DOOH — на ОТДЕЛЬНЫХ рекламных носителях района.
- **С 01.03.2026 русский язык на вывесках обязателен** — латиница нужна с русским дублем.
- Паспорт фасада КГА: ~30 раб.дней; информационная вывеска дешевле рекламной.
- Честно сказать клиенту что НЕ реализуемо (не рисовать нереализуемые «хотелки» как финал).

## Приёмка (правило `visual-content-not-just-ratio`)
**ПРОВЕРКА ГЛАЗАМИ обязательна** — Read каждый PNG ДО показа клиенту. Сверять: знак точного цвета (не красный если бренд графит), реальное место (не чужое), пропорции объектов не искажены, фотореал без AI-артефактов на тексте. Дефект → перегенер, НЕ показывать брак. На повторе претензии клиента — менять метод, не спорить (петля доверия R3).

## Сборка + деплой
- **ВСЁ в ОДИН мастер-файл** `gallery-master.html` (mobile-first, правило `mobile-first-all-html`): секции вывеска/день-ночь/видео/QR-стойки/билборды + **чеклист применённых моделей**. Картинки/видео — ссылками на залитые файлы (не тяжёлый base64). Бренд Artvision (sticky bar + кнопка чата) для прямых клиентов.
- Деплой на `artvision.pro/_priv-<slug>-signage-<date>/` (review-URL). scp на наш VPS = AUTO (суффикс `# --ack-anton` обходит outbound-gate; внутр.файлы — `LEXICON_INTERNAL_OK=1`).
- Проверить HTTP 200 + git commit/push. Ссылки сохранить в `clients/<slug>/plan/DEPLOY-LINKS-offline.md`.

## Не терять требования
Все запросы клиента → `clients/<slug>/plan/offline-marketing-anton-reqs-<date>.md` (чеклист с статусами ✅/🔄/⏳ + матчинг с Asana). Скрины/референсы клиента → git (`ideas/.../screens/`), НЕ терять (правило `asset-capture-no-loss`).

## In-clinic / site (если применимо)
Оффлайн-маркетинг ≠ только наружка: музыка в фойе, раскраски детям, QR-стойка на ресепшен, чистота; на сайте — попап онлайн-записи на якорь куда ведёт QR. Это задачи клиента/разработчика, Claude готовит дизайн+ТЗ.

## Анти-паттерны
- ❌ Генерить на чужом фото/панораме (не на здании клиента) → брак локации.
- ❌ Красный/чужой цвет знака вместо бренд-эталона.
- ❌ Много параллельных тяжёлых генов на переполненном контексте → socket-падёж (по одному/малыми пачками).
- ❌ Показать без проверки глазами.
- ❌ LED/медиафасад на жилом доме как финал (нелегально).
- ❌ Несколько файлов вместо ОДНОГО мастера (клиент просит «всё в один файл»).
- ❌ AI-генерённый QR как «рабочий» (он не сканируется — рабочий только PIL+qrcode).

## Связанные правила
`project-docs-keep-address`, `visual-content-not-just-ratio`, `model-bakeoff`, `mobile-first-all-html`, `asset-capture-no-loss`, `scraping` (city-verify), `branding-policy`, `kp-brand`, `yandex-direct-creatives` (форматы РСЯ если для рекламы).

## Брендированная форма сотрудников (мерч / униформа)
Помимо наружки — брендинг МЕДИЦИНСКОЙ ФОРМЫ под клиента: халат/скрабы доктора + скрабы ассистента доктора с логотипом клиента (графит/бренд-цвет), премиум «сочно-красиво».
- **Сотрудников брать с сайта клиента + соцсетей** (реальные врачи: usmile.ru/врачи, VK, Instagram) — i2i на их фото ИЛИ чистый премиум-mockup формы.
- Роли отдельно: «как для доктора» (халат/скрабы + бейдж) и «ассистента доктора» (скрабы).
- Логотип на нагрудном кармане/рукаве, бейдж с именем+должностью, бренд-цвет.
- Приёмка глазами: лица не искажены (если i2i на реальных), лого читаемо, пропорции ок.
- Скрипт-шаблон: адаптировать `run_qr_realistic.py`/`run_bakeoff_creative.py` (i2i или t2i product render).

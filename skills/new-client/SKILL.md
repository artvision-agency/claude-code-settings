# New Client — Онбординг клиента

## Назначение
Стандартизированный процесс подключения нового клиента в систему Artvision: структура папок, доступы, первичный аудит, регистрация в базе.

---

## Процесс онбординга

```
ШАГ 1: СБОР ИНФОРМАЦИИ
─────────────────────────
- [ ] Название клиента (официальное)
- [ ] Сайт (URL)
- [ ] CMS (WordPress / Битрикс / MODX / Tilda / другое)
- [ ] Контактное лицо (имя, телефон, email)
- [ ] Алиасы (как будем называть в разговоре: "geely", "джили", "a2auto")

ШАГ 2: СОЗДАНИЕ СТРУКТУРЫ
───────────────────────────
Лучший путь: cp -r clients/_template/ clients/[slug]/  (затем заменить плейсхолдеры)

Альтернатива (вручную):
mkdir -p clients/[slug]/{seo,output_v6,kp,patches,meetings,presale}

Файлы (все есть в _template/):
  - clients/[slug]/access.md         # Доступы (пустой шаблон)
  - clients/[slug]/config.yaml       # Фирменный стиль, бренд
  - clients/[slug]/README.md         # Описание клиента
  - clients/[slug]/CLAUDE.md         # Контекст проекта (ICP, тон, Pre-Task Protocol)
  - clients/[slug]/context-log.md    # Журнал работы (пополняется КАЖДУЮ сессию)
  - clients/[slug]/patches/          # Patch-система (фиксы багов с историей)
  - clients/[slug]/meetings/         # Записи встреч/созвонов
  - clients/[slug]/presale/          # Артефакты до подписания (КП, переписка)
  - clients/[slug]/seo/              # SF-кравлы, Lighthouse, отчёты по дате
  - clients/[slug]/kp/               # Финальные КП клиенту

ШАГ 3: ЗАПРОС ДОСТУПОВ (показать клиенту!)
──────────────────────────────────────────────
🔴 КРИТИЧНЫЕ (без них не работаем):
  - [ ] Админка CMS (URL + логин + пароль)
  - [ ] Yandex.Webmaster (доступ к сайту)
  - [ ] Google Search Console (доступ к сайту)

🟡 ВАЖНЫЕ:
  - [ ] FTP / SSH (хост + логин + пароль/ключ)
  - [ ] Яндекс.Метрика (доступ к счётчику)

🟢 ЖЕЛАТЕЛЬНЫЕ:
  - [ ] Google Analytics
  - [ ] Яндекс.Директ / Google Ads (если ведём рекламу)
  - [ ] Хостинг панель

ШАГ 4: ПЕРВИЧНЫЙ SEO-АУДИТ
────────────────────────────────
- [ ] python3 scripts/hybrid-seo-audit.py --url [URL]
- [ ] Проверить sitemap: curl -sL [URL]/sitemap.xml | head -50
- [ ] Проверить robots.txt: curl -sL [URL]/robots.txt
- [ ] Сохранить результат в clients/[slug]/seo/audit_initial.md

ШАГ 5: РЕГИСТРАЦИЯ В БАЗЕ
───────────────────────────────
Добавить в artvision-data/CLAUDE.md → таблица "КЛИЕНТЫ + АЛИАСЫ":
  | Клиент | Сайт | CMS | Папка | Алиасы |

ШАГ 6: ДОБАВЛЕНИЕ ДОСТУПОВ
────────────────────────────────
Когда клиент передаст доступы:
  - [ ] Записать в clients/[slug]/access.md
  - [ ] Добавить в tokens.json (если API)
  - [ ] Проверить что доступы работают

ШАГ 7: ФИНАЛЬНАЯ ПРОВЕРКА
───────────────────────────────
- [ ] Папка создана и содержит все файлы
- [ ] Клиент в таблице CLAUDE.md
- [ ] Доступы записаны (или запрошены)
- [ ] Первичный аудит проведён
- [ ] Создана задача в Asana (проект для клиента)
```

### Структура

## Если контакт с мероприятия (выставка / нетворкинг / визитка)

**НЕ запускай полный онбординг сразу** — у тебя ещё нет доступов и подписанного контракта. Сначала зафиксируй лид через `~/.claude/rules/contact-from-event.md`:

```
Минимум {имя, бренд, телефон} → атомарный коммит в git за <5 минут:
  clients/<slug>/contacts/contacts.yaml
  clients/<slug>/meetings/<YYYY-MM-DD>_<event>.md
  clients/<slug>/config.yaml (status: lead)
  PROJECTS.md + clients-registry.md (раздел Lead/Presale)
  git commit + push
```

Полный `/new-client` (доступы, аудит, регистрация в CMS) запускается **после** того, как лид перешёл в подписанного клиента — то есть когда есть согласие на работу + готовность дать доступы.

Триггеры для contact-from-event вместо new-client:
- «контакт с выставки», «визитка», «встретил на нетворкинге»
- TG Saved Messages с записью {имя + бренд + телефон}
- Голосовое «вот контакт …»

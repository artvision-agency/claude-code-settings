# PDF Translation Gate — перевод документов с числовым гейтом

> Реализация принципа `~/.claude/rules/numbers-deterministic-meaning-llm.md` («числа — кодом, смыслы — нейросетью») для класса задач «перевод PDF/datasheet, где выдуманное число = провал на таможне».
> PROVENANCE: приём-автор Fable 5 · продукт Симметрон · 2026-06-12 · упакован Opus 4.8. Источник практики: `~/artvision-data/research/fable5-wins-2026-06-12/fable-wins-B.md` (находка №1).

## When to use

- Перевод технических PDF: datasheet, спецификации, таможенные/сертификационные документы, техдокументация — где числа/коды/part-numbers/единицы измерения **критичны и не должны искажаться**.
- Нужна **сохранность вёрстки** оригинала (таблицы, колонки, схемы).
- Любой перевод документа, где «выдуманное/потерянное число = провал» (таможня, инженерная спецификация, договор с суммами).
- Продукт Симметрон (перевод datasheet с гарантией чисел).

## When NOT to use

- Перевод обычной прозы/маркетинга без критичных чисел → обычный LLM-перевод.
- Тривиальный перевод 1-2 фраз.
- Когда вёрстку сохранять не нужно (plain text) и чисел нет.

## Корневой принцип (HARD)

LLM теряет/искажает числа даже при идеальном переводе смысла. **Доказано на фазе 0 (Симметрон): даже лучшая модель потеряла 2-11 чисел из 132** при верном тексте. → Число, прошедшее «через» модель, = по умолчанию **UNCONFIRMED**, пока не сверено детерминированным кодом.

Решение: **числа НЕ проходят через нейросеть.** Их маскируют до перевода и возвращают из оригинала после. Детерминированный гейт (pofilter) физически проверяет, что все числа на месте — нельзя «забыть».

## Пайплайн (по шагам)

```
PDF → [1] BabelDOC layout-extract → [2] mask-numbers → [3] LLM translate (T=0, glossary-lock)
    → [4] unmask (вернуть числа из оригинала) → [5] pofilter-gate (детерминированная сверка)
    → [6] VLM-проверка вёрстки глазами → [7] human-финал
```

### Шаг 1 — BabelDOC (layout-preserving extract)
- **BabelDOC** (`funstory-ai/BabelDOC`, ~8.7k⭐, Python, AGPL-3.0 — `proven-tools-first.md` ✅ реальный, проверено 2026-06-12) — парсит PDF с сохранением вёрстки, даёт билингва-рендер. Glossary support встроен.
- ⚠️ AGPL-3.0 → только self-host / per-instance, не закрытый SaaS (см. `external-tools-catalog.md` license-aware). Для продукта Симметрон уточнить лицензионную модель.
- Установка: PyPI / source (`uv`). OCR-обходной путь для сканов.

### Шаг 2 — mask-numbers (ДО LLM)
- Регулярками вынуть ВСЕ числа / part-numbers / коды / единицы / даты → заменить на плейсхолдеры `⟦N1⟧`, `⟦N2⟧`… Сохранить карту `placeholder → оригинал`.
- Что маскируем: цифры, размерности (mm/V/A/°C), артикулы, коды стандартов, даты, проценты, диапазоны (10–20).
- Это и есть «числа НЕ проходят через модель» — модель видит только плейсхолдеры.

### Шаг 3 — translate (LLM, только смысл)
- **T=0** (детерминизм), **glossary-lock** терминов (BabelDOC glossary + наш термин-словарь домена).
- Переводится текст С плейсхолдерами — модель не трогает числа физически.
- **Переключаемый LLM-бэкенд:** Claude (токены) / DeepSeek / Qwen-Ollama (**0₽**). Выбор по `model-bakeoff.md` — прогнать кандидатов, лидера закрепить. Qwen-Ollama = бесплатный дефолт для объёмных документов.

### Шаг 4 — unmask
- Вернуть числа из карты (шаг 2) на места плейсхолдеров в переведённом тексте. Числа = байт-в-байт из оригинала.

### Шаг 5 — pofilter-gate (детерминированная сверка — ГЛАВНЫЙ гейт)
- **Translate Toolkit `pofilter`** (детерминированная проверка) — сверяет: КАЖДОЕ число/код/единица оригинала ОБЯЗАНО присутствовать в переводе. Потеря/лишнее/искажение → **БЛОК** (не пропускать документ).
- Это код, не модель → 0 галлюцинаций, нельзя «забыть». Прецедент: модель теряла 2-11 из 132 → без гейта ушло бы битым.
- Не прошёл гейт → вернуться к шагу 4 (карта плейсхолдеров битая) или шагу 2 (маскирование пропустило число).

### Шаг 6 — VLM-проверка вёрстки (глазами, не pixel-diff)
- Рендер переведённого PDF → PNG → VLM (Claude / Qwen2.5-VL) **смотрит глазами**: не разъехалась ли вёрстка, не наложился ли текст, таблицы целы.
- НЕ pixel-diff (язык меняет длину текста — pixel-diff даст ложные срабатывания). Именно визуальная проверка осмысленности.

### Шаг 7 — human-финал
- Человек = финальный гейт (Alarcon-принцип, `prompt-elaboration.md`). Перевод документа на таможню/в инженерию — критичен, отправка = CONFIRM.

## Переключаемый бэкенд (model-bakeoff)

| Бэкенд | Стоимость | Когда |
|--------|-----------|-------|
| **Qwen-Ollama** (локально) | **0₽** | дефолт для объёмных документов, нет утечки |
| **DeepSeek** | дёшево | баланс цена/качество |
| **Claude** (токены) | дороже | сложные домены, максимум качества |

Перед закреплением — bakeoff на одном документе (`model-bakeoff.md` + PROVENANCE: модель-автор перевода в манифест).

## Детерминизм + verify (determinism-first-and-verify)

Этот пайплайн — **воркфлоу-как-код** (детерминированный скелет): mask → translate → unmask → **pofilter-gate** → VLM → human. Гейты физически нельзя пропустить. Числа не дрейфуют, потому что не проходят через LLM. Каждый шаг с verify (pofilter числами, VLM глазами).

## Антипаттерны

- ❌ Дать модели переводить документ С числами без маскирования (теряет/искажает молча — 2-11 из 132).
- ❌ Принять перевод без pofilter-gate (нейро-судья ≠ детерминированная сверка чисел).
- ❌ pixel-diff вместо VLM для проверки вёрстки (язык меняет длину → ложные срабатывания).
- ❌ Отправить переведённый документ на таможню/клиенту без human-финала.
- ❌ Самописный layout-парсер вместо BabelDOC (`proven-tools-first.md`).

# Case Page Minimal — анонимный минималистичный кейс-лендинг продукта/бота

> Захвачено из работы Fable 5 (сессия bd4edb82, 2026-06-12, кейсы bot-clinic). Антон: «отлично… используй ЧЁТКО такой же формат, рисовал другие функции бота». Правило `capture-wins-as-skills.md`.

> Связано: `branding-policy.md`, `security.md` (ТАБУ AI/бренд клиента в публичном), `image-quality-standard.md`, `mobile-first-all-html.md`, `html-clients.md`, `factcheck`, `page-review`.

## Когда применять
Кейс-страница ПРОДУКТА (бот, Mini App, дашборд, автоматизация), которую делаем АНОНИМНО (без имени клиента-клиники по NDA/п.6.3) и показываем ЧТО умеет продукт через сами интерфейсы. Триггеры: «история с ботом без имени клиники», «кейс бота», «переделай кейс в этом формате», «другие функции бота тем же форматом».

## Когда НЕ применять
- Нужен подробный сторителлинг-кейс с цифрами/отзывами (это другой формат — длинный кейс).
- Можно называть клиента (тогда обычный page-review с брендом).

## ФОРМАТ (жёсткий — то что зашло Антону)
**Минимализм. Страница = ровно:**
1. **Заголовок** + 1 подзаголовок (что за продукт, без воды).
2. **3-4 интерфейса-мокапа** продукта (пиксель-точные, в стиле реальной платформы — напр. Telegram iOS) + **короткая подпись** под каждым (1 строка, что делает).
3. **CTA** (одна кнопка).
НИКАКИХ: story-секций, «о проблеме», 11 фич-карточек, статистики, тарифов, длинных абзацев. Эталон: было 53КБ → стало 25КБ (срезать всё лишнее).

## ЖЁСТКИЕ правила
1. **Анонимность (security.md ТАБУ):** на live — НОЛЬ упоминаний бренда клиента, username бота, AI/нейросети/Claude/SpeechKit. Grep перед деплоем: бренд клиента, `@bot`, «нейросет/AI/GPT/Claude/SpeechKit» = 0.
2. **Мокапы по ПЕРВОИСТОЧНИКУ (не выдумка):** тексты интерфейсов берутся из РЕАЛЬНОГО кода продукта (хэндлеры бота, экраны Mini App), не сочиняются. Фразы — те, что юзер реально видит.
3. **Пиксель-точность платформы:** мокап Telegram = реальная вёрстка Telegram iOS (пузыри, кнопки, шапка), не абстрактный «чат». object-fit cover, без растяжения (visual-content R2).
4. **OG-превью 1200×630** (для рассылки в мессенджерах) + meta description.
5. mobile-first (min-width), автономный HTML (без CDN), бренд **Artvision** (sticky bar + «Задать вопрос» + футер — это НАШ кейс, не клиентский документ).
6. Исходники + спека UI + реестр функций → git (`clients/artvision-pro/cases/`).

## Шаги
1. Прочитать реальный код продукта → выписать точные тексты экранов/фич, которые показываем.
2. Сверстать пиксель-точные мокапы платформы (TG iOS и т.п.) с этими текстами.
3. Собрать страницу по формату (заголовок → мокапы+подписи → CTA), срезать всё лишнее.
4. Анонимизация-греп (п.1) + OG-image + factcheck-v2 (0 CRITICAL) + page-review/ui-visual (375/1440 глазами).
5. Деплой `artvision.pro/cases/<slug>/` → curl page 200 + og 200 → deploy-URL первой строкой, статус «на ревью» (explicit-approval).

# /autopilot <проект> <задача> — автономное money-safe добивание

> **СТАТУС: ЧЕРНОВИК v0.1 — на ревью у Антона. НЕ деплоить на VPS, НЕ запускать боевым.**
> Предусловия боевого запуска (без них НЕ работает): см. секцию «Предусловия» внизу. Главное — `round_table` + явный approve Антона (это автономно-тратящий money-tool, blast-radius на 3 аккаунта).
> Источник спеки: `~/artvision-data/decisions/2026-06-20-autopilot-spec.md`. Образец RUNBOOK: `clients/usmile/ppc/RUNBOOK-AUTONOMOUS-2026-06-20.md`.
> Связано: `vps-parallel-combine.md` (VPS-механизм), `handover` / `resume-read-project-state` (память между сессиями), `loop`, `ppc-upload-always-off` + `security.md` (money-гейты), `determinism-first-and-verify`, `enforcement-primitives` (blast-radius), `explicit-approval-tracking`.

## Что делает (одна кнопка → добивание до конца, без траты денег)

`/autopilot usmile "добей PPC-очередь набора 2"` =

1. **STATUS-pin** — генерит/обновляет ОДИН живой `clients/<slug>/STATUS.md` (тема + живой TODO: ✅ сделано / 🔄 в работе / ⏳ осталось / 🔒 ждёт Антона + next). Источник правды между сессиями. Обновляется ПО ХОДУ.
2. **Money-safe scope** — выполняет ТОЛЬКО не-тратящие действия (whitelist). Тратящее/включение/модерация/публикация → стоп + запись в «Ждёт Антона», продолжает остальное.
3. **Dispatch на VPS (опционально)** — `combine-vps-dispatch.sh` (adw-аккаунт, headless tmux) → комп можно выключать.
4. **Петля добивания** — берёт верхний `[ ]` из STATUS → детерминированный пайплайн → verify → отметить `[x]` → следующий. При ~70% контекста → обновить STATUS + handover → **запросить /clear у Антона** (НЕ нажимает сам).
5. **Отчёт** — TG-нотификация Антону («добито N, ждёт K на CONFIRM, тратящих=0»).

Это НЕ комбайн (комбайн тянет всю очередь Asana/TODO). Autopilot пришпилен к ОДНОМУ проекту/теме и не дрейфует.

## 🔴 MONEY-SAFETY (HARD — нарушение = провал, главный инвариант)

Автономный агент **НИКОГДА** не тратит деньги клиента и не берёт на себя CONFIRM-решения. Это не «осторожность» — это жёсткая граница scope.

### Whitelist — что МОЖНО автономно (не тратит)
| Действие | Почему безопасно |
|----------|------------------|
| `assemble` / `build_*` — сборка кампаний/контента из semantics в JSON | READ-ONLY, файлы |
| `upload --apply` с результатом **OFF/SUSPENDED/DRAFT** | не показывается → не тратит (`ppc-upload-always-off`) |
| READ кабинета: `campaigns.get`, `keywordbids.get`, `AuctionBids`, отчёты | чтение |
| Файлы проекта: Read/Write/Edit в `clients/<slug>/` | локально |
| `git add/commit/push` (артефакты, STATUS, handover) | версионирование |
| Обновление STATUS.md / RUNBOOK / context-log | трекинг |

### Blacklist — СТОП + «Ждёт Антона» (тратит / CONFIRM, security.md)
| Действие | Гейт |
|----------|------|
| `campaigns.update` State=**ON** / снятие с паузы / запуск показов | 🔒 CONFIRM Антона |
| `keywordbids.set` **боевых** ставок (не минималка 30 коп) | 🔒 CONFIRM |
| `ads.moderate` (флипает DRAFT→ON, начнёт тратить) | 🔒 CONFIRM |
| Публикация страниц / page-publish на боевой сайт | 🔒 CONFIRM |
| Платные API (Topvisor checker/go, SMS, рассылки) | 🔒 CONFIRM + стоимость |
| Контакт с клиентом (TG/email/звонок) | 🔒 CONFIRM (security.md) |
| Любое необратимое/деструктивное на проде клиента | 🔒 CONFIRM |

### Hard-gate в каждом cabinet-write (детерминированно, не «на память»)
- После ЛЮБОЙ заливки → `campaigns.get` State → **assert State NOT in (ON, CONVERTED)**. Если попал → немедленный `campaigns.suspend` + повторная проверка. (`ppc-upload-always-off`: модерация черновика флипает в ON — после `ads.moderate` обязателен `suspend`.)
- Печатать «OFF/SUSPENDED» только после РЕАЛЬНОГО чтения State (не false safety).
- Ставки на резерв/заливке = минимум (30 коп), пока Антон не задал боевые.
- При попадании на любой blacklist-пункт — НЕ выполнять, записать в STATUS «🔒 Ждёт Антона: <что>», продолжить следующий `[ ]`.

### Money-доказательство по завершении (в отчёт)
- `тратящих = 0` (подтверждено `campaigns.get` State по всем кампаниям) — числом, не «вроде».
- Список CONFIRM-действий что НЕ выполнены (отложены Антону).

## Session-continue — бесшовное продолжение после /clear (БОЛЬ Антона)

**Проблема:** после `/clear` свежая сессия дрейфует — уходит в меню/комбайн, теряет тему до-clear сессии, Антон вынужден говорить «стой, работаем только с этим проектом». Task-tool TODO эфемерны — не переживают /clear.

**Механизм (как свежая сессия продолжает ТУ ЖЕ тему без печатания):**

1. **Маркер активной темы.** Autopilot при старте пишет `/tmp/autopilot-active-<slug>` (содержит slug + путь к STATUS + тему + timestamp). Живёт пока тема активна.
2. **SessionStart-хук `session-continue-pin.sh`** (черновик рядом, НЕ зарегистрирован — ждёт approve). При старте сессии (source=clear/resume): если есть свежий `/tmp/autopilot-active-*` → инжектит system-reminder: «АКТИВНЫЙ AUTOPILOT: <тема>. НЕ показывай меню-комбайн. Прочитай `clients/<slug>/STATUS.md` + context-log + продолжи верхний `[ ]` из ОЧЕРЕДИ. Money-scope из STATUS.» → **подавляет дрейф в комбайн** (источник проблемы).
3. **TODO-из-файла (Task-tool не переживает /clear).** На resume Claude re-create Task-tool задачи из `## ОЧЕРЕДЬ` STATUS.md (каждый `[ ]` → TaskCreate, `[x]`/`[🔒]` пропустить).
4. **Сверка closed vs open.** Для каждого `[x]` в STATUS — подтвердить по git (`git log --oneline -- clients/<slug>/`) и/или состоянию кабинета (`campaigns.get`), что реально сделано (не «отметил, но не сделал»). Расхождение → вернуть в `[ ]`. Это `explicit-approval-tracking` + verify (деплой/коммит ≠ одобрено/готово, проверить фактом).
5. **Продолжение без меню.** Свежая сессия НЕ запускает `/go`/меню перекрёстка — сразу берёт верхний `[ ]`. Маркер снят (`rm /tmp/autopilot-active-<slug>`) ТОЛЬКО когда очередь пуста ИЛИ всё в «Ждёт Антона».

> ⚠️ **Честно: `/clear` — клавиша Антона, Claude САМ её не нажмёт** (нет такой возможности в Claude Code). Autopilot при ~70% контекста: обновляет STATUS → handover → **просит** «контекст ~70%, готов /clear — нажми, свежая сессия продолжит сама». До нажатия Антона работу не бросает. «Ноль печатания» = почти: его `/clear` + 0 слов (хук авто-пинит проект).

## Алгоритм (детерминированный скелет — `determinism-first-and-verify`)

```
0. PRE-READ (resume-read-project-state): context-log.md → STATUS.md → plan/task-plan*.md → WAITING-FROM-CLIENT → последний handover. find на дубли перед созданием файла.
1. STATUS-pin: создать/обновить clients/<slug>/STATUS.md (тема + scope + очередь). Записать /tmp/autopilot-active-<slug>.
2. (опц.) DISPATCH: combine-vps-dispatch.sh "<prompt с путём к STATUS+RUNBOOK>" — если Антон сказал «на VPS / выключаю комп».
3. ПЕТЛЯ (для каждого верхнего [ ] в ОЧЕРЕДИ):
   a. money-precheck: задача попадает в blacklist? → да: [🔒] «Ждёт Антона», continue. нет → дальше.
   b. выполнить через [pipeline:] (детерминир. скрипт/скилл).
   c. cabinet-write? → assert State NOT in (ON,CONVERTED); если ON → suspend + re-check.
   d. verify результата ЧИСЛАМИ (State=OFF / файл создан / curl 200 / diff). Не «вроде сделал».
   e. отметить [x] + commit + обновить СОСТОЯНИЕ в STATUS.
   f. контекст ~70%? → обновить STATUS + Skill handover → ЗАПРОСИТЬ /clear у Антона, стоп до нажатия.
4. STOP: очередь пуста ИЛИ всё оставшееся = [🔒] Ждёт Антона → итог + handover + TG-отчёт. rm /tmp/autopilot-active-<slug>.
```

**Последовательно, НЕ параллельно:** петля пишет в ОДИН кабинет/STATUS → race-условие при параллели (`determinism-first-and-verify` §2.3 — write в общий ресурс не параллелить). Один проект = один поток.

## Когда применять / НЕ применять
- **Применять:** длинная money-safe очередь по ОДНОМУ проекту (PPC OFF-сборка, контент-батч, SEO-правки), Антон хочет «запустил и ушёл».
- **НЕ применять:** разовая правка <5 мин; задача целиком CONFIRM (нечего автономить); несколько разных проектов (это комбайн, не autopilot); пока нет approve Антона (черновик).

## Антипаттерны
- ❌ Включить кампанию / поставить боевые ставки / модерация / публикация без CONFIRM (главный money-провал).
- ❌ Печатать «OFF» не прочитав реальный State (false safety).
- ❌ Свежая сессия после /clear ушла в комбайн/меню вместо продолжения темы (дрейф — то, что болит Антону).
- ❌ Отметить `[x]` не проверив фактом (git/State) — false-done (`explicit-approval-tracking`).
- ❌ Claude «нажал /clear» — невозможно, только запрос.
- ❌ Параллелить петлю по одному кабинету (race).
- ❌ Боевой запуск без round_table + approve Антона.

## Предусловия боевого запуска (без них = 0)
1. 🔴 **Разовый логин adw на VPS** — `ssh vps-andrey` → `claude` → `/login` (adw.artvision.pro) → код из браузера. Только Антон, ~2 мин (`vps-parallel-combine`). Без этого VPS-автономия не работает.
2. **Тест 3 кейса:** (а) нормальный OFF-прогон — тратящих=0; (б) упёрся в CONFIRM — реально НЕ выполнил, записал в «Ждёт Антона»; (в) контекст-лимит → handover + запрос /clear → свежая сессия продолжила ту же тему без дрейфа.
3. **round_table** (`tool-adoption-proof`) + явный **approve Антона** — autonomous money tool, blast-radius 3 аккаунта.
4. Хук `session-continue-pin.sh` зарегистрирован в settings.json (после approve + тест 3 блок/3 пропуск/bypass).

## Честные ограничения (сказать Антону)
- Нативного «авто-switch на свежую сессию при 70%» в Claude Code НЕТ — эмулируется handover→запрос /clear→хук-пин.
- Subagent/socket ночью падал (403) — автоном может подвисать на VPS, не 100% гарантия (`orchestration-method-selection`: падает рой → main-процесс).
- Полностью без Антона нельзя: CONFIRM-действия (включение/трата/модерация/публикация) ждут его всегда + сам `/clear` — его клавиша.

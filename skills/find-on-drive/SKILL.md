# /find-on-drive — поиск в Google Drive (MCP)

> ⚠️ Это ЕДИНСТВЕННЫЙ путь искать Google Drive: Drive **не синкается локально**
> (нет `~/Library/CloudStorage/GoogleDrive*`), поэтому бесплатный Spotlight-хук и
> `/find-client-files` его не видят. Здесь идёт облачный MCP-запрос — он тратит токены.

## Когда вызывать
- Пользователь ЯВНО назвал Google Drive / гугл диск / драйв / гугл док в облаке.
- НЕ вызывать для «найди на компе/файл клиента» — там бесплатные `/find-client-files` (Spotlight) и `/find-anywhere`.

## Workflow
1. Из запроса вывести компактный поисковый запрос (имя клиента/тема/тип документа).
2. Вызвать MCP: `mcp__claude_ai_Google_Drive__search_files` с этим запросом.
   - Если сервер отдаёт OAuth/scope ошибку в headless/CLI (частый кейс) — сообщить честно и предложить альтернативу (export-URL гугл-дока, если ID известен; или попросить Антона дать ссылку).
3. Вернуть СПИСОК: имя файла · тип · дата · ссылка. Содержимое целиком НЕ грузить — читать только 1-2 реально нужных через `read_file_content`/`download_file_content`.
4. Если нашлось дёшево локально — не дублировать облачным поиском.

## Дешёвая альтернатива (рекомендовать Антону)
Включить **Google Drive for Desktop** (синк в локальную папку) → весь Drive попадёт
в бесплатный Spotlight-хук + `/find-client-files`, и этот MCP-скилл станет не нужен (0 токенов).

Связано: skills `find-client-files`, `find-anywhere`; memory `reference-file-search-tools-triggers`.

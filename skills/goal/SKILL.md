# /goal — Goal-Oriented Execution System

## ПРИНЦИП

```
ЦЕЛЬ → ИНТЕРВЬЮ → ПУТЬ → ВЫПОЛНЕНИЕ → ПРОВЕРКА → СРАВНЕНИЕ С ЦЕЛЬЮ
```

Claude НЕ НАЧИНАЕТ работу пока не пройдены ВСЕ фазы подготовки.
Claude НЕ ОСТАНАВЛИВАЕТСЯ пока цель не достигнута И результат не сверен с целью.

---

## ФАЗА 0: СОЗДАНИЕ GOAL-ФАЙЛА

При запуске `/goal <описание>`:

1. Создать файл `goals/GOAL_<slug>_<date>.md` в проекте
2. Записать исходную формулировку цели ДОСЛОВНО (это якорь для сравнения)
3. Все дальнейшие фазы — записываются туда же

```bash
# Пример
goals/GOAL_ant-partners-report-pages_2026-02-06.md
```

---

## ФАЗА 1: ИНТЕРВЬЮ (Claude спрашивает, пользователь отвечает)

**Claude ОБЯЗАН задать ВСЕ эти вопросы. Не пропускать. Не угадывать ответы.**

### Обязательные вопросы:

```
1. ДЕДЛАЙН
   "К какой дате это должно быть готово?"

2. ОПРЕДЕЛЕНИЕ ГОТОВНОСТИ
   "Как ты поймёшь что цель достигнута? Что ты увидишь/получишь?"
   (конкретный артефакт: файл, URL, отчёт, сообщение в чат)

3. ПОЛУЧАТЕЛЬ
   "Кто получатель результата? Клиент / ты / команда?"

4. ТЕКУЩЕЕ СОСТОЯНИЕ
   Claude САМ проверяет:
   - git log (что уже сделано)
   - ls файлов (что есть)
   - asana_cli.py tasks <client> --open (что висит)
   - sync/SYNC_STATUS.md (последний статус)
   И ПОКАЗЫВАЕТ пользователю: "Вот что я вижу: X готово, Y нет"

5. БЛОКЕРЫ
   "Есть что-то что может помешать? Доступы, оплаты, ожидание от кого-то?"

6. ОГРАНИЧЕНИЯ
   "Что НЕ делать? Платные API? Публикация без подтверждения?"

7. ПРИОРИТЕТ КАЧЕСТВА
   "Что важнее: скорость или качество? Или баланс?"
```

### Дополнительные вопросы (если контекст неясен):
- "Какой клиент / проект?"
- "Есть эталон / пример как должно выглядеть?"
- "Связано ли это с другими задачами?"

### Запись в goal-файл:

```markdown
## Интервью

- **Цель (дословно):** <то что сказал пользователь>
- **Дедлайн:** 07.02.2026
- **Готовность =** PDF отчёт в Asana + 13 URL на сайте
- **Получатель:** Клиент ANT Partners
- **Текущее состояние:** 9/13 HTML готовы, 0 опубликовано
- **Блокеры:** нет
- **Ограничения:** без Topvisor, публикация с подтверждением
- **Приоритет:** баланс скорость/качество
```

## ФАЗА 2: ПУТЬ (Path — декомпозиция до атомарных шагов)

Claude строит путь ОТ ЦЕЛИ К ТЕКУЩЕМУ СОСТОЯНИЮ (backwards planning):

```
ЦЕЛЬ: 13 страниц на сайте + отчёт
  ← Для этого нужно: опубликовать 13 HTML
    ← Для этого нужно: 13 готовых HTML
      ← Для этого нужно: доделать 4 недостающих
        ← Для этого нужно: спарсить контент исходных страниц
```

### Формат шага:

```markdown
### ШАГ N: <название>
- **Вход:** что нужно на входе
- **Действие:** что конкретно делать
- **Выход:** что получится
- **Критерий DONE:** команда проверки (bash/ls/curl/grep)
- **Постулаты:** какие правила CLAUDE.md применимы
- **Оценка:** ~X минут / ~Y токенов
```

### Пример:

```markdown
### ШАГ 1: Доделать HTML страницы 10-13
- **Вход:** контент с ant.partners (WebFetch), config.yaml клиента
- **Действие:** Task(frontend-developer) для каждой страницы
- **Выход:** 4 файла в clients/ant-partners/output_v6/
- **Критерий DONE:** `ls clients/ant-partners/output_v6/*.html | wc -l` >= 13 И каждый > 10KB
- **Постулаты:** [КОНТЕНТ ДОСЛОВНО] [HTML АВТОНОМНЫЙ] [МЕТА ЧЕРЕЗ CURL]
- **Оценка:** ~30 мин
```

### Показать пользователю и ДОЖДАТЬСЯ подтверждения:

```
Путь к цели (4 шага):
1. Доделать 4 HTML → 13 файлов в output_v6/
2. Публикация на MODX → 13 URL на ant.partners
3. Отчёт январь → PDF в reports/
4. Закрытие Asana → 0 overdue

Всего: ~2ч, ~50K токенов
Подтверждаешь путь?
```

## ФАЗА 3: ВЫПОЛНЕНИЕ (Execute)

### Перед КАЖДЫМ шагом:
1. Прочитать goal-файл (напомнить себе цель и текущий шаг)
2. Проверить постулаты применимые к этому шагу
3. Записать `[IN PROGRESS]` в goal-файл

### После КАЖДОГО шага:
1. Выполнить критерий DONE (команду проверки)
2. Записать результат в goal-файл: `[DONE]` или `[FAILED: причина]`
3. Git commit с результатом
4. Обновить sync/SYNC_STATUS.md

### При FAILED:
- НЕ переходить к следующему шагу
- Записать причину
- Попробовать исправить (до 3 попыток)
- Если 3 попытки не помогли → спросить пользователя

### Формат прогресса в goal-файле:

```markdown
## Прогресс

| # | Шаг | Статус | Время | Проверка |
|---|-----|--------|-------|----------|
| 1 | HTML страницы | [DONE] ✅ | 12:30-13:05 | 13 файлов, все >10KB |
| 2 | Публикация MODX | [IN PROGRESS] 🔄 | 13:10-... | — |
| 3 | Отчёт | [PENDING] ⏳ | — | — |
| 4 | Asana cleanup | [PENDING] ⏳ | — | — |
```

---

## ФАЗА 4: ПРОВЕРКА ПОСТУЛАТОВ (после каждого шага)

Claude ОБЯЗАН проверить применимые постулаты. Чеклист:

### Постулаты для проверки:

```
[P1] КОНТЕНТ ДОСЛОВНО
  └─ Проверка: подсчитать H2/FAQ/карточки, сравнить с исходником
  └─ Когда: создание/перенос контента

[P2] HTML АВТОНОМНЫЙ
  └─ Проверка: grep -oE 'https?://[^"'\''> ]+' file.html | grep -v schema.org
  └─ Когда: создание HTML файлов

[P3] МЕТА-ТЕГИ ЧЕРЕЗ CURL
  └─ Проверка: НЕ использовать WebFetch для проверки title/description
  └─ Когда: SEO аудит, проверка мета

[P4] ПЛАТНЫЕ API — ПОДТВЕРЖДЕНИЕ
  └─ Проверка: перед Topvisor/Директ — показать стоимость, ждать "да"
  └─ Когда: любая операция с балансом

[P5] GIT COMMIT ПОСЛЕ ШАГА
  └─ Проверка: git status = clean после каждого шага
  └─ Когда: всегда

[P6] КАРТИНКИ < 100KB
  └─ Проверка: ls -la *.{png,jpg} | awk '{if ($5>102400) print}'
  └─ Когда: HTML с изображениями

[P7] АГЕНТ БЕЗ ДАННЫХ = ГАЛЛЮЦИНАЦИИ
  └─ Проверка: перед вызовом агента — есть ли реальные данные?
  └─ Когда: SEO аудит, анализ конкурентов

[P8] SYNC_STATUS ОБНОВЛЁН
  └─ Проверка: git diff sync/SYNC_STATUS.md — изменён?
  └─ Когда: конец каждого шага
```

Запись в goal-файл:

```markdown
### Постулаты — ШАГ 2
- [P1] ✅ H2=7/7, FAQ=5/5 — совпадает с исходником
- [P2] ✅ 0 внешних URL
- [P5] ✅ commit abc1234
- [P8] ✅ SYNC_STATUS обновлён
```

## ФАЗА 5: СРАВНЕНИЕ С ЦЕЛЬЮ (финал)

**После выполнения ВСЕХ шагов — Claude НЕ СЧИТАЕТ работу завершённой.**

Claude ОБЯЗАН:

1. **Перечитать исходную формулировку цели** (из Фазы 0)
2. **Перечитать определение готовности** (из интервью)
3. **Выполнить ВСЕ проверки:**

```markdown
## Сравнение с целью

### Исходная цель:
> <дословная цитата из Фазы 0>

### Определение готовности:
> <дословная цитата из интервью>

### Проверка:
| Критерий | Ожидание | Факт | Статус |
|----------|----------|------|--------|
| 13 HTML файлов | 13 файлов >10KB | 13 файлов, мин 14KB | ✅ |
| Опубликованы на сайте | 13 URL 200 OK | 13/13 отвечают | ✅ |
| Отчёт за январь | PDF в reports/ | report_2026-01.pdf 2.3MB | ✅ |
| Asana задачи | 0 overdue по ant | 0 overdue | ✅ |

### ВЕРДИКТ: ✅ ЦЕЛЬ ДОСТИГНУТА / ❌ ЦЕЛЬ НЕ ДОСТИГНУТА

Если ❌ — указать что именно не совпадает и что нужно доделать.
```

4. **Показать пользователю итог** — не просто "готово", а таблицу сравнения
5. **Пользователь подтверждает** — "да, цель достигнута" или "нет, вот что не так"

## Исходная цель (ЯКОРЬ — не редактировать!)
> <дословная формулировка от пользователя>

## Интервью
- **Готовность =** ...
- **Получатель:** ...
- **Текущее состояние:** ...
- **Блокеры:** ...

## Путь

### ШАГ 2: ...

| # | Шаг | Статус | Время | Проверка |
|---|-----|--------|-------|----------|

## Постулаты

## ПРАВИЛА ВЫПОЛНЕНИЯ

1. **Не начинать работу без завершённого интервью**
2. **Не переходить к следующему шагу без DONE на текущем**
3. **Не считать работу завершённой без сравнения с целью**
4. **При каждом resume сессии — перечитать goal-файл**
5. **Goal-файл = single source of truth для этой задачи**
6. **SYNC_STATUS.md обновлять параллельно (для других сессий)**
7. **Git commit после каждого шага с ссылкой на goal**

---

## ОБРАБОТКА СБОЕВ

### Сессия упала:
```
1. Новая сессия стартует
2. Claude читает CLAUDE.md → видит /goal систему
3. Читает goals/GOAL_*.md со статусом ACTIVE
4. Находит последний [IN PROGRESS] шаг
5. Проверяет его DONE-критерий
6. Если DONE — переходит дальше
7. Если не DONE — повторяет шаг
```

### Шаг не получается (3 попытки):
```
1. Записать в goal-файл: [BLOCKED: причина]
2. Спросить пользователя
3. НЕ пропускать шаг молча
```

### Контекст переполнен:
```
1. Git commit текущий прогресс
2. Обновить goal-файл
3. Завершить сессию
4. При resume — продолжить с нужного шага
```

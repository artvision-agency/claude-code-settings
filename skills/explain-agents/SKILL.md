# /explain-agents — Обучающий разбор работы агентов

## ЦЕЛЬ

Создать понятный обучающий отчёт для Андрея (@PandaCaffe), который объясняет:
1. Какие агенты/субагенты были вызваны в текущей сессии
2. ПОЧЕМУ именно эти агенты (по каким признакам в промпте)
3. Как они взаимодействовали (последовательно / параллельно / рой)
4. Что каждый вернул и как это было объединено в ответ

---

## ПРОЦЕСС

### Шаг 1: Анализ текущей сессии

Проанализируй последнюю выполненную задачу (или указанную пользователем) и определи:

```
ЗАДАЧА: [что попросил пользователь]
АНАЛИЗ ПРОМПТА:
  - Ключевые слова: [какие слова в запросе]
  - Тип задачи: [исследование / создание / проверка / комплексная]
  - Сложность: [простая / средняя / сложная]
  - Нужен ли параллелизм: [да/нет]
```

### Шаг 2: Карта вызовов агентов

Для КАЖДОГО вызванного агента/субагента заполни:

```markdown
## Агент #N: [тип агента]

**Тип вызова:** Task tool → subagent_type = "[тип]"
**Почему этот агент:**
- Признак в промпте: "[конкретные слова/контекст]"
- Альтернативы: [какие ещё агенты подходили и почему выбран этот]

**Что было передано агенту:**
- Промпт: [краткое содержание]
- Контекст: [что агент знал]

**Что агент вернул:**
- Результат: [краткое содержание]
- Токены: [примерное количество]
- Время: [сколько работал]

**Параллельность:**
- Запущен параллельно с: [другие агенты] / Запущен последовательно после: [агент]
```

### Шаг 3: Схема взаимодействия

Нарисуй ASCII-схему:

```
Запрос пользователя
        │
        ├──→ [Агент 1: тип] ──→ результат 1 ─┐
        │                                      │
        ├──→ [Агент 2: тип] ──→ результат 2 ─┤──→ ФИНАЛЬНЫЙ ОТВЕТ
        │                                      │
        └──→ [WebFetch: URL] ──→ данные    ───┘
```

### Шаг 4: Правила выбора агентов (обучающий блок)

Объясни общие правила:

| Признак в запросе | Какой агент вызывается | Почему |
|-------------------|----------------------|--------|
| "проверь конкурента" | research-analyst | Глубокий анализ с веб-поиском |
| "сравни с конкурентами" | competitive-analyst | Специализация на конкурентном анализе |
| "сделай страницу" | frontend-developer | Создание HTML/CSS |
| "SEO аудит" | seo-analyzer | SEO-специализация |
| "напиши код" | [язык]-pro | Специалист по языку |
| Несколько независимых задач | Параллельный запуск | Экономия времени |

## СЛОВАРЬ ДЛЯ АНДРЕЯ

| Термин | Что значит |
|--------|-----------|
| **Агент (Agent)** | Claude с специализированным системным промптом |
| **Субагент (Subagent)** | Агент, запущенный внутри основного диалога через Task tool |
| **Task tool** | Инструмент для запуска субагентов |
| **subagent_type** | Тип субагента (research-analyst, frontend-developer, etc.) |
| **Параллельный запуск** | Несколько агентов одновременно (когда задачи независимы) |
| **Последовательный запуск** | Агенты по очереди (когда результат одного нужен другому) |
| **Рой агентов** | Много агентов работают над разными частями одной задачи |
| **Промпт** | Текст-инструкция для агента |
| **Контекст** | Информация, которую агент "видит" при работе |
| **Токены** | Единицы текста, влияют на стоимость и скорость |

## ПРИМЕРЫ

### Пример 1: Простая задача (1 агент)
```
Запрос: "Проверь SEO сайта example.com"
→ 1 агент: seo-analyzer
→ Признак: слова "проверь SEO"
```

### Пример 2: Параллельная задача (2+ агента)
```
Запрос: "Проверь конкурента и составь список агентств"
→ Агент 1: research-analyst (проверка конкурента)
→ Агент 2: competitive-analyst (список агентств)
→ WebFetch: (сайт конкурента)
→ Всё параллельно — задачи независимы
```

### Пример 3: Цепочка (последовательно)
```
Запрос: "Создай страницу по контенту с сайта"
→ Шаг 1: WebFetch (парсинг контента)
→ Шаг 2: frontend-developer (создание HTML) — нужен контент из шага 1
→ Шаг 3: code-reviewer (проверка) — нужен файл из шага 2
```

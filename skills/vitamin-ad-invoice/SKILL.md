# Vitamin Ad-Invoice — счёт на пополнение рекламного бюджета (через Vitamin + VPS)

> Прецедент: 2026-06-16 (клиент HoReCa) — VK-баланс 0₽, старые РК встали. Сформировал счёт на пополнение
> по образцу прошлого через Vitamin, заход через VPS (наш IP режется). Номер/сумма — в context-log клиента (не тут: публичный репо, #31).
> Связано: `~/.claude/rules/browser-via-vps-for-blocked-ip.md` (VPS-туннель), `vps-browse.sh`,
> `agent-browser`, `finance-password-gate.md` (показ сумм), `security.md` (отправка клиенту = CONFIRM),
> `revenue-accounting.md` (рекл.бюджет = passthrough, НЕ MRR), `client-stack-discovery.md`.

## Когда применять
- У клиента рекламный баланс 0 / на нуле, нужно пополнить (VK Реклама / Я.Директ через Vitamin).
- Клиент ведёт пополнение через Vitamin.tools (кошелёк с кэшбэком). Проверить в `clients/<slug>/access.md` (есть Vitamin-логин) + `client-stack-discovery`.
- НЕ применять: если клиент платит площадке напрямую / через eLama / наш СБИС — тогда другой рельс.

## Доступы (НЕ хардкодить — это публичный репо)
- Логин/пароль Vitamin клиента — ТОЛЬКО `clients/<slug>/access.md` (gitignored; `sync-access.sh pull` если нет).
- Обычно тот же email/пароль, что VK-кабинет клиента.

## Шаги (детерминированно)

1. **Заход (через VPS, наш IP часто режется):**
   ```
   ~/.claude/scripts/vps-browse.sh check "https://vitamin.tools/"   # direct=000 vps=200 → нужен VPS
   ~/.claude/scripts/vps-browse.sh open "https://vitamin.tools/"
   ```
2. **Логин в кабинет:** на `vitamin.tools` → «Вход ▼» → «Войти в кабинет Vitamin.tools» (координатный клик, ref глючит; скрин для координат). Форма: email + пароль из access.md → «Войти». ⚠️ Если капча «Я не робот» — человекоподобно: `agent-browser mouse move x3 → down → up` (авто-клик по ref не проходит).
3. **«ПРИМЕР ПРОШЛЫХ» (обязательно ПЕРЕД выставлением):** левое меню «Финансы» → вкладка «СЧЕТА» → прочитать прошлые счета (номер/сумма/дата/статус/договор). Запомнить типовую сумму и платёжный профиль (юрлицо клиента). Если вкладка отдаёт «Возникла ошибка» (глюк Vitamin) — повторить позже / взять сумму из истории проекта.
4. **Выставить счёт:** кнопка «Пополнить» (верх) → модал «Пополнение личного кабинета»:
   - Тип пополнения = **«Выставить счет»**
   - Выбрать договор (платёжный профиль) = юрлицо клиента (напр. «Договор NNNNN: ООО …»)
   - Сумма для пополнения = **как в прошлых счетах** (по образцу)
   - **«Скачать счёт»** → `agent-browser download @<ref> "clients/<slug>/finance/<slug>-<сеть>-popolnenie-<сумма>-<дата>.pdf"`
   - ⚠️ НЕ путать с «Открыть предоплатный счет» — это депозит (перевод С баланса под %), не счёт клиенту.
5. **Verify:** `Read` скачанного PDF — поставщик (юрлицо Vitamin), заказчик (ООО клиента + ИНН), сумма, назначение платежа, реквизиты. Совпадает с образцом?
6. **Отправка заказчику = CONFIRM (человек):** в кабинете у каждого счёта 2 кнопки — «Скачать» (PDF переслать) и «Отправить» (email заказчику из кабинета). Нажимать «Отправить» / пересылать PDF — ТОЛЬКО после явного ОК Антона/Андрея (контакт с клиентом, `security.md`). Claude готовит, человек подтверждает.
7. **Зафиксировать:** запись в `clients/<slug>/context-log.md` (номер счёта, сумма, дата, сеть, путь к PDF). Запись факта — без пароля; ПОКАЗ сумм на экране — по `finance-password-gate` (но счёт клиенту = client-facing, как КП-цена).

## Заметки по рельсам
- Vitamin ведёт ту сеть, где есть аккаунт (у Грелки — только VK; Я.Директ в Vitamin «нет аккаунтов»).
- Я.Директ-пополнение часто за 2FA на телефон клиента — Vitamin/VPS это НЕ обходит (нужен код клиента или OAuth).
- Рекл.бюджет = passthrough (деньги клиента/инвестора), НЕ в MRR агентства (`revenue-accounting`).

## Антипаттерны

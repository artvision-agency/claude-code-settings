# /ppc — оркестратор контекстной рекламы

Точка входа по всей контекстной рекламе. НЕ делает работу сам — определяет фазу и делегирует. Вся экспертиза/защитные правила лежат в субагенте `ppc-specialist` (`~/.claude/agents/ppc-specialist.md`) и в правилах `ppc-*.md`.

## Использование
`/ppc <клиент> <задача>` — например: `/ppc usmile собери поисковую РК по услугам`, `/ppc grelka проверь кабинет`, `/ppc usmile ставки по колену аукциона`.

## Маршрутизация (определи фазу по задаче → выбери канал)

| Фаза / сигнал в задаче | Канал | Чем |
|---|---|---|
| **Аудит кабинета** (проверь/аудит/план-факт/что не так/утечка) | субагент `ppc-specialist` Воркфлоу D | `cabinet-verify.py` |
| **Семантика/кластеры** (собери ядро/кластеризация/группы) | субагент `ppc-specialist` Воркфлоу A ш.2 | Wordstat + SERP-кластеризация |
| **Тексты объявлений** (тексты/заголовки/переписать объявления) | workflow `ppc-build.js` (детерминир. гейт ppc-ad-check) | `Workflow({name:'ppc-build', args:{...}})` |
| **Сборка/заливка кабинета** (собери РК/залей кампании/настрой рекламу) | субагент `ppc-specialist` Воркфлоу A (полный цикл) | скрипты + XLS-импорт, заливка OFF |
| **Ставки/оптимизация** (ставки/колено/коэффициент/AuctionBids) | субагент `ppc-specialist` Воркфлоу C | `bid_optimizer.py` |
| **«Мало показов»** (после модерации) | субагент `ppc-specialist` ш.6 | `low-impressions-audit.py` |
| **Ретаргетинг/аудитории** | субагент `ppc-specialist` Воркфлоу C | Метрика→Директ lists |

Несколько фаз в одной задаче (напр. «собери кабинет с нуля») → запускай `ppc-specialist` на полный Воркфлоу A (он сам пройдёт семантику→тексты→заливку→модерацию→мало-показов→verify последовательно).

## Как делегировать

**Субагент (большинство задач):**
```
Agent(subagent_type: "ppc-specialist", prompt: "<клиент> <задача>. Контекст: clients/<slug>/ppc/. <конкретика и что мы решили в чате>")
```
Передавай: клиент, посадочные, кластеры (если уже есть), что именно собрать, ограничения. Свежие решения из чата — явно (субагент не видит наш диалог).

**Workflow (тексты, детерминир. порядок с обязательным гейтом):**
```
Workflow({name:'ppc-build', args:{client:'<slug>', groups:[{key,intent,landing,type}]}})
```

## 🔴 Что остаётся за Антоном (CONFIRM, не делегировать на авто)
- **Включение / запуск / снятие с паузы / модерация боевых кампаний** = трата денег клиента (`security.md` CONFIRM, `ppc-upload-always-off`). Субагент готовит всё к запуску (OFF), кнопку жмёт Антон.
- Хук `pre-bash-ppc-api-write-gate` страхует: блокирует API-write до подтверждения.

## Правила (грузятся сами, для справки)
`ppc-upload-always-off`, `ppc-low-impressions-zero`, `ppc-ad-copy-relevance`, `ppc-cheap-click-coefficient`, `ppc-excel-first-then-api`, `ppc-show-as-ad-previews` + KB `knowledge/services/yandex-direct/`.

Результат субагента/воркфлоу → Антону ОДНОЙ сводной таблицей (`single-table-progress-report`): что сделано (факт из API/файла) · что Pending · что требует CONFIRM (включение/трата). Без сглаживания.

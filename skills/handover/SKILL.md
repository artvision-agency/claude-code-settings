# /handover — структурированная передача сессии

> Цель: следующая сессия (или другой человек) поднимает работу за 30 секунд, не теряя ПОЧЕМУ были приняты решения.

## Когда использовать

| Триггер | Действие |
|---------|----------|
| Контекст ≥ 50% | СРАЗУ → handover → /compact focus |
| Закрытие сессии | handover → git push → закрыть |
| Смена задачи | handover → /clear → новая сессия |
| Перед /compact | handover ОБЯЗАТЕЛЕН (auto через pre-compact.sh) |
| Передача коллеге | handover → отправить путь к файлу |

## Где сохраняется

`~/.claude/handovers/HANDOVER-{YYYY-MM-DD-HHMM}-{context}.md`

Где `{context}` = `ops` / `bot` / `infra` / `presale` / `products` (по cwd).

## Структура HANDOVER.md (ОБЯЗАТЕЛЬНЫЕ секции)

```markdown
# Handover: {краткое название работы}

**Дата:** YYYY-MM-DD HH:MM
**Контекст:** {ops|bot|infra|presale|products}
**Сессия:** {имя сессии или session_id}
**Статус:** {в работе | заблокировано | завершено}

## 🎯 Цель сессии (одна строка)

{Что хотели достичь. Без воды.}

## ✅ Что сделано (с файлами + строками)

- `path/to/file.py:42` — добавил X, потому что Y
- `clients/blumart/kp/v3.html` — переписал блок ROI (старый = выдуманные числа)

## 🧠 Решения и ПОЧЕМУ (самая важная секция)

| Решение | Альтернатива | Почему выбрали это |
|---------|--------------|---------------------|
| {что выбрали} | {что отвергли} | {причина — данные, ограничения, опыт} |

> Пример:
> | Использовать Telethon вместо Bot API | python-telegram-bot | Bot API не даёт читать чужие чаты |

## ❌ Что НЕ сделано и почему

- {задача} — заблокировано: {причина}
- {задача} — отложено: {причина, когда вернуться}

## 📚 Уроки (новое знание для memory)

- {урок} → сохранить в `feedback_X.md` или `lessons-X.md`
- {урок} → обновить `MEMORY.md` строка X

## 🔜 Следующие шаги (приоритет)

1. **HIGH:** {что делать первым} — `/path/to/start.md`
2. MEDIUM: {что делать потом}
3. LOW: {nice to have}

## 🗺️ Карта файлов (где что лежит)

```
clients/blumart/
├── kp/v3.html          ← в работе
├── context-log.md      ← обновлён (запись от {дата})
└── meetings/           ← саммари встречи 14.04
```

## ⚠️ Гачи (gotchas — что знать перед стартом)

- VPS 147.45.232.226 → pm2 restart blumart-bot после деплоя
- factcheck-v2.py ОБЯЗАТЕЛЬНО перед scp в clients/
- Антон не любит "может быть" — давай прямо: "не знаю" / "проверю"

## 🔗 Связанные ресурсы

- Asana задача: {URL}
- TG обсуждение: {ссылка на сообщение}
- Предыдущий handover: `HANDOVER-{prev}.md`
```

## Алгоритм генерации

1. **Прочитать TODO.md** текущего контекста
2. **Прочитать context-log.md** клиента (если есть)
3. **git log --oneline -20** — что коммитил в этой сессии
4. **Восстановить решения** из истории (что выбрал, что отверг)
5. **Спросить себя:** что бы я хотел знать, поднимая эту работу через неделю?
6. **Записать** в `~/.claude/handovers/HANDOVER-...md`
7. **Закоммитить** в git (handovers тоже под git)

## Различия с recap

| | Recap (built-in) | Handover (наш) |
|---|------------------|-----------------|
| **Когда** | Auto при /resume после idle | Вручную перед /compact /clear / закрытием |
| **Содержание** | Что делал последним | ПОЧЕМУ принял решения + следующие шаги |
| **Формат** | Авто-генерация LLM | Структурированный шаблон |
| **Назначение** | Я вспомнил контекст | Любой поднял работу |
| **Хранение** | В сессии | В git, переживает /clear |

## Различия с context-log.md

- **context-log.md** — лог КАЖДОГО действия (хук пишет автоматом)
- **handover.md** — СИНТЕЗ сессии (что важно, ПОЧЕМУ, что дальше)

Handover ссылается на context-log, не дублирует.

## Автоматизация

Хук `pre-compact.sh` (создать отдельно):
```bash
#!/bin/bash
# Перед /compact — напомнить про handover
echo "⚠️  Перед /compact создай HANDOVER через skill handover"
echo "   Иначе потеряешь контекст ПОЧЕМУ были приняты решения"
```

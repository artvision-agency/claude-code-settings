## 2. ГДЕ ПРОТЕЧКА (диагноз — механика)

### 🔴🔴 ПЕРВОПРИЧИНА (подтверждена community, research 25.06)
**Известный баг Claude Code: prompt-cache invalidation.** Источник: smartscope.blog (разбор утёкшего 31.03 исходника CC, ~510K строк) + cache-fix repo. Механизм: CC цепляет к КАЖДОМУ запросу anti-abuse «attestation», значения которой МЕНЯЮТСЯ каждый раз → хэш кэша меняется → прошлый кэш ВЫБРАСЫВАЕТСЯ → пересборка по полной. Инфляция **10–20×** [по источнику]. Max-юзеры: лимит за 1ч вместо 8; скачок 21%→100% за один промпт [по источнику].
**Это объясняет «мы ничего не меняли, а трата выросла»** — баг на стороне Anthropic/CC + срез cache TTL 1ч→5мин. У Антона совпало: проблема с ~19-21.06, в файлах единого нашего «переключателя 21.06» НЕТ (effortLevel high с 30.05, autoCompact off с 25.04, плагины с 12.06 — всё раньше).
**СЛЕДСТВИЕ (меняет приоритеты):** если кэш сбрасывается каждый turn — **база 110-130K оплачивается по ПОЛНОЙ цене на КАЖДЫЙ твой запрос** (без скидки кэша). → сжатие базы = прямая линейная экономия, фактор C поднимается в топ.

**cache_read доминирует (93%) потому что:** каждый новый turn перечитывает ВЕСЬ накопленный контекст (системный промпт + вся история сессии). В длинной сессии это растёт **квадратично**: turn 30 перечитывает всё что было в turns 1-29 + базу. cache_read дешевле input в 10×, но при таких объёмах = главная статья расхода лимита.

**Жалоба «два диалога — трата бешеная» объясняется так:** эти 2 диалога идут в УЖЕ РАЗДУТОЙ resume-сессии. Каждый из 2 turn-ов перечитывает 300-500M накопленного контекста. Не «2 диалога дорогие», а «2 диалога поверх горы».

| Ранг | Фактор | Эффект | Лёгкость | Действие |

## 4. ПЛАН (по убыванию ROI) — ЧТО ПОЧИСТИТЬ / ПЕРЕДВИНУТЬ (без потери качества)

> Принцип «без потери качества»: conditional-правила СОХРАНЯЮТ знание (грузятся когда cwd/path матчит). /clear не теряет работу (артефакты в git/файлах). Сжатие MEMORY = детали в topic-файлы, не удаление.

### A. Длинные сессии (ГЛАВНОЕ, поведение + хук)
- **Сейчас:** новая задача → `/clear` или новая сессия. НЕ продолжать сессию на 30+ turns. Перед /clear — handover в файл (работа не теряется).
- **Хук-кандидат (approve Антона):** statusline-предупреждение при ctx>60% «пора /clear» (часть есть) + Stop-warn при сессии >N turns/токенов.

### B. Субагенты
- Рой ТОЛЬКО на независимых задачах, макс 3-4 (уже правило). Субагент НЕ получает большие данные в промпт — путь к файлу + «читай точечно grep/jq».
- Для проверок токенов/расследований — round_table (FREE Groq), НЕ рой Opus (каждый Opus = +дамп правил 110K).

### C. Контекст-налог (дозавершить волну 2 — в ветке + откат)
- `auto-routing-table.md` (30K, 303 скилла) → SKILL-DISCOVERY хук уже даёт это в моменте → кандидат на удаление из автозагрузки.
- `MEMORY.md` (33K) → сжать до 20K (длинные строки → topic-файлы).
- Дожать узкие правила rules→rules-conditional по `TOKEN-DIET-PLAN.md` шаг 2.

### D. Большие tool-результаты
- Я.Директ/SEMrush/Lighthouse/Wordstat API → ответ в файл, в чат сводка (правило `offload-to-script-on-high-spend.md` + FINDINGS §🔴). Хук `post-tool-large-output-guard.sh` живой.

### E. MCP/tool-defs

## 5. ВНЕШНИЕ ПРИЁМЫ РАЗРАБОТЧИКОВ (research devs/GitHub/Twitter, 25.06)
> Числа «по источнику» (внешние, НЕ в клиентские доки). Research-субагент упал «Prompt is too long» — сам по себе доказательство фактора C (база раздута). Сёрфинг сделан в main.

### 🔴 ГЛАВНАЯ НАХОДКА — cache-регрессия на resume
- **`github.com/cnighswonger/claude-code-cache-fix`**: при `--resume`/`/resume` prompt-кэш ломается молча → пересобирается с нуля КАЖДЫЙ turn → сессия ~$0.50/час жжёт **$5-10/час (до 20×)** [по источнику]. ← объясняет «2 диалога = бешено» в продолженных сессиях. (Сторонний фикс — НЕ ставить без round_table/tool-adoption-proof. Но диагноз ценен.)
- **Cache TTL: Anthropic срезал с 1 часа до 5 минут** [по источнику, xda-developers + cherny-tips подтверждает]. Простой >5 мин = весь контекст пересобирается по ПОЛНОЙ цене. → не оставлять сессию idle; перед отходом `/compact`.
- **Opus 4.7+ жжёт ~2.4× от 4.6** (новый токенайзер + adaptive thinking) [по источнику]. Мы на Opus 4.8 **[1M]** — 1М-окно множит cache_read.

### ТОП-5 по ROI (синтез research + round_table + Codex)
1. **НЕ resume гигантские сессии + `/clear` на новую задачу** (cache-регрессия = до 20×). Главное.
2. **Не оставлять idle >5 мин** (TTL 5 мин = полная пересборка). Перед отходом `/compact` или закрыть.

4. **`DISABLE_NON_ESSENTIAL_MODEL_CALLS=1`** в settings (нет потери качества).
5. **Дожать контекст-налог** (auto-routing 30K из автозагрузки, MEMORY 33K→20K, волна 2) + большие API-дампы в файл.

# Presale-разведка — обязательный стандарт

> **Установлено:** 2026-05-08, Антон.
> **Применять:** при любой пресейл-разведке (новый лид, оценка SEO-потенциала, подготовка к звонку с клиентом).
> **Если клиент имеет несколько направлений / доменов — делать по КАЖДОМУ.**

## Что в брифе обязательно

### 1. Позиции через Topvisor — 10 кластерных ключей в основном регионе клиента

- Создать (или использовать существующий) проект Topvisor на ЦЕЛЕВОМ домене клиента.
- Регион — **основной регион клиента** (СПб=2, Москва=213, Казань=43 и т.д. см. `medical-kp.md`).
- Поисковая система — Яндекс (Google добавлять только если клиент явно указал что хочет Google).
- 10 кластерных ключей под основное направление. Если у клиента **N направлений** (массаж + косметология + парикмахеры) — **10 ключей × N направлений** в один проект, разбитыми на группы.
- ОБЯЗАТЕЛЬНО передавать `filters: [{name: 'id', operator: 'EQUALS', values: [<PID>]}]` при `checker/go` — иначе hook `pre-bash-topvisor-guard.sh` блокирует (broadcast по всем проектам).

### 2. Конкуренты — до 3, с размером сайта

- Если клиент сам указал — берём его список (приоритет).
- Если нет — собираем из топ-10 Я.СПб по 2-3 базовым кластерным запросам.
- Для каждого — **минимум:** ИКС, страницы в индексе Яндекс/Google, возраст домена, ключи в топ-10 / топ-50 (через `pr-cy.ru`: `https://a.pr-cy.ru/<domain>/`).
- В Topvisor проект добавить как `competitors` с `on=1` ОБЯЗАТЕЛЬНО (иначе позиции не снимаются).

### 3. Размер сайта = страницы в индексе

- «Размер» = количество страниц в Yandex и Google (через pr-cy).
- Если у клиента и конкурентов сильное расхождение (например, у клиента 49, у конкурента 418) — это главный аргумент про контентный gap.

## Когда делать

- Любая фраза «pre-sale», «лид», «КП», «разговор с клиентом», «разведка», «оценка SEO».
- Перед `presale-kp` — обязательный preflight.

## Формат вывода

HTML с таблицей вида (одна строка на домен):

| Домен | Возраст | ИКС | Стр. Я / G | Топ-10 Я | Топ-50 Я | Заметка |

Plus отдельная таблица позиций по 10 ключам × 4 (клиент + 3 конкурента).

## Критерий «прямой конкурент» (установлено 2026-05-11)

> Прецедент spb-kursy v3: strict-factchecker нашёл что 2 из 3 «прямых конкурентов» — смежные ниши с массажем как побочным направлением.

Прямой конкурент = сумма 5 сигналов (вес 100):

| Сигнал | Вес | Метрика |
|---|---|---|
| Product overlap (тот же продукт на главной) | 35 | H1/title содержит target-продукт |
| SERP overlap по target-кластеру | 25 | ≥30% пересечение ТОП-10 Яндекс ≥3 ключей |
| Регион (lr) / geo-выдача | 15 | Та же geo для целевого региона клиента |
| ICP / тип бизнеса | 15 | Школа vs академия vs частный vs колледж — совпадает |
| Сопоставимый размер | 10 | Возраст ±5 лет, ИКС ×0.3-3, страниц ×0.5-5 |

**Пороги:**
- ≥70 = **Прямой конкурент** (в КП, отслеживание в Topvisor)
- 50-69 = Частично прямой (со звёздочкой «частично»)
- <50 = **Смежный бенчмарк** (НЕ показывать как «прямого», отдельный блок)

**Process для каждого кандидата:**
1. WebFetch главной → проверить H1/title (Сигнал 1)
2. SERP-снимок 3-5 ключей через Topvisor (Сигнал 2)
3. Регион из реквизитов сайта (Сигнал 3)
4. Тип бизнеса вручную (Сигнал 4)
5. ИКС через pr-cy.ru + страницы в индексе (Сигнал 5)

**При следующем presale** — применять балльную систему явно, не «по интуиции». Зафиксировать в `clients/<slug>/config.yaml` под ключом `competitors_validated: true` после применения.

# «Тестируем» → авто-команда сеньоров-тестировщиков + авто-выбор видов тестов (DEFAULT ON)

> **Установлено:** 2026-06-15 (Антон, сессия OPS). Дословно: «когда я говорю "тестируем" — сразу понимай какие виды тестов нужны, подключай все и всю сеньорскую команду (агентов). Я не хочу проговаривать что нужна команда таких-то — ты сам должен это видеть.»
> **Связано:** `agent-roster.md` (задача→агент), `parallel-task-orchestration.md` (рой сеньоров+граф), `parallel-skill-groups.md` (Класс 3 code-review/security), `auto-specialist-routing.md` (авто-спец+рой), `orchestration-method-selection.md` (рой vs main при 403), `quality.md` (QA-gates, qa-full.sh), `bulletproof-patterns.md` (verify), `no-smoothing.md`.

## Правило (DEFAULT — без проговаривания Антоном)
На триггер **«тестируем / протестируй / прогони тесты / проверь как работает / QA / работает неправильно / все виды тестов»** Claude САМ:
1. **Определяет тип артефакта** → из него **виды тестов** (таблица ниже). Не спрашивает «какие тесты нужны».
2. **Авто-подключает сеньорскую агент-команду** под эти виды (рой, макс 3-4 параллельно, только Opus — `parallel-task-orchestration`/`antipatterns`). Антон НЕ перечисляет агентов.
3. **Прогоняет + консолидирует находки** (dedup по severity, `parallel-skill-groups`): CRITICAL>HIGH>MID>LOW, cross-confirm 2+ агента.
4. **Каждая находка → задача** (`audit-findings-to-tasks`). Вердикт PASS/REVIEW/FAILED.

## Авто-карта: тип артефакта → виды тестов → сеньоры
| Артефакт | Виды тестов (авто) | Агенты/скиллы команды |
|----------|---------------------|------------------------|
| **Frontend / HTML / дашборд** | рендер+визуал (3 breakpoints), взаимодействия E2E, адаптив/мобайл, accessibility, консоль-ошибки | `ui-visual-validator` + `e2e-runner` (Playwright) + `accessibility-tester` + `frontend-developer` |
| **Backend / API** | эндпоинты (статусы/контракты), auth/доступы, обработка ошибок, нагрузка (если нужно), security/OWASP | `backend-developer` + `security-engineer`/`/security-review` + `api`-тесты |
| **Данные / точность** | сверка источник↔вывод, числа дословно, граничные | `data-analyst` + `strict-factchecker` |
| **Код (любой)** | unit/coverage, статика, security, ревью идиом | `test-automator` + `code-reviewer` + `/security-review` (+ `/tdd`) |
| **Telegram-бот** | state-машина, сценарии, деплой-смоук | `/bot-audit` + `e2e-bot-tester` |
| **Интеграция/полный флоу** | E2E цепочка от входа до результата | `e2e-runner` + профильные по слоям |

**Кросс-слойный артефакт (напр. OPS-дашборд = frontend+backend+данные+auth)** → команда ИЗ НЕСКОЛЬКИХ строк сразу: визуал+E2E (frontend) + эндпоинты+auth (backend) + Asana↔вывод (данные) + security (доступы видов). Это и есть «все виды тестов».

## Метод запуска (надёжность — `orchestration-method-selection`)
- Здоровы субагенты → рой `Agent(run_in_background)` 3-4 параллельно, по слоям.
- **403/socket/Dumb Zone** → НЕ долбить рой: те же виды тестов **последовательно в main-процессе** по чеклисту ИЛИ named workflow (детерминированный скелет). Качество тестов в Dumb Zone падает → крупный QA лучше в свежей сессии (сказать Антону честно, не имитировать).
- Воркфлоу-кандидаты: `/qa-pipeline`, `/swarm` (test+fix+verify), `/code-audit` (4 агента).

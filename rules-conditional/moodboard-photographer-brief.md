# Мудборд / бриф фотосессии — рабочая «бумага для фотографа» (workflow)

> **Установлено:** 2026-06-05 (Антон, USmile). Уроки сессии фикса мудборда v5.
> **Связано:** image-quality-standard.md, visual-content-not-just-ratio.md (R2 проверять контент глазами), analyzed-project-design-system.md, orchestration-method-selection.md, dental-clinic-blueprint.md.

## Назначение (главное)
Мудборд фотосессии = **рабочий документ ДЛЯ ФОТОГРАФА**, НЕ клиентский сайт. Фотограф по нему: смотрит чек-лист, нужное оборудование, какие кадры/ракурсы снять, таймлайн дня → формирует образ → применяет на съёмке.
→ Структура под УДОБСТВО ИСПОЛЬЗОВАНИЯ фотографом. **Компактно, НЕ длинный-длинный сайт.** Чек-лист + оборудование + ракурсы-референсы + таймлайн, плотно.

## Референсы-фото — ПРОВЕРЯТЬ СОДЕРЖИМОЕ, не ключ (HARD)
Прецедент: менял КЛЮЧИ изображений по подписям, но за ключами были ЗУБЫ до/после и ЛИЦЕНЗИИ (гербовые документы) в блоках про людей/интервью. Подпись ≠ что на фото.
- Перед сдачей — **визуальный фактчек КАЖДОГО используемого фото**: декодировать → собрать PIL **контактный лист** (сетка с подписями ключей) → Read одним просмотром (не по одной — экономит контекст) → сверить «что изображено» vs «подпись/блок».
- Флагать и заменять: зубы-до/после, сертификаты/лицензии/документы, баннеры-сертификаты (напр. был swiss-team = подарочный сертификат), чужие watermark, не тот объект.
- В people-блоках (портреты/команда/форма/свет/интервью) — только ЛЮДИ. В предметке (E) — изделия/процесс. Не путать.

## Команда — КРУПНО, с разных премиум-клиник
- Групповые кадры команды должны быть **большими** (size «big» = 2×2), не мелкими — иначе «не видно команды».
- Брать крупные групповые кадры с НЕСКОЛЬКИХ премиум-стоматологий (вариативность эталонов). Если сайт отдаёт мелкое (ROOTT _big=570, Belgravia JS-пусто) — искать др. источник high-res / соцсети клиник, НЕ апскейлить.

## Бренд-цвет — из САЙТА клиента, не из головы/config
Прецедент: в config стоял ошибочный «#DC143C красный»; реальный бренд USmile = графит #1D1D1F + **синий #0071e3** (вытащен из usmile.ru app.min.css) + белый. Красного у бренда нет.
→ Извлекать акцент: `curl <сайт> + app.min.css | grep -oiE '#[0-9a-f]{6}' | sort|uniq -c|sort -rn` → топ-цвета = реальная палитра. Применять её (analyzed-project-design-system). Конфликт config vs сайт vs память — победитель САЙТ + слово Антона.

## Оркестрация
- Сборка/доводка — **main-процесс**, НЕ рой/Workflow при throttle (прецедент: Workflow 7 агентов 2× по 100% rate-limited, 0 токенов). orchestration-method-selection: падающий рой не долбить.
- После деплоя — **скриншот глазами** (Chrome headless 1440+375 → Read), не «со слов».

## Чеклист готовности мудборда
- [ ] Все фото визуально проверены (контактный лист): 0 зубов/лицензий/сертификатов в people-блоках
- [ ] Команда крупным кадром, с ≥2 премиум-источников
- [ ] Акцент = реальный цвет сайта клиента (не из config/головы)
- [ ] Компактно (не бесконечная лента), удобно фотографу: чек-лист+оборудование+ракурсы+таймлайн
- [ ] Деплой review-URL + скриншот глазами + статус «на ревью» (deploy ≠ одобрено)

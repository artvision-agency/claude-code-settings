# Artvision-Коэффициент: РК «дёшево + кликабельно» по нашему рейтингу (подход + триггеры)

> **Установлено:** 2026-06-20 (Антон, USmile PPC). «Это очень классная история, под неё отдельную компанию запулил бы, с топовыми ключами по коэффициенту, подтверждённому Вебмастером и отчётами. Упаковать на будущее для других проектов, чтобы триггеры в любом аккаунте создавали РК с дешёвыми/дорогими кликами и теми что за копейки классно себя показывают. Помечать UTM-коэффициентом — наш чисто коэффициент. Может быть это часть продукта — смешиваем несколько аккаунтов и инструментов Яндекса, держим коэффициенты.»
> **Связано:** `capture-wins-as-skills.md` (это её применение), `numbers-deterministic-meaning-llm.md`, `determinism-first-and-verify.md`, `ppc-upload-always-off.md`, `bid-optimizer-DEVPLAN` (USmile), `service-knowledge-base.md`, `source-consolidation-verify.md`.

## Идея (коэффициент)
Рейтинг ключей по «дёшево + кликабельно»: **коэффициент = (CTR × объём трафика) / CPC**.
- **Стоимостная часть** (CPC, объём): «колено» аукциона из `keywordbids/AuctionBids` (max трафик/₽), считает `bid_optimizer.py` (Codex-approved).
- **Кликабельность (CTR)**: фактический CTR из Директ-**отчётов работающих** кампаний (наши клиенты, напр. Творим). Вебмастер CTR (органика) — прокси привлекательности запроса (НЕ CTR рекламы — помечать).
- ТОП ключей → отдельные РК: **«Дешёвый клик» / «Дорогой клик» / «Коэф-ТОП»**, OFF, помечены `utm_campaign=artvision_coef`. Включаются отдельно, под свой бюджет, ловят лиды.

## 🔴 ЖЁСТКИЙ УРОК про данные (провенанс, прецедент 20.06)
- **AuctionBids для DRAFT/OFF-кампании ТРАНЗИЕНТЕН**: есть ~10 мин после заливки свежих ключей, потом пусто **account-wide** (проверено: резерв 0/1641 + боевая 0/548; API жив, квота ок, не Cloud/баланс). → снимок реален, но **не воспроизводим**.
- **Коэффициент НЕЛЬЗЯ кормить данными DRAFT/OFF** — только **активные/работающие** кампании (там CTR+CPC persistent) ИЛИ разовый снимок в момент заливки (пометить «snapshot, не live»).
- **Провенанс HARD** (Антон: «строго проверить что не придуманы»): каждое число — из живого источника, **re-queryable**; помечать snapshot vs persistent; **никогда не заявлять „подтверждён Вебмастером/отчётами“ пока реально не выгрузил** (иначе обман). Сверять повторным запросом API.

## Метод (по шагам)
1. Источник CTR+CPC = Директ-отчёты **работающих** РК (выгрузка: ключ·показы·клики·CTR·факт.CPC) + AuctionBids колено.
2. Коэффициент по каждому ключу → ТОП.
3. Сборка РК `build_boevoi_clickcost.py` (сплит по CPC-медиане) / `build_boevoi_coeftop.py` (топ-N), UTM `artvision_coef`, OFF.
4. Залив `upload_boevoi.py` (Codex-approved: preflight, suspend-cleanup, всё OFF). Включение = CONFIRM + боевые ставки (минималка спецразмещения, не топ-1).
5. Refresh цен 30 мин (cron, READ AUTO) — только по активным/проверяемым источникам.

## Продукт (vision, TBD — round_table + approve)
Мульти-аккаунт коэффициент-движок: собирает данные работающих кампаний нескольких клиентов + инструментов Яндекса (Директ-отчёты, Вебмастер, AuctionBids) → держит «наш коэффициент» → в любом аккаунте авто-генерит дешёвый/дорогой/Коэф-ТОП РК (OFF, UTM-метка) готовые к включению. Это потенциальный продукт Artvision (название TBD). Перед adopt — `tool-adoption-proof` round_table + approve Антона.

## Кандидат-триггеры (TBD, approve — харнес/cron)
- При настройке нового PPC-аккаунта → авто-предложить сборку дешёвый/дорогой/Коэф-ТОП.
- Cron 30 мин: refresh AuctionBids активных кампаний → обновить ТОП-коэффициент.
Не регистрировать без approve + тест.

## Антипаттерны
- ❌ Коэффициент на данных DRAFT/OFF (транзиентный аукцион → мусор).
- ❌ Заявить «подтверждён Вебмастером/отчётами» не выгрузив их.
- ❌ Число из снимка подать как live без пометки.
- ❌ Включить Коэф-ТОП одновременно с by-service Поиском на тех же ключах (само-конкуренция).
